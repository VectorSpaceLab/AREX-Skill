# Off-Policy Value Troubleshooting

## `ValueError: Sample larger than population or is negative`

**Likely cause**: replay buffer has fewer items than `batch_size` or the requested sequence batch count.

**Fix**:
- Check `memory.size()` before calling `sample`.
- Keep the source warm-up logic: DQN waits for more than 2000 transitions; ACER waits for more than 500 stored sequences.
- For synthetic tests, lower the sample size or insert enough fixture transitions.

## `RuntimeError` from `gather(1, a)`

**Likely cause**: action tensor shape or dtype is wrong.

**Fix**:
- Use integer action tensor shaped `(batch, 1)` for DQN, ACER, and V-trace selected actions.
- For continuous algorithms, route to [../../continuous-control/SKILL.md](../../continuous-control/SKILL.md); do not use `gather` with continuous action tensors.

## DQN target values change during backprop

**Likely cause**: target network outputs are part of the gradient graph or the target network is not synchronized predictably.

**Fix**:
- Compute targets from `q_target` and avoid optimizing target-network parameters in the current optimizer.
- Copy current weights to target only at the planned interval.
- If you intentionally use soft updates, use the continuous-control DDPG/SAC guidance instead of DQN's hard-copy pattern.

## ACER or V-trace ratios become NaN or infinite

**Likely causes**:
- Behavior probability `prob`/`mu_a` is zero or missing.
- Stored behavior probabilities were generated by a different action dimension after porting.
- Probabilities were stored as logits or action ids instead of probabilities.

**Fix**:
1. Confirm behavior probabilities are positive probabilities that sum to one across the action dimension where applicable.
2. Preserve full behavior vectors for ACER and selected behavior probabilities for V-trace.
3. Add an epsilon floor only as a defensive adaptation and document the algorithm change.
4. Run `python sub-skills/off-policy-value/scripts/smoke_off_policy_value.py --algorithm acer` or `--algorithm vtrace` to verify expected ratio shapes.

## ACER corrected returns cross sequence boundaries

**Likely cause**: the `is_first` marker was dropped when flattening sampled sequences.

**Fix**: keep a boolean `is_first` list and reset the reverse-scan return when a new sequence begins. The minimalRL ACER logic explicitly reinitializes `q_ret` at sequence boundaries.

## Training appears stuck or too slow

The original scripts run many episodes and replay warm-ups. First run the bundled smoke helper, then test with a reduced episode count and explicit maximum steps. Do not use full training as a first-line diagnostic.

## Gym reset/step compatibility problems

For Gym 0.26-compatible environments:

```python
s, _ = env.reset()
s_prime, r, terminated, truncated, info = env.step(a)
done = terminated or truncated
done_mask = 0.0 if done else 1.0
```

Using only `terminated` can make time-limit truncations bootstrap incorrectly.
