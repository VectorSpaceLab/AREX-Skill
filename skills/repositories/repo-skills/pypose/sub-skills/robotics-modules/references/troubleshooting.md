# Troubleshooting and recovery

## Fast triage

1. Reproduce on CPU with `torch.manual_seed(0)` and one small batch.
2. Print `shape`, `dtype`, `device`, and `isfinite().all()` for every input and
   output. Never fix a mismatch by blindly calling `squeeze()`.
3. Validate the trailing feature/matrix dimensions against the API reference,
   then add leading batch/time dimensions one at a time.
4. Check mutable clocks/state/steppers: print `model.systime`, use a fresh
   integrator/filter/model, and call `stepper.reset()` before a second run.
5. Check units and coordinate frames before tuning tolerances.

## Shape and broadcasting failures

**Symptom:** `bmv`, matrix multiplication, `broadcast_shapes`, or an assertion
reports incompatible dimensions.

**Recovery:** preserve `(..., feature)` for vectors and `(..., rows, cols)` for
matrices. For dynamics, ensure `A/B/C/D` agree on state/input/observation
sizes. For filters, use `P/Q (...,n,n)` and `R (...,m,m)`. For PnP/ICP, use
`(...,N,3)` and matching `N`; for PnP pixels are `(...,N,2)`. For LQR/MPC,
assemble `[state, control]` and create `Q (...,T,n+q,n+q)`, `p
(...,T,n+q)`. If a vector lacks a batch, add a leading singleton batch with
`unsqueeze(0)`; if a vector lacks a time axis, do not invent one unless the
caller is building a trajectory.

**Symptom:** an unbatched example works but a batched one changes values.

**Recovery:** compare a batched call against a loop over batch items. Check that
matrix batch axes are intended, that time is not being treated as a batch, and
that `LTV` properties index `self._t` rather than the input batch axis.

## Covariance and filter failures

**Symptom:** Cholesky fails in UKF, distribution construction fails in PF, or
filter covariance becomes NaN/asymmetric.

**Recovery:** verify `P`, `Q`, `R` are square, finite, same dtype/device, and
symmetric. Check eigenvalues; negative values usually mean a modeling or update
issue, not a tolerance problem. Use a physically justified positive diagonal
noise floor. UKF specifically needs a valid Cholesky-compatible covariance (or a
custom compatible `msqrt`). PF needs valid covariance for
`MultivariateNormal`; reduce `particles` only for runtime, not to repair invalid
statistics. Check observation dimension `m` matches `R`, not state dimension
`n`.

**Symptom:** EKF estimate does not improve.

**Recovery:** ensure the measurement is generated by the same observation
convention and time index, noise is added outside pure model functions, and `Q`
/`R` represent variances (not standard deviations). Start with a stable nearly
linear model and seeded data, then increase nonlinearity. Check that `P` passed
to a call is the previous posterior, not an uninitialized time slice.

## Time, dt, and state mutation

**Symptom:** a time-varying model uses the wrong matrix/time, or replay gives a
different trajectory.

**Recovery:** remember the first `System/NLS.forward` uses the current `systime`
then increments it. Call `model.reset(t0)` before replay. For a filter, explicit
`t` is passed to linearization/transition/observation, but a PF model call also
invokes the model hook; record both explicit times and `systime`. Use independent
model instances for concurrent estimator comparisons.

**Symptom:** IMU results drift or a second window starts from the previous run.

**Recovery:** `IMUPreintegrator(reset=False)` intentionally persists its last
state/covariance. Use `reset=True`, a new integrator, or a complete `init_state`
dict. Confirm `dt` is seconds and positive, gyro is rad/s, acceleration is in a
consistent distance/s² unit, and raw acceleration/gravity compensation is not
done twice. Covariance order is rotation/velocity/position, so position blocks
start at index 6.

## LQR/MPC and stepper failures

**Symptom:** LQR Cholesky fails or controls are huge.

**Recovery:** make the control-control (`Quu`) portion of each stage cost
positive definite; verify Q/p ordering and scale. Check `x_init` is `(B,n)` at
the final call, `u_init` is `(B,T,q)`, and `T` is the number of controls. Keep
`dt` consistent with the discrete model and avoid passing a covariance as Q.

**Symptom:** MPC returns a worse result, hangs, or behaves differently on reuse.

**Recovery:** use a bounded stepper, call `reset()`, and inspect each scalar or
batch cost after `step`. The supplied stepper is mutated and MPC's default
reduces its max step count by one. Start with `steps=1`/`2` and a stable nominal
trajectory; nonlinear iLQR is local and can worsen outside its basin. Apply
only the first returned control for receding-horizon operation.

## PnP and ICP failures

**Symptom:** EPnP rejects inputs or returns a bad pose.

**Recovery:** ensure `N >= 4`, points/pixels correspond in the same order, batch
prefixes broadcast, `K` is `(...,3,3)` with positive `fx/fy` and final row
`[0,0,1]`, and points are non-degenerate/non-coplanar with valid positive
camera depth. Confirm pixels use K's original pixel units. Try `refine=False`
to separate base solver issues from refinement; then compare reprojection error.

**Symptom:** ICP converges to the wrong transform or does not reduce error.

**Recovery:** initialize closer with constructor/call `SE3` (call wins), use
non-symmetric 3D geometry and enough points, remove outliers/scale mismatch,
and inspect nearest-neighbor residual rather than pointwise residual. Collinear,
planar, repeated, or symmetric clouds are degenerate for some degrees of
freedom. Increase steps only after checking initialization and correspondence
quality; more iterations cannot recover an unobserved transform.

## Safe helper policy

The bundled smoke scripts use only synthetic CPU tensors, fixed seeds, and
bounded module calls. They do not download datasets, import plotting libraries,
or write files. Run them from the `pypose` skill directory using the relative
paths shown in `SKILL.md`, or invoke them by absolute path from any working
directory. They import the installed public package and accept `--help`.
