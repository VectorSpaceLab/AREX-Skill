# Artifact layout and persistence

`mljar-supervised` saves an AutoML run automatically while `AutoML.fit()` executes. The durable artifact is the entire `results_path` directory, not one backend learner file.

## Public load and prediction pattern

```python
from supervised import AutoML

# Train once.
automl = AutoML(results_path="AutoML_run", explain_level=0)
automl.fit(X_train, y_train)

# Later, reload the whole run directory.
loaded = AutoML(results_path="AutoML_run")
predictions = loaded.predict(X_test)
all_outputs = loaded.predict_all(X_test)
```

If `results_path` already contains `params.json`, `AutoML(results_path=...)` recognizes it as an existing AutoML run and loads the saved models. `automl = AutoML(); automl.load(path)` is also available, but the constructor pattern is the normal user workflow.

Do not load individual learner files for ordinary prediction. Files such as backend model binaries, joblib files, or CatBoost/XGBoost/LightGBM learner files do not include MLJAR's preprocessing, target transformation, label handling, threshold, ensemble/stacking, and best-model orchestration.

## What to expect under `results_path`

Common top-level files and directories include:

| Path | Purpose | Public use |
| --- | --- | --- |
| `params.json` | Run configuration, saved model names, best model, stacking/ensemble dependency metadata, fit status. | Required for automatic loading. Inspect for diagnostics; do not hand-edit in normal use. |
| `data_info.json` | Feature count, column order, task/target metadata used during prediction. | Required for prediction after load and column validation. |
| `leaderboard.csv` | Saved leaderboard with human-readable metric values. | Safe to read with pandas for reporting and audit summaries. |
| `README.md` | Main Markdown run report with leaderboard and links to model reports. | First human-readable report to inspect. |
| `README.html` | HTML report generated by `automl.report()` when not already present. | Notebook/browser display artifact. |
| `report_structured.json` | Full structured-report payload written by `report_structured(...)`. | Machine-readable report archive. |
| `errors.md` | Collected training errors when some candidates fail. | Inspect when models are missing or run quality is suspicious. |
| Model subdirectories such as `1_Baseline`, `1_DecisionTree`, `Ensemble`, `Stacked_Ensemble` | Model-specific reports, framework/ensemble JSON, learner files, predictions, plots, and importance/SHAP outputs. | Keep with the run. Read reports and derived CSV/PNG/SVG files; do not treat raw learner files as a standalone public API. |

The exact model directory names depend on algorithm choice, validation, ensembling, stacking, and run order. Always discover names from `get_leaderboard()`, `leaderboard.csv`, `params.json`, or the directory listing rather than hard-coding them.

## Leaderboard access

```python
ldb = automl.get_leaderboard(
    filter_random_feature=False,
    original_metric_values=True,
)
```

Expected columns usually include `name`, `model_type`, `metric_type`, `metric_value`, and `train_time`. Additional columns can appear:

- `single_prediction_time` when `max_single_prediction_time` was used.
- `fairness_metric`, one `fairness_<sensitive feature>` column per sensitive feature, and `is_fair` when fairness-aware training was used.

Use `original_metric_values=True` for human-facing reporting. Use `filter_random_feature=True` when a random-feature diagnostic model should be hidden from the leaderboard. For the meaning of fairness columns, route to `fairness-workflows`.

## Prediction after load

A reloaded `AutoML` object should preserve the same prediction interface:

```python
loaded = AutoML(results_path="AutoML_run")
y_pred = loaded.predict(X_new)
y_all = loaded.predict_all(X_new)

# Classification only:
y_proba = loaded.predict_proba(X_new)
```

For regression, `predict_proba()` is invalid; use `predict()` or `predict_all()` instead. For classification, `predict_all()` returns class-probability columns plus a label column. For regression, it returns prediction values.

Prediction validates the new input against saved training metadata:

- Feature count must match the saved model.
- Required column names must be present when the model was trained with a DataFrame.
- The saved preprocessing and target encoders are applied by the AutoML object, not by user code that directly loads learner files.

## Model dependencies needed for prediction

`params.json` can include `best_model`, `saved`, `stacked`, and `load_on_predict`. These fields let the loader avoid loading every trained model while still loading all models needed by the best model.

Use `models_needed_on_predict(model_name)` for diagnostics when a model appears in `params.json` but cannot be predicted from:

```python
needed = automl.models_needed_on_predict("Ensemble")
```

Dependency patterns:

- A single non-stacked model needs its own model folder.
- `Ensemble` needs its selected component model folders plus the `Ensemble` folder.
- A stacked model needs the base ensemble, stacked input models, and its own folder.
- `Stacked_Ensemble` needs base models, the first-level ensemble, stacked models, the stacked ensemble folder, and their metadata files.

If any listed dependency folder or required JSON/learner file is missing, prediction after load can fail even when the top-level `params.json` exists.

## Moving, archiving, or sharing a run

Safe rule: move or archive the entire `results_path` directory as one unit.

The loader uses the actual directory path passed to `load(path)` or `AutoML(results_path=path)` as the source of truth. This means a serialized `results_path` value inside `params.json` may differ after a move and still be acceptable. However, the internal relative structure must remain intact: top-level metadata, model subdirectories, framework/ensemble files, learner files, preprocessing files, reports, and any prediction dependency files must move together.

After moving a run, verify:

```python
loaded = AutoML(results_path="moved_AutoML_run")
print(loaded.get_leaderboard(original_metric_values=True).shape)
print(loaded.predict_all(X_check).head())
```

## `need_retrain` support

`need_retrain(X_new, y_new, sample_weight=None, decrease=0.1)` compares performance on new labeled data against the saved best model's training/validation metric and returns a boolean retraining recommendation.

Use it only when:

- The AutoML object is fitted or successfully loaded from a complete `results_path`.
- `X_new` has the same schema as training data.
- `y_new` is available and uses compatible labels/target scale.
- `decrease` is set according to project tolerance; the default `0.1` means roughly a 10% performance decrease threshold.

Route metric selection and validation strategy questions to `training-core`. Treat `need_retrain` as a drift/performance check, not as a replacement for domain review.
