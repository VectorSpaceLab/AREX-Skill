# PaperQA CLI and Index Troubleshooting

Use this guide for `pqa` parser failures, settings confusion, index reuse
problems, manifest mistakes, and provider/rate-limit issues.

## `pqa` is missing or the entry point is wrong

Symptoms:

- `pqa: command not found`
- A different command named `pqa` runs.
- `pqa --help` fails before showing PaperQA commands.

Actions:

1. Run `python sub-skills/cli-and-indexing/scripts/inspect_cli.py --json` from
   the generated skill root or call the script by its actual bundled path.
2. Confirm the active Python environment installed PaperQA with console scripts.
3. Confirm `PATH` points at that environment's script directory.
4. As a fallback diagnostic, import `paperqa` in the intended environment and
   check that the installed package version is the expected one for this skill.

The inspection script only runs help commands and sets a temporary state home by
default, so it should not build indexes or call providers.

## CLI parse errors

Common causes and fixes:

- Put global settings flags before the subcommand for clarity:
  `pqa --settings fast --temperature 0.2 ask "question"`.
- Use exact dotted flag names such as `--agent.index.paper_directory`, not
  underscores or shortened aliases.
- Use `true` / `false` for booleans.
- Quote JSON or dict-valued settings so the shell does not split them.
- `pqa index` requires a `DIRECTORY` positional argument.
- `pqa search` and `pqa ask` each require a single query string; quote queries
  with spaces.

If a flag appears in `pqa --help` but does not parse as expected, run `pqa view`
with the same flags and inspect the resulting JSON before running `ask` or
`index`.

## Settings `save` and `view` confusion

- `pqa view` prints settings; it does not save them.
- `pqa save LOCATION` saves the loaded settings after applying overrides.
- `--settings NAME` selects the base settings to load. It is not the save
  destination.
- Use a known base, then save to a new location:

```bash
pqa --settings high_quality --temperature 0.2 save my-paper-settings
pqa --settings my-paper-settings view
```

If saving a relative name, PaperQA writes under its settings state directory and
adds `.json` when needed. If saving an absolute path, PaperQA writes exactly to
that path.

## `PQA_HOME` points somewhere unexpected

PaperQA appends `.pqa` below `PQA_HOME`. If `PQA_HOME=/tmp/pqa-state`, indexes
and settings default under `/tmp/pqa-state/.pqa/`. If `PQA_HOME` already ends in
`.pqa`, PaperQA will create a nested `.pqa/.pqa` layout.

Actions:

- Set `PQA_HOME` before invoking `pqa`.
- Prefer a parent state directory, for example `PQA_HOME="$HOME/paperqa-state"`.
- For reproducible commands, pass `--agent.index.index_directory` explicitly.
- If answer history or indexes seem missing, compare the `PQA_HOME` and
  `index_directory` used by the old and new commands.

## Default/autogenerated index vs named index

Symptoms:

- A new index is built after a settings change.
- `search` returns no results after `ask` or `index` appeared to work.
- A settings file has `agent.index.name`, but CLI `--index` seems to override it.

Facts:

- CLI `--index default` is a sentinel, not necessarily the literal index name.
- For `index` and `search`, if `--index` is `default` and
  `settings.agent.index.name` is set, that setting name is used.
- If neither is set, PaperQA computes an autogenerated name from path/parsing
  and embedding settings.
- For `index` and `search`, if CLI `--index NAME` is not `default`, the CLI
  value wins for that run.
- For `ask`, use `--agent.index.name NAME` or a saved settings file; do not rely
  on top-level `--index NAME` alone.

Actions:

- Use a stable named index for project workflows.
- Keep the same `index_directory` across `index`, `search`, and `ask`.
- When parser, chunking, embedding, or multimodal settings change, choose a new
  named index or rebuild the old one intentionally.

## Stale, corrupt, or locked indexes

Symptoms:

- `zlib.error` or failure to read `files.zip`.
- Tantivy metadata errors.
- Lock-busy messages or long retries while writing.
- Results mention files that no longer exist.

Actions:

1. Stop other processes using the same named index.
2. Retry once; lock acquisition is retried internally.
3. For diagnostics, set `PQA_INDEX_DONT_CACHE_INDEXES=1` to avoid reusing opened
   index handles inside the process.
4. If files were moved, restore the matching relative layout or rebuild.
5. If the index is corrupt, remove the whole `<index_directory>/<index_name>/`
   directory and rebuild with the intended settings.
6. For read-only inspection of a moved/shared index, try
   `--agent.index.sync_with_paper_directory false`; do not use it as proof that
   a stale index is correct.

Progress bars can be controlled with `PQA_INDEX_DISABLE_PROGRESS_BAR=1` or
`PQA_INDEX_ENABLE_PROGRESS_BAR=1` when terminal rendering causes trouble.

## Manifest path or column problems

Symptoms:

- Manifest is silently ignored or logged as not found.
- Rows do not map to indexed files.
- DOI/title hints are not applied.

Actions:

- Ensure the manifest path ends in `.csv`.
- If the path is relative, remember PaperQA tries it relative to the current
  context first and then relative to `paper_directory`.
- Include a non-empty `file_location` column.
- Prefer relative `file_location` values from `paper_directory`.
- Check that each path exists and is not a directory.
- Include `doi` or `title` when available; use the validation script with
  `--require-doi` or `--require-title` if the workflow depends on them.

```bash
python sub-skills/cli-and-indexing/scripts/validate_manifest.py \
  --paper-directory "$HOME/Documents/papers" \
  --manifest "$HOME/Documents/papers/manifest.csv" \
  --require-title
```

## Recursive scan or file filter surprises

Default CLI indexing recurses into subdirectories and includes:

```text
.txt, .pdf, .html, .md, .xlsx, .docx, .pptx
```

Actions:

- Use `--agent.index.recurse_subdirectories false` for top-level-only scans.
- Remove or move unsupported files instead of expecting CLI indexing to process
  every suffix.
- Use a clean document folder for a specific index.
- Use Python settings/API workflows for custom callable file filters.

## Rate limits, API keys, network, or provider calls

`pqa ask` and `pqa index` can call:

- embedding providers for chunks,
- LLM providers for metadata inference, evidence summaries, and final answers,
- metadata providers such as Crossref or Semantic Scholar.

Actions:

- Verify provider credentials or local servers before running.
- Use a manifest with DOI/title to reduce metadata ambiguity.
- Lower `--agent.index.concurrency` and answer concurrency settings for rate
  limits.
- Use a cheaper/faster named settings profile if suitable.
- If a local/offline workflow is required, route to the settings/configuration
  sub-skill to set all LLM, summary LLM, agent LLM, embedding, and enrichment
  roles consistently.

## Answer index search returns nothing

Facts:

- The special `answers` index is created by successful `ask` / agent query runs.
- It is stored in the active `index_directory`.
- Searching a different `PQA_HOME` or `index_directory` will not see prior
  answers.

Actions:

```bash
pqa --index answers \
  --agent.index.index_directory "$HOME/.cache/paperqa-indexes" \
  search "phrase from the earlier answer"
```

If the index is empty, rerun the original `ask` with the intended
`index_directory`, or point `search` at the directory used by the original run.
