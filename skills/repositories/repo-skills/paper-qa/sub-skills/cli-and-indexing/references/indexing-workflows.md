# PaperQA Indexing Workflows

PaperQA stores local Tantivy search indexes plus serialized PaperQA objects. The
CLI exposes these indexes through `pqa index`, `pqa search`, and `pqa ask`.

## State directories and `PQA_HOME`

PaperQA's state helper creates directories under a `.pqa` subtree:

- If `PQA_HOME` is unset, defaults are under `~/.pqa/`.
- If `PQA_HOME=/some/state-parent`, defaults are under
  `/some/state-parent/.pqa/`.

Common state subdirectories:

- settings files: `.pqa/settings/`
- indexes: `.pqa/indexes/`

Therefore, set `PQA_HOME` to a parent state directory, not to an existing `.pqa`
directory, unless a nested `.pqa/.pqa` layout is intentional.

For a fully explicit CLI run, pass `--agent.index.index_directory` and
`--agent.index.paper_directory` so state does not depend on the caller's current
working directory.

## Index layout

Each PaperQA search index lives under:

```text
<index_directory>/<index_name>/
  index/      # Tantivy index metadata and segments
  docs/       # serialized Docs or AnswerResponse payloads
  files.zip   # compressed mapping from file_location to content hash/status
```

Do not hand-edit these files. If the index is corrupt or was built with wrong
settings, rebuild or remove the whole named index directory.

## Choosing an index name

PaperQA has two naming modes:

1. **Named index**: pass `--index NAME` to CLI `index`, `search`, or `ask`, or
   set `--agent.index.name NAME` in settings. Named indexes are easiest to
   share within a project because the name is stable.
2. **Autogenerated index**: leave `--index` as `default` and leave
   `agent.index.name` unset. PaperQA computes a name from settings that affect
   parsing and embedding.

For `pqa index` and `pqa search`, when the CLI receives `--index default`, it
gives precedence to `settings.agent.index.name`; otherwise it uses the
autogenerated settings hash. When `--index NAME` is not `default`, that explicit
CLI value becomes the index name for that `index` or `search` run.

For `pqa ask`, the inspected CLI parser accepts `--index`, but the command path
uses the `Settings` object directly. To make `ask` use a named index, set
`--agent.index.name NAME` or save/load settings with `agent.index.name`; do not
rely on `--index NAME` alone for `ask`.

The autogenerated name changes when these inputs change: paper directory,
`use_absolute_paper_directory`, embedding model, PDF parser, chunk size,
overlap, `full_page`, and multimodal setting. This is useful automatic
invalidation. With a named index, you own invalidation: if parser, embedding, or
chunking settings change, choose a new name or rebuild the named index.

## Creating a local paper index

1. Pick the user-owned document folder, for example `$HOME/Documents/papers`.
2. Pick a state location, either by setting `PQA_HOME` or by passing
   `--agent.index.index_directory`.
3. Prefer a stable named index for reuse.
4. Validate any manifest CSV first.
5. Build the index.

```bash
python sub-skills/cli-and-indexing/scripts/validate_manifest.py \
  --paper-directory "$HOME/Documents/papers" \
  --manifest "$HOME/Documents/papers/manifest.csv"

pqa --settings fast \
  --index project-papers \
  --agent.index.paper_directory "$HOME/Documents/papers" \
  --agent.index.index_directory "$HOME/.cache/paperqa-indexes" \
  --agent.index.manifest_file manifest.csv \
  index "$HOME/Documents/papers"
```

The paper directory is read, not modified. Index files are written to
`index_directory`. The build may call embeddings, metadata providers, and LLMs
while adding documents unless configured otherwise.

## Reusing an index for search and ask

Search a named index:

```bash
pqa --index project-papers \
  --agent.index.index_directory "$HOME/.cache/paperqa-indexes" \
  search "oxide thermoelectric"
```

Ask against the same index and source directory:

```bash
pqa --settings fast \
  --agent.index.name project-papers \
  --agent.index.paper_directory "$HOME/Documents/papers" \
  --agent.index.index_directory "$HOME/.cache/paperqa-indexes" \
  ask "Which documents compare oxide thermoelectrics?"
```

If the source folder has not changed and the user wants a read-only reuse
attempt, consider:

```bash
pqa --index project-papers \
  --agent.index.index_directory "$HOME/.cache/paperqa-indexes" \
  --agent.index.sync_with_paper_directory false \
  --agent.rebuild_index false \
  search "oxide thermoelectric"
```

Only disable rebuild/sync for an existing non-empty index. Empty indexes raise a
load error or produce no results.

## Moving or sharing an index folder

For better shareability:

- Use a named index such as `project-papers` rather than relying on an
  autogenerated name tied to a path string. For `ask`, put the name in
  `agent.index.name` rather than relying on the top-level `--index` flag.
- Keep `use_absolute_paper_directory` false so stored `file_location` values are
  relative to the paper directory.
- Keep the same relative document layout and manifest `file_location` values.
- After moving, point `--agent.index.index_directory` at the moved index root
  and `--agent.index.paper_directory` at the current document folder.
- If PaperQA reports missing indexed files, either restore the matching document
  layout, rebuild the index, or temporarily set
  `--agent.index.sync_with_paper_directory false` for read-only inspection.

Do not promise that an index is portable across different parser or embedding
settings. Rebuild when those settings changed.

## Manifest CSVs

`IndexSettings.manifest_file` accepts an absolute path or a path relative to the
paper directory. The file must be a CSV. Header order does not matter.

PaperQA keys rows by `file_location`. During indexing, the most important
columns are:

```csv
file_location,doi,title
papers/example.pdf,10.1234/example,Example Paper Title
notes/methods.md,,Internal Method Notes
```

Guidelines:

- Use relative `file_location` values from the paper directory for shareability.
- Ensure every `file_location` exists before building the index.
- Add `doi` and/or `title` when available to reduce metadata inference errors.
- Extra metadata columns may be ignored by the indexer; keep the manifest simple
  unless another workflow needs richer `DocDetails` data.
- Run `scripts/validate_manifest.py` to catch missing files, duplicate rows,
  blank locations, path traversal, and suspicious DOI/title hints.

If `use_absolute_paper_directory` is false, PaperQA stores relative
`file_location` values and can fall back to absolute manifest keys. If it is
true, PaperQA stores absolute values and can fall back to relative manifest
keys, but the index becomes user-specific.

## Recursive scanning and file filters

By default, indexing recurses through subdirectories and includes files whose
suffix is one of:

```text
.txt, .pdf, .html, .md, .xlsx, .docx, .pptx
```

Use `--agent.index.recurse_subdirectories false` to scan only the top-level
folder. Custom callable file filters are a Python settings/API concern, not a
portable CLI default; for CLI-only use, organize the input folder or build a
separate folder/manifest.

## Answer index

Each successful `pqa ask` / agent query stores the answer response in an index
named `answers` under the active `index_directory`. Search it with:

```bash
pqa --index answers \
  --agent.index.index_directory "$HOME/.cache/paperqa-indexes" \
  search "phrase from a previous question or answer"
```

If no answers appear, confirm that the same `index_directory` and `PQA_HOME`
were used when the original answers were generated.
