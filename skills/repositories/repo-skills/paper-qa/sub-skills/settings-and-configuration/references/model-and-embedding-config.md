# Model, Embedding, Router, and Vector-Store Configuration

Use this reference to make provider and embedding changes that are complete across PaperQA’s multiple model roles. Running queries is handled by `../agentic-rag/`; this file focuses on configuration objects only.

## Configure every model role

PaperQA has more than one LLM-like role:

| Role | Settings path | Typical use | Default |
| --- | --- | --- | --- |
| Main LLM | `llm` + `llm_config` | final answer, metadata inference, pre/post prompt work, fake-agent search proposals | `gpt-4o-2024-11-20` |
| Summary LLM | `summary_llm` + `summary_llm_config` | summarizing/relevance-scoring evidence chunks | `gpt-4o-2024-11-20` |
| Agent LLM | `agent.agent_llm` + `agent.agent_llm_config` | tool selection inside the agent | `gpt-4o-2024-11-20` |
| Enrichment LLM | `parsing.enrichment_llm` + `parsing.enrichment_llm_config` | multimodal media descriptions when parser enrichment is enabled | default model in parsing settings |
| Embedding model | `embedding` + `embedding_config` | chunk embedding and retrieval | `text-embedding-3-small` |

When switching away from OpenAI, change all active LLM roles plus `embedding`. A common failure is setting only `llm="claude..."` while `summary_llm`, `agent.agent_llm`, and `embedding` still require OpenAI credentials.

## Provider key heuristics

PaperQA uses LiteLLM through its LLM interface, so provider-specific model names and environment variables follow LiteLLM conventions. Before a live run, check only whether the needed environment variables are present; never store secrets in settings JSON.

| Model name pattern | Usual prerequisite |
| --- | --- |
| `gpt-*`, `o1*`, `text-embedding-*`, or explicit OpenAI-compatible names | `OPENAI_API_KEY` or equivalent provider config |
| `claude-*` | `ANTHROPIC_API_KEY` |
| `gemini/*` | `GEMINI_API_KEY` |
| `ollama/*` | a local Ollama server with the named model pulled; usually no cloud key |
| `st-*` | `paper-qa[local]` / `sentence-transformers` installed; model weights available locally or downloadable by the embedding library |
| `sparse` | no cloud key; sparse keyword embedding only |
| `hybrid-*` | prerequisites for the dense component plus sparse keyword embedding |

## LiteLLM Router config shape

PaperQA’s LLM config fields are passed as LiteLLM Router-style configuration. The robust custom-provider form is a dictionary with `model_list`:

```python
router_config = {
    "model_list": [
        {
            "model_name": "my-paperqa-role-name",
            "litellm_params": {
                "model": "provider/model-or-local-alias",
                "api_base": "http://localhost:8080/v1",
                "api_key": "sk-no-key-required",
                "temperature": 0.1,
                "max_tokens": 512
            }
        }
    ],
    "router_kwargs": {},
    "rate_limit": {"my-paperqa-role-name": "30000 per 1 minute"}
}
```

The `model_name` must match the corresponding PaperQA role name (`llm`, `summary_llm`, or `agent.agent_llm`) when that role should route to this entry. Configure each role independently:

```python
from paperqa import Settings
from paperqa.settings import AgentSettings

settings = Settings(
    llm="my-paperqa-role-name",
    llm_config=router_config,
    summary_llm="my-paperqa-role-name",
    summary_llm_config=router_config,
    agent=AgentSettings(
        agent_llm="my-paperqa-role-name",
        agent_llm_config=router_config,
    ),
)
```

Notes:

- Default configs generated by PaperQA include a `model_list` and cache-control injection points.
- A config containing only `rate_limit` is useful for throttling default models, but it is not a substitute for a custom local/provider route.
- If a provider error says the model is unknown, check that `model_name` equals the PaperQA role string and that `litellm_params.model` is the provider model identifier.
- Do not put API keys directly in shared JSON. Use environment variables or runtime-only secret injection.

## OpenAI tier limits and manual limits

Bundled `tier1_limits` through `tier5_limits` set rate-limit maps for `llm_config`, `summary_llm_config`, and `embedding_config`. They do not necessarily throttle `agent.agent_llm_config`, so copy a compatible rate-limit map there if the agent LLM is the bottleneck.

Manual rate-limit settings use strings compatible with the `limits` notation accepted by the underlying stack:

```python
from paperqa import Settings
from paperqa.settings import AgentSettings

rate_limits = {"gpt-4o-2024-11-20": "30000 per 1 minute"}
settings = Settings(
    llm_config={"rate_limit": rate_limits},
    summary_llm_config={"rate_limit": rate_limits},
    embedding_config={"rate_limit": "1000000 per 1 minute"},
    agent=AgentSettings(agent_llm_config={"rate_limit": rate_limits}),
)
```

## Reasoning-model temperature

This PaperQA version changes `Settings.temperature` to `1` and emits a warning when the top-level `llm` starts with `o1` or `gpt-5` and the requested temperature is not `1`. If only `summary_llm` or `agent.agent_llm` uses an `o1`/`gpt-5` model, set `temperature=1` yourself so the shared temperature passed to those roles is compatible.

Validate before live use:

```bash
python sub-skills/settings-and-configuration/scripts/validate_settings_json.py my-settings.json --strict-warnings
```

## Local LLM examples

### Llamafile / OpenAI-compatible local server

```python
from paperqa import Settings
from paperqa.settings import AgentSettings

local_llm_config = {
    "model_list": [
        {
            "model_name": "my-llm-model",
            "litellm_params": {
                "model": "my-llm-model",
                "api_base": "http://localhost:8080/v1",
                "api_key": "sk-no-key-required",
                "temperature": 0.1,
                "frequency_penalty": 1.5,
                "max_tokens": 512,
            },
        }
    ]
}

settings = Settings(
    llm="my-llm-model",
    llm_config=local_llm_config,
    summary_llm="my-llm-model",
    summary_llm_config=local_llm_config,
    agent=AgentSettings(
        agent_llm="my-llm-model",
        agent_llm_config=local_llm_config,
    ),
    embedding="sparse",
)
```

Use a larger instruction-following model for real PaperQA tasks; very small local models are often poor at evidence selection and citation discipline.

### Ollama local stack

from paperqa import Settings
from paperqa.settings import AgentSettings

ollama_config = {
    "model_list": [
        {
            "model_name": "ollama/llama3.2",

            },
        }
    ]
}

settings = Settings(
    llm="ollama/llama3.2",
    llm_config=ollama_config,
    summary_llm="ollama/llama3.2",
    summary_llm_config=ollama_config,
    agent=AgentSettings(
        agent_llm="ollama/llama3.2",

If the local embedding endpoint is unavailable, use `embedding="sparse"` as a no-cloud fallback or install local sentence-transformers and use an `st-` embedding.

## Embedding choices

PaperQA builds its full-text vector index from the embedding model. `Settings.embedding` supports these forms:

| Form | Meaning | Prerequisites |
| --- | --- | --- |
| `text-embedding-3-small` or other plain name | LiteLLM embedding model | Provider credentials/config for that model. |
| `litellm-<model>` | Explicit LiteLLM embedding model name after the prefix | Provider credentials/config. |
| `st-<sentence-transformer-model>` | Local `SentenceTransformerEmbeddingModel` | Install `paper-qa[local]`; ensure model weights are available. |
| `hybrid-<dense-model>` | Dense model plus sparse keyword embedding | Prerequisites for the dense model; works with `hybrid-st-...` and `hybrid-text-embedding-...`. |
| `sparse` | Sparse keyword embedding only | No cloud key; lower semantic recall than dense/hybrid embeddings. |

Examples:

```python
from paperqa import Settings

openai_large = Settings(embedding="text-embedding-3-large")
local_st = Settings(embedding="st-multi-qa-MiniLM-L6-cos-v1")
hybrid_local = Settings(embedding="hybrid-st-multi-qa-MiniLM-L6-cos-v1")
sparse_only = Settings(embedding="sparse")
```

You can also pass an explicit embedding model object to document-add/query APIs; use `../agentic-rag/` for those runtime patterns.

## Vector stores and embedding cache behavior

`Settings` chooses the embedding model, but the `Docs` object owns the vector store through `texts_index`.

```python
from paperqa import Docs
from paperqa.llms import NumpyVectorStore, QdrantVectorStore

docs = Docs(texts_index=NumpyVectorStore())
# Requires paper-qa[qdrant] or qdrant-client:
qdrant_docs = Docs(texts_index=QdrantVectorStore(collection_name="paperqa-demo"))
```

Operating notes:

- `NumpyVectorStore` is the default simple in-memory store.
- `QdrantVectorStore` requires `qdrant-client`; without it, construction raises an import error. If no client is passed, it creates an in-memory async Qdrant client. For a persistent service, pass an `AsyncQdrantClient` configured at runtime.
- `texts_index_mmr_lambda` controls MMR diversity for vector retrieval.
- Embeddings are cached when the underlying `Docs` object is serialized/pickled, regardless of vector store choice.
- CLI/search indexes are built from a hash of the current settings, including embedding, parser, chunk size, overlap, multimodal state, and paper-directory choices. Use `../cli-and-indexing/` for index lifecycle.

## Optional dependency choices

Install only the extras needed for the intended workflow:

| Extra | Enables | Configuration impact |
| --- | --- | --- |
| `local` | `sentence-transformers` local embeddings | Required for `embedding="st-..."` and `hybrid-st-...`. |
| `qdrant` | Qdrant vector store | Required for `QdrantVectorStore`. |
| `office` | Office document parsing | Parser workflow; route format details to `../docs-and-parsing/`. |
| `zotero` | Zotero helper plus related parser dependency | Source workflow; route setup to `../metadata-and-sources/`. |
| `openreview` | OpenReview helper | Source workflow; route setup to `../metadata-and-sources/`. |
| `pymupdf`, `docling`, `nemotron`, `pypdf-media`, `pypdf-enhanced` | Alternative/enhanced readers and media parsing | Parser workflow; select only if required by document types and service constraints. |

## Anthropic-only and no-cloud patterns

Anthropic-only settings must replace all OpenAI defaults:

```python
from paperqa import Settings
from paperqa.settings import AgentSettings

anthropic_config = {"model_list": [{"model_name": "claude-3-5-sonnet-20240620", "litellm_params": {"model": "claude-3-5-sonnet-20240620"}}]}
settings = Settings(
    llm="claude-3-5-sonnet-20240620",
    llm_config=anthropic_config,
    summary_llm="claude-3-5-sonnet-20240620",
    summary_llm_config=anthropic_config,
    agent=AgentSettings(
        agent_llm="claude-3-5-sonnet-20240620",
        agent_llm_config=anthropic_config,
    ),
    embedding="st-multi-qa-MiniLM-L6-cos-v1",
)
```

If local sentence-transformers is unavailable, a no-cloud fallback is `embedding="sparse"`. Expect lower semantic retrieval quality than dense or hybrid embeddings.
