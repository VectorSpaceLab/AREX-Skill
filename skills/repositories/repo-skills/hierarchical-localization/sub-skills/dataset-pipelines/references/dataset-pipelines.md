# Dataset pipeline routes

This reference is for planning only. It summarizes dataset layouts, prerequisites, output-root conventions, command skeletons, and skip reasons without telling future agents to inspect upstream source files.

## Common output conventions

Most dataset workflows write a small set of recognizable artifacts:

- `sfm_sift` or `sfm_reference_empty` for the imported or placeholder reference model.
- `sfm_superpoint+superglue` for the triangulated reference model.
- `pairs-db-covis{N}.txt` for covisible database pairs.
- `pairs-query-netvlad{N}.txt` or `pairs-query-<sequence>-dist{N}.txt` for localization pairs.
- `results.txt`, `results_sparse.txt`, `results_dense.txt`, or dataset-specific submission text files.
- `submission_hloc+superglue/` for challenge-style submissions.

For plan-only requests, show the command skeleton and the required inputs, but do not start downloads or dataset-scale extraction/matching.

## Safe dry-run checklist

- Verify the dataset root and the exact named folders before any benchmark run.
- If a prerequisite download, pair file, or calibration file is missing, produce only a plan and the expected output tree.
- Use `scripts/list_pipeline_entrypoints.py` to confirm which route to pick, but do not make it import or run a pipeline.
- Never start benchmark downloads or submission runs implicitly in a planning request.
