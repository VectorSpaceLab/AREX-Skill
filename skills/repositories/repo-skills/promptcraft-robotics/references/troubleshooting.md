# Cross-cutting troubleshooting

This page collects problems that apply across the whole repository. Sub-skills add deeper workflow-specific detail.

## 1) The AirSim sample fails to start

**Symptoms**
- `ModuleNotFoundError` for `openai`, `numpy`, or `airsim`
- Config file not found
- AirSim connection fails immediately

**Likely causes**
- The Python environment was not prepared from the repo's published dependency stack.
- The script is being launched from the wrong working directory, so relative paths do not resolve.
- The AirSim simulator is not running or is not reachable.

**Recovery**
- Use the AirSim sub-skill's setup reference before trying the runtime.
- Confirm the config and prompt files are being read from the intended AirSim sample working context or from explicit paths.
- Verify the simulator is up before instantiating the wrapper.

## 2) Generated code is unsafe or unexpectedly destructive

**Symptoms**
- A response includes a code block that performs an unreviewed action.
- The sample executes code generated by the language model.

**Likely causes**
- The `chatgpt_airsim.py` loop extracts fenced code and executes it directly.
- A prompt example was copied without preserving its safety boundaries.

**Recovery**
- Treat the sample as a sandbox-only demonstration.
- Prefer prompts that are explicit about allowed helper functions and object names.
- Never run unreviewed generated code against a live simulator or robot.

## 3) The prompt example is ambiguous

**Symptoms**
- Multiple objects share a type and the example silently chooses one.
- The prompt lacks enough scene context to write a correct command.

**Likely causes**
- The example was adapted without the repo's clarification behavior.
- Exact object names were not preserved.

**Recovery**
- Ask a clarification question when the object is not uniquely identified.
- Keep the example's exact object naming rules and response style.

## 4) Coordinate or direction mistakes

**Symptoms**
- A drone or robot moves in the opposite direction from what the prompt intended.
- A placement or inspection command uses the wrong sign convention.

**Likely causes**
- The AirSim wrapper and the example families use explicit coordinate conventions that must be respected.
- The prompt was adapted too literally from another robotics example.

**Recovery**
- Re-read the relevant sub-skill reference on coordinate conventions.
- Verify whether the task is using world, vehicle, camera, or scene coordinates.
- Recompute the target position instead of guessing a sign.

## 5) Repository paths leak into runtime guidance

**Symptoms**
- A generated instruction tells future agents to open the original checkout.
- A reference links directly to source-repo files outside the generated skill tree.

**Likely causes**
- Source evidence was summarized without being bundled into the skill.

**Recovery**
- Replace the instruction with a bundled reference or script path inside `skills/disco/promptcraft-robotics/`.
- Keep original repo paths only in provenance and review artifacts, not runtime instructions.

## 6) The repository has no automated tests

**Symptoms**
- There is no `pytest` or similar repo-native test suite to run.

**Likely causes**
- This repository is a prompt collection plus a sample interface, not a library project.

**Recovery**
- Use the markdown examples as content-backed verification cases.
- Use compile/import checks for the AirSim sample instead of inventing repo tests.
