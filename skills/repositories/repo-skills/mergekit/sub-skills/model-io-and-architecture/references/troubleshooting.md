# Troubleshooting model IO and architecture

Classify the first failing layer before changing flags. Keep the exact model
reference, revision, package versions, options, and output directory in the
incident record.

| Symptom | Likely cause / evidence | Recovery |
|---|---|---|
| `ModuleNotFoundError`, import error, or a signature differs from this route | The CLI is using another Python, an incomplete editable install, or a Transformers version outside the tested combination. | Run the diagnostic with the same interpreter as the CLI. Confirm `mergekit`, `torch`, `transformers`, `safetensors`, and `huggingface_hub` versions; run `python -m pip check`. Avoid mixing a system `mergekit-yaml` with the private environment. |
| `Unable to find model files at ...` | Local directory lacks `model.safetensors`, `pytorch_model.bin`, or a supported `.index.json`; path may be a file, typo, or wrong revision snapshot. | Run the diagnostic with `--checkpoint`. Inspect `config.json`, model filename, and index `weight_map`. Use a new resolved snapshot for Hub input and retain the explicit revision. |
| `ModelReference.parse` raises `RuntimeError` | More than one `+` component, more than one `@` in a path component, or an empty/malformed reference. | Parse each model and LoRA as `MODEL[@REV]`, joined once as `MODEL[@REV]+LORA[@REV]`. Quote shell/YAML strings when special characters are present. Do not “fix” a bad ref by dropping its revision. |
| Hub config/file lookup fails for a valid-looking ID | Wrong repository revision, private/gated repo without credentials, missing model files, or a local path accidentally treated as a Hub ID. | Check access and revision outside the merge, use `transformers_cache`, and pin a commit/tag that exists. For a local directory use an absolute or correctly resolved path and verify files. Do not download an unreviewed fallback branch. |
| `More than one architecture in config?` | `config.architectures` has zero or multiple values when the architecture resolver expects one. | Correct the config or set a deliberate `override_architecture` only when the checkpoint and model class are known to match. Then inspect all target names and shapes. |
| `No JSON architecture found` / `No modules found in models` | The package has no matching definition, the architecture name is custom, or raw checkpoint names do not expose recognizable layers. | Check `model_type`, architecture name, and checkpoint keys. Use the auto-inference warnings as a gap report; provide a compatible architecture definition or route custom architecture work to extension-and-evolution. Do not assume a generic CausalLM layout. |
| `Must specify --allow-crimes ... different architectures` | Known architecture objects differ across inputs. | Prefer compatible checkpoints. If the user explicitly accepts the risk, use `--allow-crimes` only after comparing modules, layer counts, target keys, expert counts, shapes, and semantics; record that the guard was bypassed. |
| Required tensor missing although a similar key exists | Missing alias/tied candidate or checkpoint-to-Transformers layout conversion cannot prove a complete pattern. | Compare the target, aliases, tied names, `model_type`, and the complete source-key set. For MoE/packed weights check every expert and every source pattern. Add a correct architecture mapping or convert the checkpoint; do not mark a required tensor optional just to continue. |
| Converted tensor is `None`, has the wrong shape, or has wrong expert order | Transformers conversion mapping is absent/incompatible, wildcard group is partial, or checkpoint and target layouts differ semantically. | Run `can_convert_checkpoint_keys` for a key-only preflight, then test `convert_checkpoint_tensors` with tiny tensors. Verify mapping direction against the installed Transformers version and compare shape/order. Use `--allow-crimes` only for an independently justified architecture mix; it does not repair conversion. |
| Remote config/model import executes unexpected code or fails in a custom class | `trust_remote_code` is required but the repository's Python is unreviewed, revision changed, or dependencies are missing. | Keep `trust_remote_code=False` by default. If unavoidable, pin/review the revision, isolate the environment, document the trust decision, and rerun architecture/config checks. Never enable it merely because auto inference failed. |
| CPU RAM OOM or process is killed during a CPU run | Eager BIN loading, multiple live graph values, large shard threshold, cloning, or tokenizer/model materialization. | Use safetensors input when possible; reduce `out_shard_size`; disable `clone_tensors` and async writes while testing; use `lazy_unpickle` only for a compatible trusted BIN; consider CUDA storage only after VRAM preflight. A smaller output shard does not make the arithmetic graph free. |
| CUDA unavailable, invalid device, or `torch.cuda.OutOfMemoryError` | CPU-only torch/driver mismatch, device index absent, allocation test fails, or `read_to_gpu`/`low_cpu_memory` keeps too much on VRAM. | Run the diagnostic for `cpu`, `cuda`, and the exact index. Confirm torch CUDA build, availability, device count, capability, and a tiny allocation. Remove `read_to_gpu` first, then `low_cpu_memory`/`multi_gpu` as appropriate; fall back explicitly to CPU. Do not claim CUDA support from a package import alone. |
| Multi-GPU fails during graph partitioning | No detected accelerator, zero requested capacity, a main-thread-only task is in the parallel region, or a task is both per-GPU and main-thread-only. | Verify devices before constructing `MultiGPUExecutor`. Start with one-device `Executor`; then use `--multi-gpu` with synchronous writes and enough storage. If a custom task is involved, correct its scheduling hooks in the extension route. |
| Lazy `.bin` loading raises unsupported-type, archive, offset, or unpickle errors | The experimental unpickler only accepts a limited set of torch/numpy objects and expected torch ZIP storage layout. | Disable `--lazy-unpickle` and retry with the weights-only loader, or convert the checkpoint to safetensors in a trusted environment. Do not add arbitrary globals to the unpickler or treat it as a generic pickle sandbox. |
| Output shards collide, rename fails, or index points to missing files | `out_path` already contains prior output, a failed async writer left partial files, or two runs use the same basename. | Stop; do not overwrite blindly. Inspect and preserve logs, then use a fresh empty output directory. Confirm async futures completed and rerun with synchronous writes. Validate every `weight_map` path after finalization. |
| Safetensors rejects shared storage or non-contiguous tensor | A tensor is a view/shared tied tensor or has non-contiguous strides; cloning was disabled. | Let the writer make a contiguous copy; enable `--clone-tensors` when the duplicated/shared-storage warning recommends it. Expect higher memory. If safe serialization still fails, isolate the offending tensor and inspect its shape/stride before considering legacy BIN. |
| Output contains config/shards but no usable model | Merge graph may have finalized partially, optional weights were all skipped, or output config/architecture does not match names. | Enumerate the output index and load a tiny tensor with `ShardedTensorIndex`/`LazyTensorLoader`. Compare target names against the output architecture and check required versus optional decisions. A model-card file alone is not a success signal. |
| Tokenizer missing or model loads but token IDs are wrong | `copy_tokenizer=False`, donor tokenizer assets were incomplete, tokenizer task was not configured, or vocab size/config was not updated after permutation/padding. | Inspect tokenizer files and `config.json` vocabulary key. Use the configuration route to choose `tokenizer`/`tokenizer_source`; rerun only tokenizer/output completion when safe. If a chat template was requested without a tokenizer, add a tokenizer source or record that it was not saved. |
| Tagalong or generation files missing | Donor model did not contain an architecture-declared file, or donor resolution selected an unexpected base/first model. | Confirm the effective donor (`base_model` or first referenced model), local snapshot, and architecture's tagalong list. Copy a missing auxiliary file deliberately; do not fake model weights. |

## Minimal recovery sequence

1. Reproduce with `--device cpu`, `--safe-serialization`, synchronous writes, and a
   fresh temporary output, using the exact pinned revisions.
2. Run the diagnostic for each reference and checkpoint directory; save its
   output alongside the merge log.
3. Validate architecture and key conversion with tiny tensors before restoring
   CUDA, low-memory, lazy-unpickle, or multi-GPU optimizations.
4. Restore one optimization at a time and compare output keys, dtype, shape,
   tokenizer vocabulary, and index files.
5. If the cause is YAML/method/tokenizer policy, hand it to
   [merge-configs](../../merge-configs/SKILL.md); if it is a custom task,
   architecture, or method implementation, hand it to
   [extension-and-evolution](../../extension-and-evolution/SKILL.md).
