# Training settings catalog

Use this catalog to choose a valid `train_module` / `train_name` pair and to identify the data, checkpoint, model, actor, and trainer expectations before launching or modifying LTR training.

Always verify the live checkout with:

```bash
python skills/disco/pytracking/sub-skills/ltr-training/scripts/build_training_command.py --list
```

## Naming rules

- `train_module` is the directory under `ltr/train_settings`.
- `train_name` is the Python file stem in that directory.
- The source entry point imports `ltr.train_settings.<train_module>.<train_name>` and calls its `run(settings)` function.
- Avoid relying on prose-only aliases. In this snapshot, for example, the ATOM settings are actual files such as `atom`, `atom_paper`, `atom_prob_ml`, and `atom_gmm_sampl`.

## Dataset split and path notes

- GOT-10k settings commonly use `split='vottrain'` for training and `split='votval'` for validation; split text files live under `ltr/data_specs` in the checkout.
- TrackingNet settings often use set IDs. ATOM paper uses a wider train set range and a separate validation set ID.
- LaSOT settings generally use `split='train'`.
- COCO is wrapped as sequence-like data for SOT settings. TaMOs uses MOT-style COCO sequence wrapping.
- TaMOs adds YouTubeVOS, ImageNet-VID MOT/GMOT, and TAO/BURST-style data; these fields may need to be added to local config manually.
- LWL and RTS rely on VOS mask data or pregenerated masks rather than only bounding-box datasets.

## Checkpoint prerequisites by setting

- `keep_track.keep_track`: loads `super_dimp_simple.pth.tar` from `pretrained_networks` and copies compatible base-network weights into the candidate-matching model.
- `kys.kys`: loads `dimp50.pth` from `pretrained_networks` and copies DiMP backbone/classifier/bounding-box regressor weights into KYS.
- `lwl.lwl_stage1`: loads `e2e_mask_rcnn_R_50_FPN_1x_converted.pkl` from `pretrained_networks`.
- `lwl.lwl_stage2`: loads the stage-1 LWL checkpoint from the configured workspace project path.
- `lwl.lwl_boxinit`: loads the stage-2 LWL checkpoint from the configured workspace project path.
- `rts.rts50`: loads `lwl_stage2.pth` from `pretrained_networks` and requires pregenerated masks.
- TaMOs Swin setting: requires a Swin-Base backbone weight file compatible with its constructor.

## When creating a new setting

1. Copy the closest existing family setting.
2. Pick a new `train_name` file stem and keep `def run(settings):` as the only entry function expected by `run_training`.
3. Keep `settings.project_path` under `ltr/<module>/<name>` unless you intentionally want to resume/save into another project directory.
4. Update all dataset fields and p-dataset weights together; sampler probabilities are normalized, but wrong lengths or missing datasets will fail.
5. Keep actor/objective/model compatibility aligned. For example, `KLDiMPActor` expects KL regression outputs; `ToMPActor` expects dense regression outputs; `LWLActor` and `RTSActor` expect segmentation masks.
6. Reduce `samples_per_epoch`, `num_workers`, and batch size for tiny smoke experiments; restore production values for real training.
7. Re-run the command builder to validate the new module/name pair before handing off a launch command.
