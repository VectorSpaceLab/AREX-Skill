# Parsing troubleshooting

## Purpose

Use this when a parser imports correctly but the parsed output is wrong,
incomplete, or difficult to match.

## Format mismatch

**Symptoms**
- Many lines are skipped.
- `Loading ... messages done` shows a low loading rate.
- `EventTemplate` looks like raw content or all wildcards.

**Likely causes**
- The `log_format` string does not match the file layout.
- A regex preprocessor removed too much text.
- The parser's thresholds are too aggressive for the sample.

**Recovery**
1. Start with the tiny Drain smoke in `scripts/parse_tiny_drain.py`.
2. Remove regex preprocessing until the line split is stable.
3. Tune the parser threshold knobs only after the format string is correct.

## Output shape surprises

**Symptoms**
- A template file is missing.
- `ParameterList` is empty or not what you expected.
- `logmatch` cannot find the template file.

**Likely causes**
- Not every parser writes the same pair of CSVs.
- `logmatch` requires a templates CSV generated by a prior parse.
- The template file path is wrong or the parser was not run first.

**Recovery**
- Check `references/data-formats.md` for parser-specific output notes.
- Run the parser first, then feed its templates CSV into `logmatch`.
- If a parser only writes structured rows, treat that as expected behavior.

## `logmatch` loader escape bug

**Symptoms**
- `RegexMatch.match` raises `regex._regex_core.error: bad escape \s` when it reads the log format.

**Likely cause**
- The upstream `logloader.py` uses a legacy replacement string that the current `regex` package rejects.

**Recovery**
- Use `scripts/match_templates.py`, which patches the loader at runtime before matching.
- If you are experimenting manually, patch `logparser.utils.logloader.LogLoader._generate_logformat_regex` so the whitespace replacement emits a literal `r"\\s+"`.

## Path and directory issues

**Symptoms**
- Output files appear in an unexpected location.
- A parser seems to succeed but no files are found where you expected.

**Likely causes**
- Some parsers build output paths by concatenating strings.
- A missing trailing slash changes the final filename.

**Recovery**
- Pass an explicit output directory that already exists.
- Keep the output path normalized and, when in doubt, include the trailing
  slash expected by the parser.

## When to move on

If the issue is not a simple format or threshold mistake, check whether the
parser is actually part of `specialized-parsers` before changing any code or
trying a different backend.
