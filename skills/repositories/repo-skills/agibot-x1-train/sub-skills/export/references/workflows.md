# Export workflows

This route covers the repository's model-side conversion path only. It does not
train a policy, start interactive playback, or run MuJoCo. The two source entry
points implement different stages:

- `humanoid/scripts/export_policy_dh.py`: runner checkpoint → JIT policy.
- `humanoid/scripts/export_onnx_dh.py`: existing JIT policy → ONNX policy.

The bundled [`preflight_export.py`](../scripts/preflight_export.py) is an
advisory, dependency-light helper; it is not a replacement for either source
entry point.

## 1. Establish the checkpoint handoff

1. Obtain a completed runner checkpoint from the sibling
   [training checkpoint handoff](../../training/SKILL.md#checkpoints-and-handoff).
   A normal artifact is
   `logs/<experiment_name>/exported_data/<run>/model_<iteration>.pt`.
2. Confirm that task and experiment identify the same registered configuration.
   The checked-in registry exposes `x1_dh_stand`, whose experiment name is also
   `x1_dh_stand`.
3. From the export sub-skill directory, select the path without deserializing it:

   ```bash
   python scripts/preflight_export.py \
     --task x1_dh_stand --kind jit --logs-root logs \
     --experiment-name x1_dh_stand --load-run <run> \
     --checkpoint <iteration>
   ```

4. For a **trusted local checkpoint**, add `--inspect-checkpoint` to load its
   `model_state_dict` on CPU and check representative X1 DH layer shapes.
   `torch.load` can execute pickle payloads, so never use that flag on an
   untrusted file. A path-only pass does not prove architecture compatibility.

## 2. Check the environment gate

The source scripts begin by importing `humanoid.envs` and then use
`task_registry.get_cfgs(name=args.task)`. That import chain requires Isaac Gym
Preview 4 in this checkout, even though the conversion computation is performed
by PyTorch. In an environment without that private/legacy dependency, record
`BLOCKED_REQUIRED_BACKEND` and stop the full export. Do not fake an Isaac Gym
module or report a helper-only check as source-export verification.

The repository README describes Python 3.8, PyTorch 1.13.1 with CUDA 11.7,
NumPy 1.23.x, editable installation of the project, and Isaac Gym Preview 4.
Use the approved project environment for the source checkout; do not download
models or silently change the PyTorch version. ONNX export also requires a
PyTorch-compatible `onnx` package. `onnxruntime` is optional and only needed
when a CPU inference smoke check is explicitly requested.

Check already-installed packages without changing the environment:

```bash
python -c "import torch; print(torch.__version__)"
python -c "import onnx; print(onnx.__version__)"
```

A missing package is an environment gap, not permission to install or download
it. Obtain approval before changing the export environment.

## 3. Checkpoint → JIT

Run from the repository root in the verified Isaac Gym environment:

```bash
python humanoid/scripts/export_policy_dh.py \
  --task=x1_dh_stand --load_run=<run> --checkpoint=<iteration>
```

`--task` selects registered environment and training configuration.
`--load_run` is a run directory under `exported_data`. If the flag is omitted,
the script replaces its missing value with integer `-1`, and the helper selects
the lexicographically last run. Do **not** pass literal `--load_run=-1`: the
shared parser stores it as a string and the source helper may instead look for a
directory named `-1`. An explicit run is safest.

`--checkpoint` is an integer. `-1` selects the last filename containing
`model`; explicit `N` selects `model_N.pt`. The script loads the
`model_state_dict` key with strict `load_state_dict` behavior.

The exporter reconstructs `ActorCriticDH`, wraps the actor, long-history CNN,
and state estimator in `ExportedDH`, moves the copied modules to CPU, applies
`torch.jit.script`, and saves:

```text
logs/<experiment_name>/exported_policies/<YYYY-MM-DD_HH-MM-SS>/policy_dh.jit
```

The timestamp is generated by the source script; there is no output-path flag.
Do not use the README's singular `log/` spelling: source code uses `logs/`.
Keep the printed `Load model from:` and `Export policy to:` paths as the stage
handoff record.

## 4. JIT → ONNX

Run from the repository root in the verified Isaac Gym environment:

```bash
python humanoid/scripts/export_onnx_dh.py \
  --task=x1_dh_stand --load_run=<jit_timestamp>
```

This script does **not** read a training checkpoint. It selects a serialized JIT
artifact under `logs/<experiment_name>/exported_policies`. Omit `--load_run` to
request source “latest” behavior, but pass the exact JIT timestamp for
reproducibility. As above, do not pass literal `--load_run=-1` through the
source parser.

The shared parser exposes `--checkpoint`, but the ONNX script's local loader
ignores it. Never use that flag to select a training iteration for this stage.
Preflight the selected `policy_dh.jit` before conversion.

The source creates a random example input with shape `(1, 3102)` and calls
`torch.onnx.export` with opset 11, constant folding, and names `input`/`output`.
It writes:

```text
logs/<experiment_name>/exported_onnx/<YYYY-MM-DD_HH-MM-SS>/x1_policy.onnx
```

The filename is `<task.split('_')[0]>_policy.onnx`; for `x1_dh_stand`, it is
`x1_policy.onnx`. The README's `exported_policies` ONNX destination is stale;
follow source behavior and preserve the printed output path.

## 5. Validate each artifact

For JIT:

```bash
python scripts/preflight_export.py \
  --task x1_dh_stand --kind jit --artifact path/to/policy_dh.jit
```

For ONNX, check the graph and optionally request CPU ONNX Runtime inference:

```bash
python scripts/preflight_export.py \
  --task x1_dh_stand --kind onnx --artifact path/to/x1_policy.onnx \
  --run-runtime-check
```

The fixed contracts are one input `(1, 3102)` and one output `(1, 12)`. Helper
exit status `0` means the requested available checks passed, `1` means an
artifact/path check failed, `2` means CLI or task-contract error, and `3` means
a requested validation was skipped because its optional library was absent.
A `SKIP` is not evidence that the artifact is valid.

A successful CPU artifact check validates only the serialized model. It does
not validate observation construction, Isaac Gym simulation, MuJoCo sim2sim,
controller integration, or robot safety. Route those tasks back through the
siblings named in the export sub-skill router.
