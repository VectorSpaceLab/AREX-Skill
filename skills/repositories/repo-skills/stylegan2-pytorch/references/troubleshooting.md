## CUDA import assertion

**Symptom**

```text
AssertionError: You need to have an Nvidia GPU with CUDA installed.
```

**Cause**

The package asserts `torch.cuda.is_available()` while importing the main module.
Even help and signature inspection can fail in a CPU-only or CPU-wheel PyTorch
environment.

**Recovery**

1. Verify the host sees an NVIDIA GPU:
   ```bash
   nvidia-smi
   ```
2. Verify the Python environment has a CUDA-enabled torch build:
   ```bash
   python - <<'PY'
   import torch
   print(torch.__version__, torch.version.cuda)
   print(torch.cuda.is_available(), torch.cuda.device_count())
   if torch.cuda.is_available():
       print(torch.cuda.get_device_name(0), torch.cuda.get_device_capability(0))
       torch.empty((1,), device='cuda')
   PY
   ```
3. If `torch.cuda.is_available()` is false, reinstall PyTorch/torchvision with a
   CUDA wheel compatible with the driver. A CPU-only torch install is not enough
   for this package.

## Python version and Aim install issues

**Symptom**

Installation fails while resolving or building `aim`, often mentioning
`aimrocks`.

**Cause**

`stylegan2_pytorch` imports `aim` at module import time, so the package's base
install depends on Aim. Some Aim/Aimrocks releases do not support the newest
Python versions.

**Recovery**

- Prefer Python 3.10 or 3.11 for this repository.
- Install CUDA PyTorch/torchvision first, then install `stylegan2_pytorch`.
- If a mirror lacks compatible `aimrocks` wheels, retry against the official
  PyPI index for Python 3.10/3.11. Do not work around this by deleting Aim from
  the package unless the user is deliberately patching the source.

## Missing runtime dependency on import

**Symptom**

A traceback names modules such as `fire`, `retry`, `einops`, `kornia`, `aim`,
`vector_quantize_pytorch`, `torchvision`, or `PIL`.

**Recovery**

- Reinstall from package metadata rather than copying source files:
  ```bash
  pip install stylegan2_pytorch
  # or from a clone
  pip install -e .
  ```
- Then run:
  ```bash
  python scripts/check_install.py
  ```
  from this generated skill directory if you want a non-training import/CUDA
  check.

## Optional feature dependencies

Some flags need packages or services beyond the minimum package install:

| Feature | Signal | Requirement / response |
| --- | --- | --- |
| `--fp16` | `AssertionError: Apex is not available` | NVIDIA Apex is optional and must match CUDA/PyTorch. Prefer leaving `--fp16` off unless the environment is already prepared for Apex. |
| `--calculate-fid-every` | `ModuleNotFoundError: pytorch_fid` | Install `pytorch-fid` only when FID calculation is required; it is not needed for ordinary training or generation. |
| `--log` | Aim imports succeed but no UI appears | The package can create an Aim session, but the UI requires running Aim's service separately. Do not assume Docker/service access exists. |
| `--cl-reg` | Import/runtime failure in contrastive regularization | Requires `contrastive_learner`; it is incompatible with transparent images and not recommended with multi-GPU in this source snapshot. |

## CLI parser confusion

The CLI is generated by Python Fire. Fire help shows flags such as
`--image_size` and `--batch_size`, while the README examples often use
hyphenated forms like `--image-size` and `--batch-size`. If a command fails at
argument parsing, run:

```bash
stylegan2_pytorch -- --help
```

Then retry the exact underscore spelling from help.
