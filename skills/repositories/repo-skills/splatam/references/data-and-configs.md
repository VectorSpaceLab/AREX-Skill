# Data and Configuration Reference

## Purpose

Read this when adapting a SplaTAM config, relocating a dataset, checking captured iPhone data, or explaining where outputs are written.

## Config loading model

SplaTAM entry points accept a Python file path, load it with `SourceFileLoader`, and read a module-level `config` dictionary. The config file is executable Python, not YAML. It may compute names, frame counts, or image sizes before building the dictionary.

Common top-level keys:

| Key | Meaning |
| --- | --- |
| `workdir` | Base output directory or capture dataset directory, depending on the script. |
| `run_name` | Output subdirectory for reconstruction/optimization/eval scripts. |
| `seed` | Seed passed to `seed_everything`. |
| `primary_device` | Usually `cuda:0`; all selected workflows require CUDA. |
| `data` | Dataset name, path, frame range, image sizes, and optional gradslam YAML. |
| `tracking` | Pose tracking optimizer settings for `scripts/splatam.py` and live demo. |
| `mapping` | Mapping/update settings for SLAM and evaluation. |
| `train` | Post-SplaTAM and GT-pose Gaussian splatting optimization settings. |
| `viz` | Open3D viewer/rendering parameters. |
| `use_wandb`, `wandb` | W&B logging controls; disable for local non-credentialed runs. |

## Dataset families

| Dataset family | Config evidence | Data root convention | Notes |
| --- | --- | --- | --- |
| Replica | `configs/replica/splatam.py`, `configs/data/replica.yaml` | `./data/Replica/<scene>` | Public configs enumerate `room0`, `room1`, `room2`, `office0`, `office1`, `office2`, `office_`, `office4`. |
| Replica-V2 | `configs/replica_v2/splatam.py`, `configs/data/replica_v2.yaml` | Config-specific root | Uses `dataset_name: replicav2` and depth scale `1000.0`. |
| TUM RGB-D | `configs/tum/splatam.py`, `configs/data/TUM/*.yaml` | TUM sequence directory | TUM YAML provides intrinsics, crop edge, and `png_depth_scale: 5000.0`. |
| ScanNet | `configs/scannet/splatam.py`, `configs/data/scannet.yaml` | `scannet/<scene>/frames/{color,depth,intrinsic,pose}` | ScanNet `.sens` extraction is external to SplaTAM. |
| ScanNet++ | `configs/scannetpp/*` | Config-specific root | Has dedicated SLAM, eval, post-opt, and novel-view configs. |
| iPhone/NeRFCapture | `configs/iphone/*` | `./experiments/iPhone_Captures/<scene>` by default | Capture scripts write `rgb/`, `depth/`, and `transforms.json`; SLAM configs use `dataset_name="nerfcapture"`. |

GradSLAM YAML files define camera intrinsics and depth scale for datasets that do not store a full NeRFCapture-style manifest.

## Reconstruction output convention

For `scripts/splatam.py`, `scripts/post_splatam_opt.py`, `scripts/gaussian_splatting.py`, and `scripts/eval_novel_view.py`, the common result root is:

```text
<config["workdir"]>/<config["run_name"]>/
```

Typical contents:

- `config.py`: copy of the experiment file used for the run.
- `params.npz`: final Gaussian, pose, intrinsic, and metadata arrays.
- `params<time_idx>.npz`: optional checkpoint files when checkpoint saving is enabled.
- `keyframe_time_indices<time_idx>.npy`: checkpoint support file for SLAM resume.
- `eval/`, `eval_train/`, or `eval_nvs/`: evaluation images and metrics depending on script/config.
- `splat.ply`: generated by `scripts/export_ply.py` after `params.npz` exists.

Run the bundled reconstruction result validator before handing an output to export/eval users:

```bash
python sub-skills/reconstruction/scripts/check_result_bundle.py \
  --result-dir <workdir>/<run_name>
```

## NeRFCapture dataset layout

`scripts/nerfcapture2dataset.py` and `scripts/iphone_demo.py` create a NeRFCapture-style RGB-D dataset under `config["workdir"]`:

```text
<scene>/
  rgb/
    0.png
    1.png
    ...
  depth/
    0.png
    1.png
    ...
  transforms.json
```

`transforms.json` includes global camera fields (`fl_x`, `fl_y`, `cx`, `cy`, `w`, `h`, `integer_depth_scale`) and a `frames` list. Each frame has a `transform_matrix`, RGB `file_path`, camera intrinsics, image size, and optional `depth_path`.

Run the bundled capture dataset validator before an offline SLAM run:

```bash
python sub-skills/capture/scripts/validate_nerfcapture_dataset.py \
  --dataset-dir <captured-scene> --require-depth
```

## Config-editing checklist

Before launching a run:

1. Set `use_wandb=False` unless W&B credentials/network are intentionally available.
2. Confirm `primary_device` matches an available CUDA device.
3. Confirm `data.basedir`, `data.sequence`, `start`, `end`, `stride`, and `num_frames` match the actual dataset.
4. For quick smoke runs, reduce `num_frames`, `tracking.num_iters`, `mapping.num_iters`, and image sizes, but do not infer benchmark quality from the result.
5. For post-SplaTAM optimization, set `data.param_ckpt_path` to the upstream `params.npz` produced by SLAM.
6. For visualization-only configs, provide either `scene_path` or a matching `workdir/run_name` pair plus `viz` settings.
