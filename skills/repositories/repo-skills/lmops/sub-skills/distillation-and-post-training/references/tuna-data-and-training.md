# Tuna data and training

Tuna is the ranking-finetuning branch in this sub-skill. Use it for
probabilistic ranking, contextual ranking, GPT-4 ranking provenance, and the
sequential Tuna finetuning recipe.

## Training stages

The Tuna workflow is staged:

1. **Supervised finetuning** on Alpaca-style instruction data.
2. **Probabilistic ranking** finetuning using probability-scored candidate
   responses. This produces the intermediate model often called Tuna_p.
3. **Contextual ranking** finetuning using GPT-4-ranked responses generated by
   the intermediate model.
4. **Tuna** is the sequential application of the probabilistic and contextual
   ranking stages.

The training shell concept wraps `deepspeed train_tuna.py` with a model name,
JSON data path, output directory, number of epochs, train batch size, gradient
accumulation, learning rate, MLE weight, ranking margin, length penalty,
DeepSpeed config, gradient checkpointing, and fp16.

## Formatted ranking training schema

The ranking trainer consumes a JSON array of objects. The minimal training
shape is shared by probabilistic and contextual ranking finetuning:

```json
{
  "id": 0,
  "instruction": "full prompt or instruction text",
  "output": ["candidate response A", "candidate response B"],
  "score": [1.0, 0.5]
}
```

Validation rules:

- `id` must be present.
- `instruction` must be a string.
- `output` must be a list of candidate strings.
- `score` must be a numeric list with the same length as `output`.
- Ranking needs at least two candidates.
- Do not assume a fixed score scale: provided data may include sentinel values,
  log-probability-derived scores, or rank-derived integers.

Use `scripts/check_tuna_ranking_data.py` with `--schema probabilistic` for this
formatted training shape. The same checker can validate contextual formatted
training data because the training shape is identical.

## Raw contextual ranking schema

Raw contextual ranking data records the provenance of GPT-4 ranking before it is
converted into the training shape. The minimal raw contextual object is:

```json
{
  "prompt": "prompt sent to the judge model",
  "instruct": "instruction text",
  "generation": ["response 0", "response 1", "response 2", "response 3"],
  "id": 0,
  "gpt_eval": "judge-model explanation and scores",
  "rank_str": "[4, 3, 0, 1, 2]",
  "ranks": [4, 3, 0, 1, 2],
  "response_4": "judge-model reference answer"
}
```

Validation rules:

- `generation` should contain the four model responses offered to the judge.
- The rank list uses response ids `0` through `4`, where `4` refers to
  `response_4`; it may be shorter than five entries when the judge drops
  duplicate responses.
- `rank` and `ranks` are treated as aliases because source evidence uses the
  plural key while prose may describe the singular key.
- `gpt_eval`, `rank_str`, and `response_4` preserve GPT-4 provenance; losing
  them makes the contextual ranking artifact incomplete.

Use `scripts/check_tuna_ranking_data.py` with `--schema contextual` for this raw
provenance shape.

## Trainer behavior

The ranking trainer loads JSON data, tokenizes each instruction and candidate
response group, sorts candidates by score, and passes the result to a custom
trainer. The custom trainer computes a candidate margin-ranking loss and adds an
MLE loss scaled by `mle_weight`.

Important knobs:

- `mle_weight`: relative strength of the language-modeling loss.
- `margin`: separation enforced between ranked candidates.
- `lenpen`: length-penalty value passed through the training wrapper.
- `model_max_length`: truncation length inherited from Transformers training
  arguments.
- `deepspeed`: training config; the provided concept uses ZeRO-3 with CPU
  offload and fp16.

## Generation and GPT-4 provenance

Contextual ranking data is not just a training file. It depends on two earlier
steps:

1. Generate multiple candidate responses with the intermediate Tuna_p model.
2. Ask GPT-4 to score/rank those responses and produce an additional reference
   response.

The ranking-generation utilities depend on OpenAI credentials, rate-limit
handling, JSON/jsonlines writing, DeepSpeed inference, ROUGE duplicate checks,
and stable IDs. Partial or resumed outputs must be schema-checked before use.

## Common mistakes

- Passing a single response string where the trainer expects a list of candidate
  strings.
- Using `rank`/`ranks` inconsistently without preserving the actual rank list.
- Dropping `response_4`, which removes the judge-provided reference answer.
- Allowing `output` and `score` lengths to diverge after filtering.
- Treating contextual ranking data as license-free: it may inherit restrictions
  from Alpaca-style data, model checkpoints, and OpenAI outputs.
