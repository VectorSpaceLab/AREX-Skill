# Instruction augmentation and data selection

This reference covers:

- Instruction Pre-Training corpus synthesis.
- Data Selection via Optimal Control / PDS planning.

## Instruction Pre-Training

Instruction Pre-Training augments raw corpora with instruction-response pairs generated by a vLLM-backed synthesizer.

### Core planning facts

- The synthesizer is treated as an open-source model served through vLLM.
- Raw text is processed in rounds to build multi-shot examples.
- The generated text is formatted as reading material plus comprehension-style question/answer blocks.
- The helper logic tracks previous synthetic examples so that later rounds can inherit context when the total length permits it.

### Practical interpretation

When a user asks for instruction corpus generation, ask for:

- The raw text source.
- The target domain, if any.
- The maximum context length.
- The maximum number of new tokens for synthesized outputs.
- The number of rounds or shots desired.
- Whether the caller has a locally available vLLM environment.

### Safe working rule

If the user only needs a planning artifact, do not try to run model synthesis. Instead:

- Describe the multi-round synthesis shape.
- State the model and tokenizer compatibility constraints.
- Explain that the synthesizer may need GPU memory and network access if the model is not already cached.

## Data Selection via Optimal Control / PDS

The PDS pipeline is staged. The important order is:

1. Tokenize the large corpus.
2. Convert tokenization if the scorer and pretrain model use different tokenizers.
3. Sample proxy data.
4. Train the small baseline model.
5. Prepare the PMP-solver data.
6. Solve the control problem.
7. Prepare data-scorer training data.
8. Train the data scorer.
9. Infer scores on large data.
10. Select the final data.
11. Pre-train baseline and PDS models.
12. Evaluate the models.

### Stage families

| Family | Purpose | Typical missing input |
| --- | --- | --- |
| Corpus tokenization | Build the large training shard set | Raw corpus root, tokenizer choice, output root |
| Proxy sampling | Select a small proxy subset for PMP solving | Tokenized corpus and proxy count |
| PMP solving | Estimate data quality scores | Baseline model, proxy data, dev data |
| Data scorer training | Learn a scorer from proxy labels | Training set, scorer checkpoint, tokenizer alignment |
| Scorer inference | Score the full corpus | Trained scorer checkpoint and inference data |
| Data selection | Filter the corpus by scores | Score path, ratio, gumbel temperature, matching tokenizers |
| Pre-training | Train baseline and PDS models | Selected corpus, checkpoints, schedule |
| Evaluation | Run offline evaluations | Model checkpoints and evaluation corpus |

### Bundled planner

Use `scripts/pds_pipeline_planner.py` to validate placeholders and produce a stage checklist without launching training.

```bash
python scripts/pds_pipeline_planner.py --base-path ./pds-workspace --json
```

### Important path and checkpoint considerations

- The scorer checkpoint and tokenizer may come from a different model family than the pre-training model.
- The scorer stage often needs a separate checkpoint root and tokenizer root.
- The proxy stage depends on a small sampled subset, not the whole corpus.
- The selection stage depends on score files, not only model weights.
- The evaluation stage depends on both the selected corpus and the target evaluation data.

### Common failure patterns

- Huge corpus paths exist but the tokenizer output is missing.
- Proxy data is sampled from the wrong shard family.
- The scorer tokenizer does not match the data scorer checkpoint.
- The score directory is present but the score shards are incomplete.
- The selected-data directory is missing because the scoring stage was skipped.
- The pre-training script is launched before the data-selection outputs exist.

## What not to do

- Do not conflate planning with execution.
- Do not treat the source shell scripts as mandatory runtime dependencies inside this skill.
- Do not route this workflow to MiniLLM/DPKD/Tuna or to VeRL-style RL workflows.
