# LatentSync data-preparation formats and layout

The preprocessing pipeline treats `input_dir` as the raw local `.mp4` tree and writes stage outputs as sibling directories beside it. The final tree consumed by later LatentSync training workflows is `high_visual_quality/`.

## Canonical workspace layout

If the raw clips live under `workspace/raw/`, the default data-prep layout is:

```text
workspace/
├── raw/                         # input_dir; .mp4 files may be nested
├── resampled/                   # 25 FPS video, 16 kHz audio
├── shot/                        # scene/shot splits from PySceneDetect
├── segmented/                   # roughly 5-second chunks
├── high_resolution/             # optional face-size prefilter
├── affine_transformed/          # aligned face crops with original audio reattached
├── av_synced_3/                 # SyncNet-gated clips; suffix follows sync_conf_threshold
├── high_visual_quality/         # final training-ready clips
└── temp/                        # scratch only; path is caller-controlled
```

The runner computes `workspace/` from `input_dir.parent`, matching the repository pipeline's use of `os.path.dirname(input_dir)`.

## Raw input tree

Expected input:

- Local `.mp4` files.
- Optional nested subdirectories, such as speaker/session IDs.
- Each useful clip should contain a decodable video stream, a decodable audio stream, and a single visible talking face.

Important behavior:

- Most stages recurse through the input tree and preserve relative directory structure.
- `remove_broken_videos` is destructive: unreadable files are deleted from `input_dir`.
- Do not point the destructive stage at the only copy of raw data.
- Network crawling/downloading is outside this sub-skill; pass an already-local raw tree.

## Stage output schemas

### 1. Raw tree after `remove_broken_videos`

```text
raw/
├── clip_a.mp4
└── speaker_001/
    └── clip_b.mp4
```

- Same tree as input, minus corrupt/unreadable `.mp4` files.
- Brokenness is defined by whether `latentsync.utils.av_reader.AVReader` can open synchronized audio/video streams.

### 2. `resampled/`

```text
resampled/
├── clip_a.mp4
└── speaker_001/
    └── clip_b.mp4
```

- Mirrors the raw tree.
- Leaf names are preserved.
- Video is 25 FPS.
- Audio is mono-compatible 16 kHz data as produced by `ffmpeg -ar 16000`.
- Existing 25 FPS clips are not frame-resampled, but their audio is still normalized.

### 3. `shot/`

```text
shot/
├── clip_a_shot_001.mp4
├── clip_a_shot_002.mp4
└── speaker_001/
    └── clip_b_shot_001.mp4
```

- Mirrors the source folder structure.
- Filenames are derived from the input stem and the scene number generated by the `scenedetect` split-video command.
- Shot detection uses adaptive detection with threshold `2`.

### 4. `segmented/`

```text
segmented/
├── clip_a_shot_001_000.mp4
├── clip_a_shot_001_001.mp4
└── speaker_001/
    └── clip_b_shot_001_000.mp4
```

- Mirrors the `shot/` tree.
- Each shot is split into approximately 5-second segments.
- Segment filenames use the source stem plus a zero-padded integer pattern (`_%03d.mp4`).
- Very short or codec-problematic clips may produce fewer segments than expected.

### 5. `high_resolution/` optional

```text
high_resolution/
└── ... same relative layout as segmented/ for retained clips ...
```

- Input is normally `segmented/`.
- Output contains copies only for clips whose detected face box is at least the configured `resolution` in both width and height.
- This gate is optional and useful when the corpus is too large or noisy to send directly to GPU alignment.

### 6. `affine_transformed/`

```text
affine_transformed/
└── ... same relative layout and leaf filenames as segmented/ or high_resolution/ ...
```

- Input is `segmented/` by default or `high_resolution/` when that optional gate is enabled.
- Leaf names and relative directories are preserved.
- Each frame is aligned from InsightFace landmarks and resized to the target resolution, typically `256 x 256`.
- The original audio track is extracted and muxed back into the newly written aligned video.
- Clips with failed face detection are skipped, not copied.

### 7. `affine_transformed/` after optional `remove_incorrect_affined`

- Same path as above; this optional stage deletes files in place.
- The stage keeps only clips where MediaPipe detects exactly one face in every decoded frame.
- Use this only when you accept destructive cleanup of the aligned tree.

### 8. `av_synced_<threshold>/`

```text
av_synced_3/
└── ... same relative layout and leaf filenames as affine_transformed/ for retained clips ...
```

- Suffix is the numeric `sync_conf_threshold` argument.
- The default threshold is `3`.
- A clip is retained only if:
  - mean SyncNet confidence is at least the threshold, and
  - absolute AV offset is at most `6` frames.
- If offset is non-zero, the stage shifts the audio by `offset / 25` seconds using `ffmpeg -itsoffset`.

### 9. `high_visual_quality/`

```text
high_visual_quality/
└── ... same relative layout and leaf filenames as av_synced_<threshold>/ for retained clips ...
```

- Final data-prep output.
- The stage samples first, middle, and last frames, crops/normalizes them for HyperIQA, and computes a 0-100 quality score.
- Clips with score `>= 40` are copied.
- This is the tree later training configs point at for processed data.

## Scratch layout

`temp_dir` is not an input dataset and not a persistent output. It may contain temporary files such as:

```text
temp/
├── process_0/
│   ├── *_temp.wav
│   ├── *_temp.mp4
│   ├── detect_results/
│   └── syncnet_eval_results/
└── process_1/
    └── ...
```

Stage-specific notes:

- Alignment deletes and recreates the top-level scratch directory at stage start.
- SyncNet detection repeatedly deletes and recreates `crop/`, `video/`, `frames/`, and nested temp directories under each process scratch tree.
- `latentsync.utils.util.read_video(change_fps=True)` also uses a hard-coded `temp/` directory, so avoid running unrelated LatentSync video readers concurrently in the same working directory.

## Auxiliary checkpoint layout

The data-prep gates expect these files relative to the checkout root used by the runner:

```text
checkpoints/
└── auxiliary/
    ├── syncnet_v2.model        # SyncNet AV confidence/offset gate
    ├── sfd_face.pth            # S3FD detector used by SyncNet face cropping
    └── koniq_pretrained.pkl    # HyperIQA visual-quality gate
```

Do not hide missing checkpoints inside worker exceptions. The preflight checker and runner name missing files before heavy GPU work starts.

## Path semantics in bundled scripts

- `--repo-root` points to a LatentSync checkout so helper scripts can import repo modules when no package metadata is installed.
- `--input-dir` may be absolute; if relative, it is resolved against `--repo-root`.
- `--temp-dir` may be absolute; if relative, it is resolved against `--repo-root`.
- `--start-at` and `--stop-after` slice the planned stage list while preserving the original sibling directory names.
- JSON output from the helpers contains absolute resolved paths for execution clarity; runtime Markdown avoids machine-specific absolute paths.

## Data quality assumptions

The downstream training code assumes clips are already:

- 25 FPS.
- 16 kHz audio.
- Short segments, usually around 5 seconds after segmentation.
- Centered/aligned face crops at the configured resolution.
- SyncNet confidence filtered and audio offset corrected.
- HyperIQA quality filtered.

If a later training or evaluation route reports FPS, sync, missing-face, or low-quality issues, route the data back through this sub-skill rather than patching the training command.
