# Pytorch-UNet prediction CLI reference

This reference distills the repository's prediction command-line interface and file behavior. The original interface is `predict.py` in a user Pytorch-UNet checkout; this generated skill bundles `scripts/prediction_cli_wrapper.py` so future agents can preview or intentionally execute that command without depending on the checkout used during skill generation.

## Safe wrapper usage

Preview a prediction command without reading checkpoints/images or writing masks:

```bash
python scripts/prediction_cli_wrapper.py --repo-root "$REPO_ROOT" -- --model MODEL.pth --input image.jpg --output mask.png --classes 2
```

Execute only after the user approves the file reads/writes:

```bash
python scripts/prediction_cli_wrapper.py --repo-root "$REPO_ROOT" --execute -- --model MODEL.pth --input image.jpg --output mask.png --classes 2
```

`$REPO_ROOT` should point to the user's Pytorch-UNet checkout containing `predict.py`, `unet/`, and `utils/`. For no-download functional checks that do not need user files, prefer `scripts/prediction_smoke.py`.

## Verified parser contract

The prediction CLI description is:

```text
Predict masks from input images
```

Verified options accepted by the underlying `predict.py` parser:

| Option | Default | Meaning |
| --- | --- | --- |
| `--model FILE`, `-m FILE` | `MODEL.pth` | Checkpoint state dict to load. |
| `--input INPUT [INPUT ...]`, `-i INPUT [INPUT ...]` | required | One or more input image filenames. |
| `--output OUTPUT [OUTPUT ...]`, `-o OUTPUT [OUTPUT ...]` | generated names | Output mask filenames. If omitted, each input `image.jpg` becomes `image_OUT.png`. |
| `--viz`, `-v` | off | Display input and masks interactively with matplotlib. |
| `--no-save`, `-n` | off | Do not write output mask files. Useful with `--viz` or for smoke checks. |
| `--mask-threshold T`, `-t T` | `0.5` | Threshold for single-channel (`n_classes == 1`) sigmoid masks. |
| `--scale SCALE`, `-s SCALE` | `0.5` | Input image downscale factor before inference. Output is resized back to original image size. |
| `--bilinear` | off | Construct the model with bilinear upsampling. Must match the checkpoint. |
| `--classes CLASSES`, `-c CLASSES` | `2` | Number of model output classes. Must match the checkpoint. |
| `-h`, `--help` | n/a | Print parser help. |

## Common argument sets

Single-image prediction arguments:

```bash
--model checkpoint_epoch5.pth --input image.jpg --output image_mask.png --classes 2 --scale 0.5
```

Multiple images with generated output names:

```bash
--model checkpoint_epoch5.pth --input image1.jpg image2.jpg image3.jpg --classes 2 --scale 0.5
```

Visualization without saving:

```bash
--model checkpoint_epoch5.pth --input image.jpg --viz --no-save --classes 2
```

Binary one-channel checkpoint:

```bash
--model binary_model.pth --input image.jpg --classes 1 --mask-threshold 0.5
```

If the checkpoint was trained with `--bilinear`, include `--bilinear` during prediction.

## Output filename behavior

If `--output` is omitted, output names are generated by appending `_OUT.png` to each input stem. Examples:

| Input | Generated output |
| --- | --- |
| `car.jpg` | `car_OUT.png` |
| `frames/frame001.jpeg` | `frames/frame001_OUT.png` |
| `scan.slice.png` | `scan.slice_OUT.png` |

When providing `--output`, give one output path per input image. The underlying code indexes `out_files[i]`; too few output paths can fail after some images are processed. Output parent directories are not created automatically.

## Side effects and safety

A real prediction run:

- Loads the checkpoint with `torch.load(..., map_location=device)`.
- Pops `mask_values` from the state dict, defaulting to `[0, 1]`.
- Loads the state dict into a freshly constructed `UNet(n_channels=3, n_classes=args.classes, bilinear=args.bilinear)`.
- Writes output masks unless `--no-save` is set.
- Opens matplotlib windows when `--viz` is set.

Do not use `--viz` in headless automation unless a display backend is configured. Use the bundled smoke helper for a deterministic local check.

## Checkpoint and class matching checklist

Before executing prediction, confirm:

- `--classes` equals the checkpoint's trained `n_classes`.
- `--bilinear` is present only if the checkpoint was trained with bilinear upsampling.
- The checkpoint is a raw `state_dict` compatible with `UNet`, not an optimizer checkpoint wrapper.
- Input images are compatible with the prediction CLI's fixed `n_channels=3` model. For grayscale or custom-channel checkpoints, use an API workflow with a matching model.
- The checkpoint `mask_values` palette has at least one entry for every class ID the model can predict.

## Safe smoke alternative

For no-download functional checking, use the bundled `scripts/prediction_smoke.py`. It creates a temporary dummy checkpoint and synthetic image, exercises `predict_img` and `mask_to_image`, and prints JSON. It is a safer check than running a real checkpoint on user data when you only need to verify imports and output conversion.
