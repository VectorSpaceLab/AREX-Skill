# Geocameras and Rendering Operator Reference

This reference distills BlenderGIS camera behavior from the add-on camera operators. It is self-contained for future operation; do not reopen the source repository to use these APIs.

## Menu Placement

After the add-on is enabled, the camera tools appear under `GIS > Camera` in the 3D View menu:

- `Georender` → `camera.georender`
- `Geophotos` → `camera.geophotos`
- refresh/switch entry → `camera.geophotos_setactive`

## `camera.geophotos` — create objects from geotagged photos

Purpose: create target cameras, cameras, empties, or move the scene cursor from JPEG/TIFF EXIF GPS tags.

### Invocation

Typical UI path: `GIS > Camera > Geophotos`, then select one or more `.jpg`, `.jpeg`, `.tif`, or `.tiff` files.

Script-style call in an already georeferenced Blender scene:

```python
import bpy

bpy.ops.camera.geophotos(
    'EXEC_DEFAULT',
    directory='/photos/',
    files=[{'name': 'IMG_0001.jpg'}, {'name': 'IMG_0002.jpg'}],
    exifMode='TARGET_CAMERA',
)
```

Use the Python call only in a Blender context where file-list operator properties are supported; the UI file browser is more reliable for interactive use.

### Options

| Property | Values | Default | Meaning |
| --- | --- | --- | --- |
| `directory` | directory path | empty | Folder containing selected photo files. |
| `files` | Blender file-list elements | empty | Selected photo basenames from `directory`. |
| `filter_glob` | `*.jpg;*.jpeg;*.tif;*.tiff` | fixed | File browser filter. |
| `exifMode` | `TARGET_CAMERA`, `CAMERA`, `EMPTY`, `CURSOR` | `TARGET_CAMERA` | Output type. |

`exifMode` behavior:

- `TARGET_CAMERA`: create a camera and a `<photo>.target` empty 50 Blender units in negative Y from the camera; add a `TRACK_TO` constraint so the camera tracks the target with `TRACK_NEGATIVE_Z` and `UP_Y`.
- `CAMERA`: create only a camera.
- `EMPTY`: create an empty helper at the photo location.
- `CURSOR`: move the scene cursor to the photo location. When multiple files are supplied, each file moves the cursor; final cursor position is from the last processed valid photo.

### EXIF fields consumed

Required for every selected file:

- `GPSLatitude`
- `GPSLatitudeRef`
- `GPSLongitude`
- `GPSLongitudeRef`

Optional:

- `GPSAltitude`: if missing, altitude defaults to `0`.
- `FocalLengthIn35mmFilm`: if missing, camera lens defaults to `35` mm.
- `Orientation`: if missing, camera-data custom property `orientation` defaults to `1` (no rotation).

The source EXIF reader multiplies latitude by the latitude reference and longitude by the longitude reference, so south and west references become negative decimal degrees. It assumes photo GPS coordinates are WGS84 (`EPSG:4326`) and reprojects them into the scene CRS.

### Placement formula

For each valid photo:

1. Read `(lon, lat)` from EXIF GPS in WGS84.
2. Reproject `(lon, lat)` from `EPSG:4326` to the current scene CRS.
3. Read the scene projected origin `(crsx, crsy)` from the georeferenced scene.
4. Place the output at:

```text
x = projected_photo_x - scene_crsx
y = projected_photo_y - scene_crsy
z = GPSAltitude if present else 0
```

Scene map scale is not applied by this operator; it subtracts the projected origin directly.

### Camera data side effects

For `TARGET_CAMERA` and `CAMERA`, the operator stores metadata on the Blender camera data block:

| Custom property | Value |
| --- | --- |
| `background` | Original photo filepath. Used later by `camera.geophotos_setactive`. |
| `imageWidth` | Width loaded from the Blender image. |
| `imageHeight` | Height loaded from the Blender image. |
| `orientation` | EXIF `Orientation`, or `1` if missing. |

It also loads the image into `bpy.data.images` to read size.

### Orientation handling

All new geophoto cameras are created with:

```text
rotation_euler[0] = pi / 2
rotation_euler[2] = pi
```

Then the operator applies a Y-axis rotation for a subset of EXIF orientation values:

| EXIF `Orientation` | Rotation adjustment |
| --- | --- |
| `8` | `rotation_euler[1] -= pi / 2` |
| `6` | `rotation_euler[1] += pi / 2` |
| `3` | `rotation_euler[1] += pi` |
| other/missing | no additional adjustment |

The source comments mark this rotation adjustment as not fully tested. Treat it as a starting alignment, not as calibrated photogrammetry orientation.

### Automatic active camera

If `scene.camera` is `None` and the output mode creates a camera, the operator calls `camera.geophotos_setactive` for the first created camera.

## `camera.geophotos_setactive` — switch active geophoto camera

Purpose: select one camera generated by `camera.geophotos`, make it the scene camera, match render resolution to the source photo, and show the source photo as camera background.

### Valid cameras

The operator lists scene objects where:

```python
obj.type == 'CAMERA' and 'background' in obj.data
```

Only those cameras appear in the `camLst` enum.

### Invocation

UI path: `GIS > Camera >` switch/refresh geophoto entry.

Script-style call from a 3D View context:

```python
bpy.ops.camera.geophotos_setactive('EXEC_DEFAULT', camLst='IMG_0001')
```

### Required context

`context.space_data.type` must be `VIEW_3D`. Running from a text editor, console-only override, or background context cancels with `Wrong context`.

### Side effects

- Selects the chosen camera object and makes it active.
- Sets `scene.camera` to that object.
- Sets render size to `cam['imageWidth']` × `cam['imageHeight']` at `100%`.
- Loads or reuses the image stored in `cam['background']`.
- Enables `cam.show_background_images`.
- Hides existing background image slots on that camera.
- Creates or reuses the background slot for the stored image, shows it, and sets `alpha = 1`.

## `camera.georender` — create/update georeferenced render camera

Purpose: create or update a top-view orthographic camera that frames a selected mesh and writes a matching world-file text block for the render.

### Invocation

UI path: `GIS > Camera > Georender`.

Script-style call in Object Mode with a valid selected mesh:

```python
bpy.ops.camera.georender(
    'EXEC_DEFAULT',
    name='Georef cam',
    target_res=5.0,
    zLocOffset=50.0,
)
```

### Options

| Property | Default | Meaning |
| --- | --- | --- |
| `name` | `Georef cam` | Camera object/data name for a new camera, or updated name on redo for an existing camera. |
| `target_res` | `5` | Pixel size in scene map units per pixel; stored as camera custom property `mapRes`. Minimum is `0.00001`. |
| `zLocOffset` | `50` | Extra Z offset as percent of selected mesh Z dimension; also used for clipping. Minimum is `0`. |

### Poll and selection contract

The operator polls true only in Object Mode.

Selection must be one of:

- exactly one selected `MESH`: create a new georender camera;
- exactly two selected objects, one `MESH` and one `CAMERA`: update the selected camera.

Any other selection cancels with `Pre-selection is incorrect`.

When updating an existing camera, that camera must already have a `mapRes` custom property. A normal Blender camera selected with the mesh cancels with `This camera has not map resolution property`.

### Camera setup

Given the selected mesh world-space bounding box:

```text
xmin, ymin, zmin, xmax, ymax, zmax
center = (locx, locy, locz)
dimx = xmax - xmin
dimy = ymax - ymin
dimz = zmax - zmin, but dimz is forced to 1 when zero
```

The operator:

- creates a camera when only a mesh is selected;
- stores/updates `cam['mapRes'] = target_res`;
- sets `cam.type = 'ORTHO'`;
- sets `cam.ortho_scale = max(dimx, dimy)`;
- places the camera at `(locx, locy, zmin + dimz + offset)` where `offset = dimz * zLocOffset / 100`;
- sets `cam.clip_start = 0` and `cam.clip_end = dimz + offset * 2`;
- selects the camera and makes it active;
- sets `scene.camera` to the camera.

### Render resolution equation

The operator sets render resolution directly from mesh dimensions and target pixel size:

```text
resolution_x = int(dimx / target_res)
resolution_y = int(dimy / target_res)
resolution_percentage = 100
```

This truncates fractional pixels. If `dimx / target_res` or `dimy / target_res` is below `1`, Blender may receive `0`, so choose a smaller `target_res` or use a larger target mesh extent.

### World-file text block equation

The operator writes a Blender text data block named `<camera object name>.wld` with six lines:

```text
A = target_res
D = 0
B = 0
E = -target_res
C = scene_origin_x + bbox_xmin + target_res / 2
F = scene_origin_y + bbox_ymax - target_res / 2
```

Serialized as:

```python
wf_data = '\n'.join(map(str, [res, rot, rot, -res, x + res/2, y - res/2]))
```

where:

```text
res = target_res
rot = 0
x = bbox['xmin'] + scene_crsx
y = bbox['ymax'] + scene_crsy
```

The world file uses upper-left pixel center coordinates. Positive X pixel size is `target_res`; negative Y pixel size is `-target_res` because image rows go downward while map Y goes upward. This is the expected ESRI-style six-line world-file order:

1. pixel size in X (`A`)
2. rotation about Y (`D`, zero)
3. rotation about X (`B`, zero)
4. negative pixel size in Y (`E`)
5. X coordinate of upper-left pixel center (`C`)
6. Y coordinate of upper-left pixel center (`F`)

### Text-block cleanup

After writing the current world-file text block, the operator removes `.wld` Blender text blocks whose basename no longer matches any object name. Save or export needed world-file text before deleting or renaming cameras extensively.
