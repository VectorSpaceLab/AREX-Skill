# Model Families And Selection

This reference helps choose a RecBole model family before training or
customization. It is intentionally a selection guide, not an exhaustive catalog.
Always validate uncertain names against the installed package because optional
extras and package versions can change available models.

## Fast Family Decision Table

| User request / data shape | Prefer this family | Typical examples | Required data | Notes |
|---|---|---|---|---|
| Top-N recommendation from user-item interactions only | General recommendation | `BPR`, `LightGCN`, `NeuMF`, `ItemKNN`, `MultiVAE`, `Pop` | `.inter` with user and item fields | Collaborative-filtering setting. Mostly implicit feedback and ranking evaluation. Use when side features are absent or intentionally ignored. |
| Next-item, session, or sequence-aware recommendation | Sequential recommendation | `SASRec`, `GRU4Rec`, `BERT4Rec`, `NARM`, `SRGNN`, `FPMC` | `.inter` with user, item, and ordering signal such as timestamp or sequence order | RecBole builds item sequences with fields like item-list and list-length. Some models use `loss_type: CE` and therefore no train negative sampling. |
| CTR, click/no-click, conversion, labeled explicit feedback, or side-feature recommendation | Context-aware / CTR recommendation | `FM`, `DeepFM`, `xDeepFM`, `DCN`, `AutoInt`, `LR`, `WideDeep` | Usually `.inter` with a label field; may also need `.user` and/or `.item` side features loaded by config | This is the correct route for a CTR request with side features. Do not treat it as plain `BPR`/general recommendation unless the user chooses to ignore labels and features. |
| Recommendation augmented by a knowledge graph | Knowledge-aware recommendation | `KGAT`, `CKE`, `KGCN`, `KGNNLS`, `RippleNet`, `KGIN`, `MKR`, `CFKG` | `.inter`, `.kg`, and `.link` | `.link` maps item ids to entity ids; `.kg` contains head/relation/tail triples. Some graph models need optional graph packages or more memory. |
| Gradient boosting over tabular features | External-library / decision-tree models | `XGBoost`, `LightGBM` | Labeled `.inter`; often `.user`/`.item` features | Requires the matching optional package (`xgboost` or `lightgbm`). Use class spellings when resolving through RecBole. |

## Selection Patterns

### General recommendation

Choose a general recommender when the task is classic collaborative filtering:
rank items for users from observed user-item interactions. The minimal dataset
is an atomic `.inter` file with configured user and item id fields. Many general
models optimize pairwise ranking (`InputType.PAIRWISE`) and expect negative item
ids generated by the dataloader; some traditional or pointwise models use a
label-style input.

Good first choices:

- `BPR`: simple pairwise matrix factorization baseline for implicit feedback.
- `LightGCN`: graph collaborative filtering baseline when interaction graph
  structure is important.
- `ItemKNN`/`Pop`/`Random`: fast baselines or sanity checks.
- `MultiVAE`/`RecVAE`: autoencoder-style collaborative filtering; often require
  no train negative sampling.

Avoid this family when the central requirement is CTR labels, tabular side
features, item/user attributes, or a knowledge graph.

### Sequential recommendation

Choose a sequential recommender when order matters: next-item prediction,
session recommendation, or user-history modeling. RecBole sequential base
classes expect sequence fields derived from `.inter`, including an item sequence
field and item-list length field. `SASRec`, `GRU4Rec`, `BERT4Rec`, `NARM`, and
`SRGNN` are durable examples.

Watch the loss contract. Several sequential models choose input type indirectly
from `loss_type`: `CE` behaves pointwise/list-classification style and normally
sets train negative sampling to `None`; `BPR` is pairwise and needs negative
sampling. If a sequential model raises a negative-sampling or missing sequence
field error, check both `loss_type` and the data/config route.

### Context-aware / CTR recommendation

Choose context-aware models for CTR-style or explicit-label tasks. The dataset
usually needs a configured label field in `.inter`; feature fields may be loaded
from `.inter`, `.user`, and `.item`. `ContextRecommender` builds token, float,
token-sequence, and float-sequence feature embeddings from those loaded fields.

Good first choices:

- `FM`/`NFM`: factorization-machine baselines over sparse/dense features.
- `DeepFM`, `xDeepFM`, `WideDeep`, `DCN`, `AutoInt`: neural CTR models for
  feature interactions.
- `LR`: fast linear baseline.

If the user says "CTR with user/item side features", route to this family and
check that the side-feature columns are loaded. Do not reduce it to a general
recommender merely because the data also has user and item ids.

### Knowledge-aware recommendation

Choose knowledge-aware models when recommendation must exploit external entity
or relation structure. The dataset must provide all three atomic sources:

- `.inter`: user-item interactions.
- `.link`: item-to-entity mapping.
- `.kg`: head-entity, relation, tail-entity triples.

The config must also name entity, relation, head, and tail fields. If any of
these files or fields are missing, the failure is a data-family mismatch, not a
model-code bug. Some knowledge-aware models use pairwise recommendation losses;
some also optimize knowledge-graph terms internally.

### External-library models

`XGBoost` and `LightGBM` are decision-tree style external-library models. They
are useful for labeled tabular features and CTR-like tasks, not for pure
sequence modeling or KG propagation. They require their optional packages to be
installed and use matching specialized trainers. When names are ambiguous,
prefer `XGBoost` and `LightGBM` class spellings for registry resolution; some
property filenames are lower-case.

## Registry Resolution And Defaults

### `get_model(model_name)`

RecBole resolves model classes with `get_model(model_name)`. In common RecBole
versions the resolver:

1. Searches model-family submodules under `recbole.model`.
2. Uses a lower-case module filename derived from `model_name`.
3. Looks up the class with the exact `model_name` string.

Consequences:

- `get_model('BPR')`, `get_model('SASRec')`, `get_model('FM')`, and
  `get_model('KGAT')` are the safe public spellings.
- Case mismatches can import the module but fail class lookup. Retry the class
  spelling reported by the installed package.
- Project-local custom models are not automatically discoverable by string.
  Pass the class object to `Config(model=YourClass, ...)` or install/register
  the class inside a package location that RecBole searches.

### `get_trainer(model_type, model_name)`

Trainer resolution first tries a model-specific trainer named
`<ModelName>Trainer`. If that class is absent, RecBole falls back by model type:
knowledge-aware models use `KGTrainer`, traditional models use
`TraditionalTrainer`, and most other models use `Trainer`. External-library
models rely on exact specialized trainers such as `XGBoostTrainer` and
`LightGBMTrainer`.

If a custom model needs a special loop, name the trainer consistently
(`YourModelTrainer`) or instantiate it explicitly in the run script instead of
expecting the default trainer to know the custom behavior.

### Model property YAML

RecBole loads model defaults from model-property YAML files, normally named after
the model class such as `BPR.yaml`, `SASRec.yaml`, `FM.yaml`, or `KGAT.yaml`.
External-library defaults may use lower-case filenames such as `xgboost.yaml` or
`lightgbm.yaml`. Missing defaults commonly show up as `KeyError` for a
hyperparameter inside the model constructor.

For custom models, either provide all custom hyperparameters through config files
or config dictionaries, or package a matching model-property YAML where the
installed RecBole can load it. The model constructor should read hyperparameters
from `config`, not from hard-coded constants or hidden files.

## Installed-Package Inspection

Use the bundled helper from this sub-skill when the available model names or
property files are uncertain:

```bash
scripts/inspect_model_registry.py BPR SASRec FM KGAT --details
scripts/inspect_model_registry.py XGBoost LightGBM --details
scripts/inspect_model_registry.py MyModel --properties-dir path/to/properties/model
```

The helper prints only package-level module/class information and known property
filenames; it does not depend on a source checkout.
