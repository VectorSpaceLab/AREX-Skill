# Evaluation workflows

## A. Fast, reproducible no-relax evaluation

Use this when structures have already been relaxed and energies were produced
by DFT or another explicitly documented calculator:

```bash
python <mattergen-skill-root>/sub-skills/evaluation/scripts/evaluate_structures.py \
  --structures_path samples.extxyz \
  --relax False \
  --energies_path energies.npy \
  --structure_matcher disordered \
  --reference_dataset_path <TRI2024_REFERENCE>.gz \
  --energy_correction_scheme TRI2024 \
  --save_as metrics.json \
  --save_detailed_as detailed_metrics.json
```

Before the command, make a manifest containing the structure count and the
calculator's energy ordering. `energies.npy` is positional: it is not matched
by filename, structure id, formula, or material id. A directory's order is
`os.listdir` order, and a multi-frame EXTXYZ's order is frame order.

## B. MatterSim relaxation and output structures

```bash
python <mattergen-skill-root>/sub-skills/evaluation/scripts/evaluate_structures.py \
  --structures_path samples \
  --relax True \
  --potential_load_path <MATTERSIM_POTENTIAL>.pth \
  --device cuda \
  --structure_matcher disordered \
  --reference_dataset_path <TRI2024_REFERENCE>.gz \
  --energy_correction_scheme TRI2024 \
  --save_as metrics.json \
  --save_detailed_as detailed_metrics.json \
  --structures_output_path relaxed.extxyz
```

The default potential is MatterSim-v1-1M according to the repository README;
the larger local checkpoint is selected with `MatterSim-v1.0.0-5M.pth`. A
relaxation creates MatterSim total energies and final structures. The output
EXTXYZ contains relaxed atom data written by MatterSim and is independent of
the JSON metrics files. Use a separate output path from the input to avoid
confusing original and final structures.

Relaxation is an expensive local computation. It may require a CUDA-capable
PyTorch/MatterSim install and enough GPU memory; it may load a model from a
local cache. The adapter never downloads a large reference dataset or model.
Obtain files through an approved data/model process before running.

## C. Historical benchmark comparison

For comparisons to the repository's benchmark numbers, use MP2020 correction
and its matching Alex-MP reference asset. Preserve the same sample count,
matcher, relaxation/potential assumptions, and metric definitions. The README's
published numbers were DFT-evaluated in the paper, while repository benchmark
artifacts were obtained with MatterSim relaxation; do not present them as
interchangeable.

## D. Custom reference dataset

Create `ComputedStructureEntry` objects with structures and total energies.
For an MP-compatible dataset, the source README uses `VasprunLike` plus
`MaterialsProject2020Compatibility()`; for the recommended outside-benchmark
TRI path it uses `VasprunLike` plus `TRI110Compatibility2024()`. Then serialize:

```python
from mattergen.evaluation.reference.reference_dataset import ReferenceDataset
from mattergen.evaluation.reference.reference_dataset_serializer import LMDBGZSerializer

reference = ReferenceDataset.from_entries("my_reference_dataset", entries)
LMDBGZSerializer().serialize(reference, "my_reference_dataset.gz")
```

This writes a gzip-compressed LMDB format. Verify the correction scheme and
that every terminal chemical system needed by the samples has finite energies
before using it. Serialization can be large and is not performed by the
bundled evaluation adapter.

## Output precedence and accounting

- `save_as` is the aggregate metrics JSON path; it is independent of
  `save_detailed_as`.
- `save_detailed_as` is a per-entry table generated by `MetricsEvaluator` and
  may contain serialized entry/property/capability columns. Treat it as a
  machine-readable table, not a simple list of dictionaries unless inspected.
- `structures_output_path` is only produced by the relax path and contains
  final EXTXYZ structures with MatterSim energy/force/stress information.
- Console JSON is the return dictionary; logging may also appear on stderr.
- If a run fails after a relaxation, keep any output file and determine which
  structures completed before retrying. Never silently pair a partial energy
  array with the full structure input.

## Expensive/network limits

The wrapper performs no network access intentionally. It can read a caller
supplied reference `.gz` and local potential path, and MatterSim itself may
resolve its normal local/cache behavior when no explicit checkpoint is given.
Do not run a large reference download, model download, DFT calculation, or
full relaxation merely as a preflight. Use `--help`, import probes, and a tiny
trusted fixture first.
