# Evaluation troubleshooting

## Install and import

**`ModuleNotFoundError` for `mattersim`, `lmdb`, `ase`, `pymatgen`, or PyTorch**

Use the MatterGen environment, not an unrelated system Python. Confirm the
project's tested baseline (Python 3.10, torch 2.2.1+cu118, torch_geometric
2.8.0.post1, CUDA PyG wheels, pymatgen 2024.10.29, mattersim 1.1.2,
hydra-core 1.3.1, and pytorch-lightning 2.0.6). Run only cheap checks first:

```bash
python -c "import mattergen, mattersim, pymatgen, torch; print(torch.__version__, torch.cuda.is_available())"
python <mattergen-skill-root>/sub-skills/evaluation/scripts/evaluate_structures.py --help
```

Do not solve a missing optional package by editing the runtime skill or by
starting a large installation during evaluation. Repair the environment and
rerun the probes.

## Optional dependencies and backend

**MatterSim cannot construct a potential or CUDA extension fails.**

Use `--device cpu` only for a tiny diagnostic; this does not make a full
relaxation cheap. Verify that torch and the installed MatterSim/PyG wheels
agree on backend and CUDA ABI. `cuda:0` selects an explicit device; `cuda`
uses the default visible device. An unavailable CUDA device should be fixed or
an intentional CPU diagnostic requested, not silently substituted for a
benchmark.

**GPU out-of-memory or a killed process.**

Reduce the fixture/sample count, run batches externally, free other GPU jobs,
use a compatible smaller local potential, or use CPU for debugging. A partial
EXTXYZ or metrics file is not proof that all samples were evaluated. Preserve
logs and identify the completed subset before retrying.

## Input and configuration

**Invalid input path or zero structures.**

Use a real `.xyz`, `.extxyz`, `.zip`, or directory. Directory extensions must
be lowercase. Verify CIF syntax and remember directory XYZ files are read at
frame 0 only. A directory can contain unreadable CIFs that are logged and
skipped; count the resulting structures explicitly.

**`energies` count/order error.**

For `relax=False`, print `len(load_structures(Path(path)))` and
`len(np.load(energies_path))` before the call. Recreate the array in exact
EXTXYZ frame or `os.listdir` order. Do not sort only one side, join by
filename after a multi-frame file, or pass per-atom energies as total values.
The difficult synthetic check is two structures plus a deliberately reversed
or three-element array: it must fail before package evaluation.

**`Cannot accept energies if relax is True`.**

Choose a mode. Relaxed mode computes energies with MatterSim and ignores no
external array; no-relax mode requires precomputed total energies and does not
call MatterSim relaxation.

**`structures_output_path` confusion.**

This output is a relaxed EXTXYZ path and only has meaning in `relax=True`.
Keep it distinct from `save_as` (aggregate JSON) and `save_detailed_as` (table).

## Reference and correction issues

**Compatibility assertion or wrong hull/stability.**

Ensure the sample entry correction names and reference name agree. Use MP2020
with `reference_MP2020correction.gz` for historical benchmark reproduction, or
TRI2024 with `reference_TRI2024correction.gz` for non-historical work. If the
user supplies MP2020 reference data while requesting TRI2024, stop and explain
that the correction changes corrected energies and convex-hull/stability
results; do not label the output comparable. A custom reference requires the
same explicit preparation discipline.

**TRI2024 rejects an entry.**

`TRI110Compatibility2024` expects `run_type` `GGA` or `GGA+U`, as generated by
`VasprunLike`/appropriate computed entries. Inspect metadata and rebuild the
reference or input entries rather than removing the assertion.

**Missing terminal systems / energy metrics absent.**

The reference must contain finite-energy entries for every terminal chemical
system needed by the sample phase diagrams. With incomplete references,
structure metrics may still be valid; report energy metrics as unavailable.

## Matcher and metric failures

**Ordered matcher assertion with disordered data.**

Select `disordered` for any partial occupancy, mixed ordered/disordered set, or
substitution-aware alloy matching. It uses chemical-system grouping and
Hume-Rothery-like substitution rules. Ordered matching groups by reduced
formula and is stricter. A different formal space group alone does not imply
different structure.

**Unexpected novelty/uniqueness.**

Check matcher choice, reference correction/version, oxidation-state removal,
partial occupancies, atom ordering, supercell/primitive normalization, and
whether the reference has all material IDs. The evaluator adds index material
IDs when missing; a partially populated `material_id` field is an error.

**No RMSD or NaN RMSD.**

RMSD requires original structures plus final evaluated structures. No-relax
runs set originals only if the API caller supplies them; the CLI no-relax path
uses the same structures for both and therefore does not represent a true
relaxation displacement. Treat NaN as unavailable, not zero.

## Workflow failures

- First run `--help` and a tiny trusted fixture; then run the full sample set.
- Keep a manifest of input order, count, energy source, correction, matcher,
  reference, potential, device, and output paths.
- Do not auto-fetch LFS reference assets, MatterSim checkpoints, or DFT data.
- If an output path already exists, choose a new path or explicitly archive
  the prior result; do not overwrite an authoritative benchmark silently.
- If only a later metric fails, inspect the aggregate and detailed outputs,
  then rerun the smallest affected path. Preserve the original sample set.
