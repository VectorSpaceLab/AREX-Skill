# Deployment and Maintenance Troubleshooting

## Backend dependency setup fails

Symptoms:
- `uv sync --frozen` cannot resolve or install.
- Raw `pip install -e` fails on package metadata.

Recovery:
- Use `uv sync --frozen` from `src/backend/` as the supported path.
- Check Python version and network/proxy availability.
- Do not edit package metadata just for local inspection unless that is the intended code task.

## Service starts against the wrong database or Redis

Likely cause:
- API, worker, or script used a different `config` env value or working directory.

Recovery:
- Export the same `config=config.yaml` or deployment-specific value for all backend processes.
- Confirm settings through the shared config service, not by re-parsing YAML in scripts.
- Remember DB-derived config can be Redis-cached for about 100 seconds.

## Docker stack starts but app is unhealthy

Check by layer:

- MySQL and Redis health: required for backend and workers.
- Milvus requires etcd and MinIO-like storage.
- Elasticsearch is required for keyword recall and telemetry/search paths.
- Frontend depends on backend route availability and MinIO sharepoint consistency.
- Optional FT/OnlyOffice/Unstructured services are separate compose files.

Do not treat a healthy frontend container as proof that workers, vector search, or Linsight are healthy.

## Frontend dev proxy fails

Symptoms:
- `/api` is 404 or OAuth endpoints missing.
- MinIO signed URLs return 403.

Recovery:
- Platform FastAPI proxy target defaults to backend `:7860`; gateway mode uses `:8180`.
- Client prefixes paths with `/workspace` and rewrites before forwarding.
- MinIO proxy target host must match backend `sharepoint` exactly.
- Route UI code details to `frontend-apps`.

## Operational script failed or seems dangerous

Checklist:
- Run from `src/backend/` unless the script says otherwise.
- Verify dry-run output before `--apply`.
- Confirm whether it touches DB only or needs full app context.
- Confirm tenant scope or bypass mode.
- Preserve distinct exit codes and summaries when editing scripts.

Do not move data backfills into Alembic revisions to make deployment look simpler.

## Alembic or schema changes fail on DM8

Likely causes:
- MySQL-only JSON/DDL/default syntax.
- Autogenerated migration was not reviewed for DM8.

Recovery:
- Use dialect helpers.
- Keep data cleanup as a pre-deploy/backfill procedure.
- Add or run compatibility-focused tests when available; central DM8 verification remains a release-level gate.

## Architecture guard reports a violation

Recovery:
- Read `docs/constitution.md` and the exact rule output.
- Fix the root layering, permission, frontend store, or secret issue.
- Do not disable the hook or route around it to keep diffs small.

## Production batch interruptions

If a repo-skill production run is interrupted by 5xx, capacity, overloaded, or quota errors:

- Reuse the same session id for that repo.
- Continue from generated files and redo interrupted steps rather than waiting for a missing tool result.
- Delete truly partial/generated invalid skill output only when retrying a failed production run from scratch.
- Do not mark a repo blocked for transient errors unless the same reason repeats to the configured threshold.
