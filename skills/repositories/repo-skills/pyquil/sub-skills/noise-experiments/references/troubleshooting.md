# Noise-experiment troubleshooting

Use the symptom/cause/recovery sequence below. First classify the failure as
local model construction, program transformation, statistical post-processing,
or backend execution. Do not repair a local model by trying a service.

| Symptom | Likely cause | Recovery |
| --- | --- | --- |
| `Kraus operators ... shape ...` or matrix multiplication failure | An `n`-qubit map contains a non-square matrix or a matrix other than `(2**n, 2**n)`; tensor factors may be ordered or sized incorrectly. | Convert to complex arrays, print every shape, confirm target count and tensor factor order, and reject the model until all dimensions agree. |
| Completeness check is not identity | Probabilities do not sum to one, a Kraus amplitude used `p` instead of `sqrt(p)`, or maps were composed/tensored incorrectly. | Check `sum(K†K)`, normalize only at model-design time when mathematically intended, and rebuild from `pauli_kraus_map`, `damping_kraus_map`, or `dephasing_kraus_map`. Do not silently clip. |
| A map is called “CP-TP” with no proof | A unitary or matrix-shape check proves neither the intended map nor hardware behavior. | State CP from the Kraus form and verify TP with completeness. For a newer superoperator, use its package validation/Choi analysis if available. Keep physical-device claims separate. |
| `T2 must not exceed 2*T1`, non-positive-time, `inf`, `nan`, or odd decoherence values | `T1/T2` imply a negative pure-dephasing rate, or a zero/negative/NaN duration was passed. The legacy helper's validation is less strict for zero than the newer constructor. | Require finite positive `T1`, `T2`, and gate duration, allow `inf` only to intentionally disable a contribution, and enforce `T2 <= 2*T1`. At `T2=2*T1`, use no additional pure dephasing. |
| Damping/dephasing composition gives an unexpected state | `combine_kraus_maps(k1,k2)` means `k2` acts first and `k1` second; tensor operand order also affects basis ordering. | Apply both candidate orders to a test density matrix, compare with the documented formula, and name the order in the model record. |
| `NoisyGateUndefined`, “unsupported gate”, or bad parameter | Legacy high-level decoherence noise is limited to recognized fixed `I`, `RX(±pi/2)`, `RX(±pi)`, `CZ`, while `RZ` is deliberately noiseless. A custom/parametric gate has no fixed matrix match. | Compile or translate to the supported native-like set first, use a custom explicit `KrausModel`, or deliberately leave the gate ideal. Never label an untouched unsupported gate noisy. |
| Noisy gate name remains ideal after `apply_noise_model` | `apply_noise_model` only rewrites recognized matches; `RZ` is in `NO_NOISE` and unsupported gates are preserved. | Inspect `get_noisy_gate` compatibility and the transformed Quil. Do not infer from the presence of one model entry that every instruction was transformed. |
| `DEFGATE`/`ADD-KRAUS`/`READOUT-POVM` headers appear twice | `apply_noise_model` was called on an already transformed program, or a program already carried noise pragmas. | Keep the pristine program as the source, apply one model once, and assert header counts. Strip/rebuild in a fresh program rather than stacking models unless double noise is intentional and documented. |
| Readout correction swaps qubits or makes the result worse | Assignment matrices were supplied in a different order from the shot columns, or observed/prepared rows/columns were transposed. | Use `A[o,t] = p(observed=o | true=t)` and verify with a basis distribution. Keep matrix list order equal to the measured bit-column order; test one-qubit `|0>` and `|1>` cases. |
| Assignment matrix is rejected or correction explodes | Matrix is not 2-by-2, contains negative values, has columns not summing to one, or is singular/ill-conditioned. | Validate shape, finite/nonnegative entries, column sums, determinant and condition number. Recalibrate with more shots or use a better-conditioned model. Never take a pseudoinverse without reporting the change in estimator. |
| Corrected probabilities are negative or exceed one | Linear inverse correction amplified finite-shot uncertainty; this is expected in some samples and is also a conditioning warning. | Report raw and corrected distributions, sum and uncertainty; increase shots or use a constrained estimator outside this sub-skill. Do not silently clip to `[0,1]`. |
| `estimate_assignment_probs` hangs or returns no data | It submits two programs through `qc`; compiler, QVM/QPU, readout register, or service configuration is unavailable. | Route service setup and raw execution to `../compile-execute/`. For local validation use synthetic arrays and `corrupt_bitstring_probs`/`correct_bitstring_probs`; do not claim assignment calibration without the backend. |
| Symmetrization trial count changes with a warning | Requested `trials` is below the minimum for the number of symmetrized qubits and level. | Accept and record the modified count or provide enough trials in advance: exhaustive `2**n`, OA strength 2's package minimum, OA strength 3 next power of two at least `2*n`, and 2 for levels 0/1. Treat these as minima, not precision guarantees. |
| Invalid `symm_type` or unsupported OA memory-map path | Only `-1,0,1,2,3` are accepted by `run_symmetrized_readout`; `Experiment.build_symmetrization_memory_maps` in 4.18.0 implements only `NONE` and `EXHAUSTIVE`. | Choose the actual API path. Use `run_symmetrized_readout` for OA execution with a backend; use exhaustive maps for the `Experiment` parameterized path. Do not assume enum construction implies implementation support. |
| Calibration is silently absent or constructor warns | Calibration is supported only with exhaustive symmetrization in this release; nonzero calibration with another level is reset to `NONE`. | Inspect `experiment.calibration` after construction. Set exhaustive plus-eigenstate intentionally, or set calibration to `NONE` and report uncalibrated expectations. |
| `generate_calibration_experiment` rejects settings | It received grouped settings, a non-plus-eigenstate calibration method, or a non-exhaustive experiment. | Generate calibration from an ungrouped singleton-setting experiment before grouping. Use only plus-eigenstate calibration in 4.18.0, unless a version-pinned alternative is verified. |
| Grouped settings raise “input states are not compatible” | Two settings in one group request different eigenstates on a qubit. | Split the group or regroup with `group_settings`; compare one-qubit state descriptors per qubit. |
| Grouped settings raise “observables not compatible” | Two settings request different nonidentity axes on the same qubit. Commutation alone does not imply a local tensor-product basis. | Split the group, choose compatible axes, or use a different measurement scheme. Validate input and output compatibility independently. |
| `QuantumComputer.run_experiment` rejects a grouped experiment | The 4.18.0 method has a length-1 setting limitation even though `Experiment` can store groups. | Use singleton settings with `run_experiment`, or hand a grouped experiment to `operator_estimation.measure_observables` only when its backend prerequisites are available. |
| `operator_estimation.measure_observables` rejects calibration | Readout calibration requires exhaustive symmetrization; the observable coefficient may also be complex/non-real. | Set `symmetrization=EXHAUSTIVE`, use a real coefficient for a sampled Hermitian observable, or set `calibrate_readout=None` and label the result uncalibrated. |
| Calibrated expectation is huge, NaN, or has huge error | Calibration expectation is zero or nearly zero; ratio correction is ill-conditioned. | Inspect raw and calibration expectations, keep the uncorrected result, increase shots, improve symmetrization/readout model, and report the denominator warning. Do not clamp or discard the uncertainty. |
| `ExperimentResult.std_err` appears inconsistent with shot spread | It is a standard error of the mean, not a single-shot standard deviation; symmetrization changes `total_counts`. | Recompute from the actual bitstring count and preserve `total_counts`, raw/calibration fields, and the sample convention. |
| Expectation has the opposite sign | Bit convention or measured register order was reversed. PyQuil maps bit 0 to +1 and bit 1 to -1. | Run `bitstrings_to_expectations` on `[[0],[1]]` and a known joint array, verify `get_meas_qubits()`/`get_meas_registers()`, and only then consume backend results. |
| `exponentiate_pauli_sum` rejects input | Coefficients are symbolic or qubits are placeholders; dense matrix exponentiation requires fixed coefficients and integer qubits. | Use `exponential_map`/`trotterize` for program construction or resolve/address parameters before requesting a dense unitary. |
| Exponentiated circuit or matrix has the wrong angle | `exponential_map` uses `exp(-i*alpha*term)` while `exponentiate_pauli_sum` uses cycles `exp(-i*pi*sum(theta P))`. | Write down the convention before comparing, and test a single `Z` term (`RZ(2*coefficient*alpha)`) as a unit case. |
| `PauliTerm.from_list` rejects a term | The list repeats a qubit or uses an invalid operator/index. | Use one operation per qubit in `from_list`; multiply terms to combine/reduce repeated operators and use nonnegative integer, placeholder, or formal-argument indices as appropriate. |
| Import of a newer `Channel` or `NoiseModel` fails | In 4.18.0 those classes live in private implementation modules and are not re-exported from `pyquil.noise`; optional quax/JAX runtime may also be unavailable. | Use the public legacy imports for QVM Kraus pragmas. If migration analysis is explicitly required, pin the PyQuil version and inspect the private signatures without mixing model classes. |
| `from_compiler_isa` emits a deprecation warning | The newer private channel model marks the rpcq `CompilerISA` adapter deprecated since 4.17.0. | Prefer `NoiseModel.from_isa` with a QCS SDK ISA on a verified version-matched migration path; otherwise keep the public legacy model and document the dependency. |
| Actual experiment cannot start, times out, or lacks credentials | `run_experiment`, `measure_observables`, `run_symmetrized_readout`, and assignment calibration require a configured `QuantumComputer` and a usable compiler/QVM/QPU/QCS path. A generated program/model does not create one. | Stop and hand off to `../compile-execute/` with the exact missing service, endpoint, compiler, credentials, and timeout. Use only local construction and synthetic post-processing here. |
| A QCS/QPU claim is inferred from an ISA/noise model | An ISA fixture or model is descriptive metadata; it does not query or validate live hardware behavior. | Label the result “model/ISA-derived” and report the actual execution evidence separately. |
