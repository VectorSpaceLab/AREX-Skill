# ISA conversion and invariants

## Representations

There are three distinct forms:

1. **NetworkX topology**: a graph whose nodes are qubit labels and whose edges
   are allowed 2Q connectivity. Use a simple undirected `nx.Graph` for the
   supported contract.
2. **RPCQ-compatible `CompilerISA`**: a dataclass with
   `qubits: dict[str, Qubit]` and `edges: dict[str, Edge]`. Each `Qubit` has
   integer `id`, `dead`, and 1Q `gates`; each `Edge` has sorted integer `ids`,
   `dead`, and 2Q `gates`.
3. **QCS `InstructionSetArchitecture`**: an installed SDK model with
   `architecture.nodes`, `architecture.edges`, `instructions`, and optional
   `benchmarks`. Operations have a `name`, `node_count`, `parameters`, and
   `sites`; sites have `node_ids` and characteristics.

Do not interchange these by duck typing. Conversion directions are explicit.

## NetworkX → `CompilerISA`

```python
from pyquil.quantum_processor.transformers import graph_to_compiler_isa
isa = graph_to_compiler_isa(
    graph,
    gates_1q=["RX", "RZ", "MEASURE"],
    gates_2q=["CZ"],
)
```

`graph_to_compiler_isa(graph, gates_1q=None, gates_2q=None) -> CompilerISA`
uses the supported gate mapping described in
[processor-types.md](processor-types.md). It creates qubit entries for every
integer from `0` through `max(graph.nodes)`, not just `graph.nodes`. Thus a
sparse graph such as nodes `{0, 2}` produces a qubit `1` marked dead. Every
actual graph node is non-dead and receives the uniform 1Q gates. Every graph
edge gets a canonical edge ID and uniform 2Q gates.

This range-based behavior means labels should normally be contiguous
non-negative integers when an ISA is intended for a QAM/compiler. If a graph is
empty, `max(graph.nodes)` fails; validate non-empty nodes first. Negative,
string, mixed-type, or incomparable labels are outside the safe contract even
if a particular NetworkX operation accepts them.

`GraphGateError` is raised before a usable ISA is returned when a requested gate
name is unsupported. Validate operation names before shipping a custom target.

## `CompilerISA` → NetworkX

```python
from pyquil.quantum_processor.transformers import compiler_isa_to_graph
graph = compiler_isa_to_graph(isa)
```

`compiler_isa_to_graph(compiler_isa) -> nx.Graph` uses only `edge.ids` and
`nx.from_edgelist`. It includes endpoints of listed edges, but it does not add
all keys from `compiler_isa.qubits`. Consequently it loses isolated qubits and
cannot represent dead flags or gate availability. Compare edge sets directly
and compare nodes only after adding expected isolated nodes from the ISA when
needed:

```python
expected = nx.Graph()
expected.add_nodes_from(q.id for q in isa.qubits.values())
expected.add_edges_from(tuple(edge.ids) for edge in isa.edges.values())
```

For an `NxQuantumProcessor`, use `qproc.qubits()` or the original topology as
the authoritative qubit set. The installed fact for `Graph([(0, 1)])` is
`qubits == [0, 1]`, `edges == [(0, 1)]`, and an ISA with two qubits and one
edge.

Edge IDs are generated by `make_edge_id(a, b)`, which sorts endpoints and joins
them with `-`; `add_edge` stores `Edge.ids` sorted as well. This is why an input
edge encountered as `(16, 15)` still serializes as `15-16` with IDs `[15, 16]`.
Do not use string lexical order as a substitute for integer ordering when
validating multi-digit labels.

## QCS ISA → compiler/graph

```python
from pyquil.quantum_processor.transformers import (
    qcs_isa_to_compiler_isa,
    qcs_isa_to_graph,
)
compiler_isa = qcs_isa_to_compiler_isa(qcs_isa)
graph = qcs_isa_to_graph(qcs_isa)
```

`qcs_isa_to_graph` uses only QCS architecture edge `node_ids`, so it has the
same isolated-node omission as the compiler transformer. `qcs_isa_to_compiler_isa`
first declares all architecture nodes and edges, then visits each operation
site. It rejects:

- a 1Q operation whose site does not contain exactly one node ID;
- a declared-missing 1Q node;
- a declared-missing 2Q edge;
- an unsupported operation name (`QCSISAParseError`);
- an unexpected `node_count`.

The current source has an edge-case defect: the 2Q site-length branch creates a
`QCSISAParseError` but does not raise it. A site with fewer than two IDs can then
surface as `IndexError`; a site with more than two can be silently treated using
its first two IDs. Pre-validate every QCS operation site has exactly
`node_count` IDs before calling the transformer if malformed input is possible.

Recognized QCS operations map as follows:

| QCS operation | Compiler result |
|---|---|
| `RX` | fixed-angle RX entries, benchmark-derived fidelity when available |
| `RZ` | symbolic RZ entry |
| `MEASURE` | target and no-target measurement entries, `fRO` fidelity when available |
| `CZ`, `ISWAP`, `CPHASE`, `XY` | corresponding 2Q `GateInfo` with default/characteristic fidelity and duration |
| `WILDCARD` | wildcard entries |
| `I`, `RESET` | recognized but contribute no compiler gate entries |

If a qubit or edge ends with no gates, the transformer sets its `dead` flag.
Architecture declarations alone therefore do not imply usable operations.
Duplicate operation names for the same resource are skipped after the first
site. QCS operation characteristics can populate duration/fidelity, but those
values are metadata rather than a live calibration proof.

## Legacy RPCQ-shaped data

The `pyquil.external.rpcq` classes are dataclasses retained for compiler target
compatibility. Useful constructors/helpers include:

```python
from pyquil.external.rpcq import CompilerISA, Qubit, Edge, GateInfo
from pyquil.external.rpcq import add_qubit, add_edge, get_qubit, get_edge, make_edge_id
```

The compatibility models expose private `_dict()`/`_parse_obj()` and deprecated
public `dict()`, `parse_obj()`, and `parse_file()` methods. `CompilerISA._dict()`
uses `qubits`/`edges`; `_dict(by_alias=True)` uses `1Q`/`2Q`. The public methods
emit deprecation warnings in the inspected version (pyQuil 4.18.0). Prefer
QCS SDK models for QCS-shaped input and use the compatibility models only where
pyQuil compiler APIs require `CompilerISA`. Do not publish a claim that RPCQ
serialization has disappeared: this version still serializes a compiler target
through that compatibility layer.

## Round-trip checklist

For graph → ISA → graph, validate:

- Original graph is a non-empty simple undirected graph.
- `sorted(qproc.qubits())` equals intended qubit labels.
- Every original edge has a canonical `CompilerISA.edges` ID.
- Every non-isolated graph node has a corresponding non-dead ISA qubit.
- Requested operation names appear on each intended resource.
- Reverse graph edge set equals original edge set.
- Isolated nodes are checked separately and restored explicitly if the reverse
  graph is used as a topology.
- No live-resource conclusion is made from conversion alone.

For QCS/Compiler fixture transformation, validate architecture/ISA node and edge
sets, operation arity, supported names, dead flags, and expected
fidelity/duration fields. Keep fixtures bundled by the calling test or task;
this skill does not fetch a live ISA.
