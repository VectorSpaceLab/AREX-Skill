# NeMo troubleshooting

This matrix covers the failure modes that are specific to trlX's NeMo / Megatron wrappers and the optional backend. The local inspection env did not include NeMo or Apex, so these fixes are source-backed guidance rather than backend-verified claims.

| Symptom | Likely cause | What to check | Safe next step |
| --- | --- | --- | --- |
| `ImportError: NeMo is not installed. Please install \`nemo_toolkit\` to use NeMo-based trainers.` | The installed trlX package registered dummy trainer entries because NeMo was absent. | Confirm whether the environment actually has `nemo_toolkit` and Apex. The loader intentionally falls back to import-error stubs when NeMo is missing. | Install the NeMo/Apex stack in a prepared backend, or route the task to `../training/SKILL.md` if NeMo is not required. Do not claim NeMo verification in the current env. |
| Apex build or CUDA-extension failures | NeMo/Apex version mismatch, incompatible CUDA toolchain, or build flag mismatch. | Compare the target NeMo branch and Apex build instructions with the local CUDA/PyTorch wheel. Inspect the build log for extension compile errors. | Align the NeMo/Apex versions with the repository's documented branch for the target workflow. Rebuild only in a prepared backend; do not bundle the install as a runtime script. |
| Trainer starts but checkpoint load fails with missing `model_weights.ckpt` | The wrapper expects checkpoint root directories, not arbitrary filenames. | Check whether the checkpoint root contains `model_weights.ckpt` or `mp_rank_XX/model_weights.ckpt`. | Point `pretrained_model` or `resume_from_checkpoint` at the checkpoint root. For tensor-parallel shards, keep the shard directory structure intact. |
| Checkpoint loads on one rank but not another | Tensor/pipeline degree changed between save and load, or the rank directory was injected incorrectly. | Compare `tensor_model_parallel_size`, `pipeline_model_parallel_size`, and the rank-subfolder layout. | Keep tensor/pipeline parallel settings constant across save and load. For ILQL inference, follow the rank-injection flow exactly. |
| `ValueError` or shape mismatch around parallel sizes | `trainer.num_nodes * trainer.devices` is not compatible with `tensor_model_parallel_size * pipeline_model_parallel_size`. | Compute the model-parallel degree and check the derived data-parallel world size. | Reduce or rebalance tensor/pipeline parallelism, or choose a smaller default config that matches the hardware. |
| Tokenizer path or vocabulary errors | The checkpoint root does not contain the tokenizer assets expected by the NeMo config, or the tokenizer library does not match the checkpoint format. | Check `tokenizer.library`, `tokenizer.model`, `tokenizer.tokenizer_model`, `vocab_file`, and `merge_file`. | Keep tokenizer files under the same checkpoint root. For sentencepiece-backed loads, ensure `pretrained_model` points at the unpacked model directory. |
| PPO inference works only on a single data-parallel world | The PPO inference flow expects `trainer.world_size == trainer.devices` after setting `num_nodes=1`. | Confirm that data-parallel world size is 1 and that the model-parallel degree equals the device count. | Use the inference recipe's exact world-size setup. Disable reference-model construction for pure generation. |
| ILQL inference or generation behaves oddly after setup | Sequence parallelism or activation checkpointing stayed enabled during generation, or the model-parallel state was not initialized. | Check whether `fake_initialize_model_parallel`, `inject_model_parallel_rank`, and the inference toggles were applied. | Follow the ILQL inference flow exactly; temporarily disable sequence parallelism and activation checkpointing while generating. |
| `always_save_nemo` / checkpoint-save expectations do not match the output | Model-parallel save support is limited; some NeMo save paths are not implemented for model-parallel training. | Inspect the `exp_manager.checkpoint_callback_params` settings and the source note about model-parallel saves. | Prefer rank-sharded checkpoint directories as the primary artifact. Treat full `.nemo` export on model-parallel jobs as limited or unsupported unless the backend confirms it. |
| Triton / reward-model serving is mentioned alongside NeMo | That is a separate serving workflow, not the NeMo wrapper contract. | Check whether the task is actually about model serving or reward-model deployment. | Route serving questions to the training skill or a serving-specific skill. Do not assume Triton is bundled with the NeMo sub-skill. |
| GPU memory / VRAM pressure is too high | The selected model and context length are too large for the available hardware. | Compare `hidden_size`, `num_layers`, `seq_length`, `global_batch_size`, and the tensor/pipeline degree. | Start from the 1.3B or 2B config, lower `seq_length`, reduce batch size, and keep `num_layers_unfrozen` conservative. Use activation checkpointing and parallelism only after the smaller path is stable. |

## Extra notes
- The repo evidence contains a version mismatch: the installation docs and the model README do not name the exact same historical NeMo pin. Treat that as a source discrepancy, not a verified compatibility guarantee.
- The current inspection env verified CUDA torch only; no NeMo/Apex backend claim should be made from this skill draft.
- If the user wants a concrete run plan, prefer a safe config-only answer over a launch command unless the backend is already prepared.
