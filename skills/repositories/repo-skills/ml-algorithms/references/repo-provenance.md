## Evidence use

Included evidence:

- `README.md` for project purpose, install instructions, implemented algorithm list, and example-running guidance.
- `setup.py`, `setup.cfg`, `requirements.txt`, `MANIFEST.in`, `.github/workflows/python-app.yml`, and `Dockerfile` for package metadata, dependency evidence, package data, and CI-style verification clues.
- `mla/` for public APIs, signatures, source behavior, metrics, datasets, neural layers, and troubleshooting evidence.
- `examples/` for native workflow intent; useful examples were distilled into bundled scripts or references.
- `mla/tests/`, `mla/metrics/tests/`, and `mla/neuralnet/tests/` for expected behavior, accuracy thresholds, skipped PCA status, and edge-case assertions.

Excluded evidence:

- `.git/`, caches, generated bytecode, build outputs, local environments, and production logs.
- `skills/tests/` review artifacts and generated runtime skill files, except as outputs of this creation workflow.
- Large package-data files were documented but not copied into the generated skill.

## Refresh triggers

Refresh this skill when:

- `git rev-parse HEAD` differs from the recorded commit.
- Package metadata changes the distribution name, version, requirements, package data, or supported Python/dependency range.
- Public import paths, constructor signatures, estimator outputs, metric behavior, dataset loaders, or neural layer/optimizer APIs change.
- The `mla.svm.kernerls` module is renamed or compatibility aliases are added.
- `load_nietzsche()` no longer uses `np.bool`, DQN is updated for Gymnasium/new Gym APIs, or factorization-machine `fit` initialization is fixed.
- Examples/tests add new public workflows or change safety/runtime expectations.
