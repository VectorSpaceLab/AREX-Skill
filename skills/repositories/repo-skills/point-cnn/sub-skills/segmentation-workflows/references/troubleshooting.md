# Segmentation troubleshooting

Use this table before retrying a training or inference command. Keep source
data and outputs intact until a diagnosis identifies what is safe to regenerate.
The helper scripts in this sub-skill are read-only and do not repair inputs,
compile operators, download data, or start training.

| Symptom | Likely cause | Recovery |
|---|---|---|
| `tf_sampling_so.so` is missing or `tf.load_op_library` fails | The FPS shared library was never built, is not beside its Python wrapper, or was built for a different TensorFlow/Python ABI | Stop. Run `python3 scripts/check_fps_prerequisites.py --sampling-dir PATH --source-dir PATH --load-library --require-gpu` to record the missing component. Rebuild only in an explicitly approved compatible CUDA/TensorFlow toolchain, then repeat the load-only check. Do not replace FPS with CPU execution or call a load check a pass. |
| The FPS checker reports `PARTIAL_REQUIRED_BACKEND` | Source/build files, TensorFlow, GPU, and possibly shared-library loading were inspected, but no FPS/GatherPoint kernel ran | Keep the required execution status unresolved. Run only a bounded target-GPU custom-op smoke in the prepared runtime when explicitly approved; a loadable `.so` is not execution evidence. |
| The FPS checker reports `BLOCKED_REQUIRED_BACKEND` | A wrapper, shared library, CUDA-enabled TensorFlow runtime, GPU, source requirement, or library load is missing/failed | Stop before graph construction. Preserve the diagnostic output and repair the environment outside this sub-skill. |
| `No OpKernel was registered` or placement fails on CPU | The custom sampling kernels are GPU-only | Choose an accessible compatible GPU or treat this workflow as blocked. The shipped FPS settings have no CPU fallback. |
| Build errors mention `nvcc`, `cudart`, compiler version, undefined TensorFlow symbols, or `GLIBCXX` | CUDA toolkit, host compiler, TensorFlow headers/library, or C++ ABI differs from the runtime | Record TensorFlow version/build, CUDA path/version, compiler version, and ABI used; rebuild against that exact runtime. A library compiled in another environment is not portable by default. |
| GPU appears in TensorFlow but a basic GPU/custom-op session times out | Device initialization, resource contention, driver/runtime, or host GPU execution is unresolved | Treat GPU execution as unverified and retain `BLOCKED_REQUIRED_BACKEND`. Retry only with a bounded minimal diagnostic on an idle GPU; inspect scheduling/driver conditions. Do not start a long job or infer that PointCNN's operator passed. |
| `validate_segmentation_h5.py` reports a rank/dtype/count error | A required dataset is missing, flattened, nonnumeric, nonfinite, or not aligned to `[items, padded_points]` | Stop. Repair or regenerate the data through [data-preparation](../../data-preparation/SKILL.md), then validate every flat HDF5 list again. Do not pad/truncate in this skill. |
| Validator reports mixed `indices_split_to_full` contracts | Some files have no mapping, or files disagree between rank 2 and rank 3 mapping | Do not concatenate the list. Separate dataset workflows or regenerate file lists so one inference/merge job uses one mapping convention. |
| Validator reports an index bound failure | Active map entries are negative or exceed the supplied `--full-point-count`/`--index-group-count` bound | Check the source-cloud length and block preparation. Use only active `:data_num[i]` entries and pass the verified exclusive bounds; do not hide invalid padding or clip indices. |
| Checkpoint restore reports missing/unmatched variables | The setting/model differs from the checkpoint (class count, `data_dim`, X-Conv/X-DeConv arrays, feature flags, or layer names) | Use the setting recorded at training, or retrain after deliberate architecture changes. Compare the configuration module before deleting outputs. |
| Placeholder shape error or `data_dim` mismatch | HDF5 feature width does not equal the setting's `data_dim`, or general inference `--max_point_num` differs from the padded width | Validate with `--data-dim`; preserve XYZ in channels 0–2 and select a matching setting. Set general-test `--max_point_num` exactly to `data.shape[1]`, never below any active count. |
| Feature split/normal augmentation fails | `use_extra_features` or `with_normal_feature` conflicts with width/layout | For normals, provide at least XYZ+3 normal channels when the normal flag is enabled. For non-normal extra channels, set the setting consistently; do not reinterpret arbitrary channels as normals. |
| `IndexError` during label weighting or metric construction | Active `label_seg` contains a negative/out-of-range class or `num_class` is wrong | Run the validator with `--num-class`. Repair label mapping upstream; padded positions are not automatically ignored by the trainer's full label array. |
| `InvalidArgument` from `GatherNd`, empty sampling, or a point index exceeds bounds | `data_num` is zero/too large, a file's padded width differs from `--max_point_num`, or data/index mappings are corrupt | Validate every HDF5 file. Ensure `1 <= data_num <= padded_points`, set general-test `--max_point_num` to the HDF5 padded width, and verify active map entries before merge. |
| General inference creates `*_pred.h5` but merge/evaluation cannot map blocks | Input lacked `indices_split_to_full`, mapping shape is wrong, or invalid padded rows were used | Preserve mapping in upstream block preparation and use only `:data_num[i]` entries. Validate mapping bounds against its target full cloud before passing it to evaluation. |
| A prediction HDF5 has `-1` labels or zero confidence in padding | The tester intentionally leaves inactive padded rows at `-1` and `0` | Ignore only `:data_num[i]`; never treat padding as class 0 or as an uncovered valid prediction. |
| ShapeNet `.seg` labels look globally offset or object/category mapping is wrong | Category-file order does not match HDF5 `label`, or sorted `data_folder` traversal does not match HDF5 item order | Verify category rows, HDF5 object labels, and sorted `.pts` file order. The tester writes labels relative to each category's class range. |
| ShapeNet `assert point_num == len(coordinates)` fails | The HDF5 item and matching `.pts` file have different counts or ordering | Stop; do not use the output. Reconcile the test file list and coordinate tree before rerunning. |
| ShapeNet PLY output is missing | `--save_ply` was omitted, or the output path was inspected before the tester completed | The writer creates the sibling `<data_folder>_pred_nips_<repeat>_ply/<category>/` tree when `--save_ply` is used. Check the exact `<basename>.ply` path; do not use PLY as the metric source. |
| Out-of-memory or unexpectedly huge test graph | `repeat_num` and `max_point_num` determine the fixed test batch size | Lower `repeat_num`; set `max_point_num` to the actual padded HDF5 width, never below valid counts. Start with one repeat. |
| S3DIS/ScanNet/Semantic3D merge cannot find a source index | The prediction HDF5 did not copy a mapping, or the wrong dataset mapping rank was supplied | Return to block preparation and inference. S3DIS/Semantic3D require rank-2 maps; ScanNet requires `(room_id, point_id)` rank-3 maps. Route merge to evaluation-and-artifacts. |
| Semantic3D preparation/testing consumes unexpected disk or creates many artifacts | Semantic3D preprocessing is large and block predictions require a later merge; the source workflow can involve very large storage | Do not download/decompress or delete marker/output files casually. Use data-preparation for a storage/side-effect plan and evaluation-and-artifacts for merge. Keep raw, prepared, and prediction locations separate. |
| A copied shell launcher rejects flags or does not target expected data | Historical launcher scripts contain dataset-path/argument defects and background jobs | Use the explicit Python CLI contracts in this sub-skill. General testing needs `--filelist/-t`; do not supply a second `-t` or an unsupported `-f`. |
