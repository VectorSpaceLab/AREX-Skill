# Face alignment troubleshooting

Use this reference when face.evoLVe alignment imports fail, images are skipped, crops look wrong, or the resize-before-align helper behaves unexpectedly.

| Symptom | Likely cause | Recovery |
| --- | --- | --- |
| `--repo-root` is rejected, or imports fail with `detector`, `align_trans`, `get_nets`, `box_utils`, or `first_stage` missing. | The supplied repo root is not a face.evoLVe checkout, or its `applications/align/` directory is missing. | Use the bundled `scripts/align_faces.py` and pass `--repo-root` to a local checkout that contains `applications/align/`. Do not run source-tree scripts directly; the bundled helper sets the import path and working directory for the MTCNN helpers. |
| Error mentions missing `pnet.npy`, `rnet.npy`, or `onet.npy`. | The local checkout does not contain the MTCNN weights. The generated skill does not bundle or download these weight files. | Use a checkout that still has `applications/align/{pnet,rnet,onet}.npy`, or restore those files before running the bundled aligner. |
| All or many images are skipped as no face/no landmarks. | Faces are smaller than `min_face_size`, stage `thresholds` are too strict, images are blurred/occluded/profile, or the source contains non-face/corrupt files. Some no-face paths in the legacy detector raise an internal empty-array error, which the bundled helper treats as no detection. | Lower `--min-face-size`, lower one or more `--thresholds`, pre-resize very large images with `scripts/resize_faces.py`, and spot-check whether the image actually contains a visible frontal or near-frontal face. Replace corrupt/non-face inputs instead of forcing them through alignment. |
| The wrong person is aligned from a group photo. | The batch workflow uses the first returned MTCNN landmark set for each image. Group photos violate the one-subject-per-image assumption behind identity folders. | Split group photos, crop the intended subject before batch alignment, or build a custom one-image inspection flow that chooses a face by bounding-box score/size before calling `warp_and_crop_face`. |
| `PIL.UnidentifiedImageError`, `OSError`, or `cv2.imread` returns `None`. | The input image is corrupt, empty, truncated, encrypted, or in an unsupported format. | The bundled scripts skip and report bad files; they never delete from the source tree. Repair or replace the source image, or remove it with an explicit data-cleaning step outside the alignment helper. |
| Hidden `.DS_Store` or dotfiles are present in identity folders. | macOS or notebook tools wrote metadata files into the data tree. | The bundled scripts ignore hidden names instead of deleting them. If downstream tooling still sees them, clean or validate the ImageFolder tree in `data-preparation`. |
| Crops have strange colors, or debugging snippets disagree about RGB/BGR order. | face.evoLVe detection uses `PIL.Image`/RGB and NumPy arrays; the resize helper uses OpenCV, which reads/writes BGR arrays. Mixing ad-hoc OpenCV reads into the alignment path can invert colors or confuse visual debugging. | Keep MTCNN detection/alignment in the bundled `align_faces.py` path. Use `resize_faces.py` only as a preprocessing writer, and convert BGR↔RGB explicitly in any custom OpenCV diagnostic code. |
| Aligned crops are the wrong size or face parts are shifted after using a non-112 crop. | The 112x112 reference points were not scaled consistently with the requested crop size. | Use `align_faces.py --crop-size <edge>` so the reference template is scaled by `<edge> / 112.0`. Keep downstream PyTorch/PaddlePaddle image-size settings consistent with the aligned crop edge. |
| PNG, BMP, or uppercase-extension inputs become `.jpg`. | face.evoLVe's batch alignment normalizes non-JPEG outputs for ImageFolder-style training. | Expect `.jpg` output names and update downstream manifests. Keep a separate raw-data archive if original extensions or lossless encodings matter. |
| Destination root is rejected as overlapping the source root. | Writing aligned outputs inside the source tree can cause recursive reprocessing or accidental overwrites. | Choose a new sibling or separate destination tree, then point downstream training or feature extraction to that destination. |
| Python reports `SyntaxWarning: "is" with a literal` from `align_trans`. | The legacy affine helper compares string values with identity operators. Installed inspection confirmed these warnings during import on modern Python. | Treat the warning as benign if crops are produced. If maintaining a patched checkout, replace those string comparisons with equality comparisons (`==`) while preserving the `warp_and_crop_face` behavior. |
| PyTorch warns that `volatile` was removed or `softmax` has an implicit dimension. | The MTCNN implementation targets an older PyTorch API. Modern PyTorch can still run the path but may warn. | The bundled aligner suppresses the known noisy warnings while preserving behavior. For a maintained fork, wrap detector forward passes in `torch.no_grad()` and pass `dim` to `softmax`. |
