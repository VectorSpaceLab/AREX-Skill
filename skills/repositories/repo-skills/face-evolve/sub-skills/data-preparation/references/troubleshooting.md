# Data-preparation troubleshooting

Use this reference when a face.evoLVe dataset root, low-shot pruning run,
validation pair, or external artifact is failing before training begins.

| Symptom | Likely cause | Recovery |
| --- | --- | --- |
| Checker reports no class folders | The root points at a parent directory, validation-pair root, or an empty folder instead of an ImageFolder identity root. | For PyTorch, point at the directory that contains identity folders, often the `imgs` child under the configured data parent. For PaddlePaddle, point at the configured data root whose immediate children are identities. |
| Class has zero valid images | The class contains only hidden files, unsupported extensions, nested folders, or images one level deeper than expected. | Move images directly under the identity folder, remove hidden files, convert unsupported files, then rerun `scripts/check_image_folder.py`. |
| Hidden `.DS_Store` or `.ipynb_checkpoints` appears in the report | Files were copied from macOS/notebooks or generated by tooling. PyTorch may ignore unsupported hidden files, but PaddlePaddle loaders can try to open every listed file. | Clean hidden entries before training. `scripts/remove_lowshot_safe.py --apply --copy-to <new-root>` removes hidden entries in the copied/pruned tree. |
| Low-shot pruning would remove too many classes | Threshold is too high, valid images are not counted because they have unsupported extensions, or the root is wrong. | Run the checker with the same `--min-num`, inspect class counts, lower the threshold if appropriate, and dry-run before any `--apply`. |
| Source data changed after an in-place prune | The original repo helper removed class folders destructively, and `--apply` without `--copy-to` mutates the chosen root. | Restore from backup if needed. Prefer the bundled safe helper's default dry-run and use `--copy-to` for production data so the source tree remains intact. |
| `bcolz` validation set is missing or cannot open | The validation benchmark was not downloaded, the directory name is wrong, or the matching `<name>_list.npy` file is missing. | Put each validation carray directory and its list file under the same validation root, for example `lfw/` with `lfw_list.npy` or `agedb_30/` with `agedb_30_list.npy`. Missing one benchmark blocks only that benchmark. |
| `import bcolz` fails before reading data | The Python/numpy/bcolz combination is incompatible. | Fix the environment dependency first. Once `bcolz` imports, recheck validation folder names and list files. |
| Training loader finds classes but labels shift unexpectedly | Class folders were added, removed, or renamed after checkpoint creation; PaddlePaddle source assigns labels from directory listing order. | Freeze the class folder set for a run. If labels must be reproducible across tools, generate and save a class-name manifest before training. |
| Model-zoo or data-zoo download cannot be accessed | External host, credential, password, license, or storage limitation. | Ask the user for an approved local artifact or permission. Do not embed credentials, cookies, or alternate-drive scraping logic in runtime scripts. |
| User asks for MTCNN crops or alignment transforms | Data preparation is not the alignment owner. | Route to `face-alignment`; return here only after the aligned identity-folder root exists. |
| User asks why a checkpoint score is low after data prep | Data layout may be valid, but checkpoint/backbone/head/loss or metric settings may be wrong. | Route checkpoint loading and ROC/verification to `feature-extraction-verification`; route training configuration to `pytorch-training` or `paddle-workflows`. |

## Quick recovery order

1. Validate the root with `scripts/check_image_folder.py`.
2. Remove hidden files and low-shot classes on a copy if pruning is desired.
3. Re-validate the copy and record class counts.
4. Check validation `bcolz` carray/list pairs separately.
5. Only then hand off to training or feature verification workflows.
