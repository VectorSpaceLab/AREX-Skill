# Dataset-management troubleshooting

Back to [dataset-management](../SKILL.md). Diagnose in a non-destructive order:
identify whether the operation is catalog-only, local/offline, or networked;
record the exact dataset class and selected ids; inspect without overwriting;
then choose a new writable path where possible.

| Symptom | Likely cause | Check | Recovery |
|---|---|---|---|
| `ImportError: mne_bids` while using `LocalBIDSDataset` or BIDS conversion | Optional BIDS dependency is absent or incompatible | `python -c 'import mne_bids; print(mne_bids.__version__)'` | Install the MOABB BIDS extra in the active environment, then rerun the tiny local/fake check. Do not convert real data until imports pass. |
| `ImportError` from an individual dataset reader | Dataset-specific optional reader is not installed | Import the dataset class and read its documented loader dependency; inspect the raised module name | Install only the required optional extra/reader, or select a base-package dataset. Do not silently substitute a different format. |
| `set_download_dir` appears ignored | A dataset-specific MNE path, explicit `path=`, environment variable, or stale process config wins | Print `mne.get_config("MNE_DATA")`, `MNE_DATASETS_<SIGNIFIER>_PATH`, and the explicit argument without secrets | Use one explicit writable `path=` for the operation; do not edit user data to migrate directories. |
| Default data directory is unexpected or missing | `MNE_DATA` was unset and resolution chose the home default | Run `scripts/check_download_config.py`; inspect `mne.get_config("MNE_DATA")` | Set an explicit project/cache directory with `set_download_dir`; preserve any existing default tree. |
| `Unknown download provider` | Provider name is not one of `auto`, `nemar`, `upstream` | `get_download_provider()` and inspect the requested string | Normalize to a supported value. For one run, set `MOABB_DOWNLOAD_PROVIDER`; restore persistent config after testing. |
| NEMAR provider fails for a dataset with no mirror | Provider pinned to `nemar`, but the class has no `nemar_id` | Inspect `dataset.nemar_id` and `get_download_provider()` | Use `auto` or `upstream` if network policy allows. If reproducible NEMAR-only acquisition is required, stop and report it as unavailable. |
| `auto` warns and falls back to upstream | NEMAR sourcedata is missing/unavailable | Capture the warning and provider; inspect the dataset's `nemar_id` | Accept the upstream fallback only with network approval, or pin `nemar` to fail closed. Do not call `force_update` merely to silence the warning. |
| `data_path()` returns no usable path or network starts unexpectedly | A missing local subject triggers the dataset downloader | Check whether the root contains expected files and whether the host is offline | Switch to `FakeDataset`/local BIDS for offline work; for approved network work use one subject and a new writable path. |
| HTTP, DNS, TLS, rate-limit, or license prompt failure | Network/provider/host/license boundary, not a parsing bug | Reproduce with a single subject; inspect URL/provider and license requirement without logging credentials | Stop, report the blocked host or acceptance requirement, or retry later under approved network policy. Do not claim data availability. |
| `ValueError: Invalid subjects` | Subject is not in the dataset's selected/full ids | Print `dataset.subject_list` and `dataset.all_subjects` | Instantiate with valid `subjects=[...]`; do not cast identifiers blindly. |
| Session filter returns no data | Session key is wrong or does not match the numeric-prefix rule | Inspect `data[subject].keys()` from an unfiltered fake/local fixture | Use integer `0` for `"0train"`-style keys or the exact string `"0desc"`; retain numeric-prefix session naming. |
| `ValueError` about session/run names | Loader or hand-built fixture emitted invalid/duplicate keys | Print the nested keys and compare with `0`, `0train`, `1test` pattern | Fix the source adapter/fixture; do not bypass validation or rename after a scientific run without recording it. |
| `LocalBIDSDataset` says no BIDS dataset found | Root is empty, wrong, or has no matching EEG raw extension | Run `mne_bids.find_matching_paths` for the root and inspect `sub-*/*/eeg` | Point to the BIDS root (not a subject/eeg leaf), or provide `path_search_params`; use a tiny known-good fixture to isolate format issues. |
| Local BIDS loads one session instead of two | Session entities are absent, filtered, or uneven across subjects | Inspect BIDS filenames/entities and `local.bids_paths(subject)` | Add/repair session entities or set `sessions_per_subject` only when the files really have that structure; do not fabricate a second session. |
| `get_additional_metadata` returns `None` | No matching events sidecar | Check the selected BIDS path and `*_events.tsv` | Treat event metadata as unavailable; supply a correct sidecar or route event construction to the paradigm workflow. |
| Event metadata is empty or labels do not match | `trial_type` values do not intersect `dataset.event_id` | Print unique `trial_type` values and `dataset.event_id` | Correct the declared event mapping or sidecar labels after confirming source semantics; do not relabel silently. |
| Channel count or names disagree with `metadata` | Metadata is stale, raw includes/excludes modalities, or BIDS sidecar is inconsistent | Compare non-stim `raw.ch_names`, `get_channel_types()`, `raw.info["sfreq"]`, sidecars, and metadata | Stop and report the mismatch. Check `return_all_modalities`; repair provenance/source metadata, not the data by arbitrary channel deletion. |
| BIDS conversion fails on missing annotations | Raw data has no annotations for event export | Inspect `raw.annotations` before `convert_to_bids` | Use the dataset's fixed annotation/event pipeline or a source format with event markers; do not invent event onsets. |
| Unsupported BIDS format | `format` is outside `EDF`, `BrainVision`, `EEGLAB`, `BDF` | Inspect the exact argument and current `convert_to_bids` signature | Choose a supported format and a new output root. |
| `PermissionError`, read-only filesystem, or lock/sidecar write failure | Cache/output root is not writable, quota is exhausted, or another process holds a lock | Write a harmless permission sentinel; check free space and active writers; inspect without deleting | Preserve the root, choose a new writable cache/output path, rerun one subject. Never respond by deleting user data. |
| Cache has data files but loading says no cache | A per-session completion lock is missing or processing digest differs | Inspect `code/*lockfile.json`, the data filenames, and cache `path`; use `bids_metainfo` read-only | Treat it as incomplete; preserve it and recompute into a new root. Use `overwrite_*` only against a disposable copy. |
| Cache reads but raw is wrong/stale | Cache digest or dataset version/path changed | Compare the cache path, processing configuration, MOABB version, and raw metadata | Isolate a fresh cache and compare one subject; do not mutate the only copy. |
| Archive extraction raises unsafe member path/link error | ZIP/TAR contains traversal or symlink/hardlink members | Inspect member names only; do not extract with raw `extractall` | Reject the archive or manually vet it under a quarantine root. MOABB safe helpers intentionally fail closed. |
| Metadata property is `None` | Dataset is not in the structured catalog (as with `FakeDataset`) | Call `dataset.metadata` and `get_dataset_metadata` for a known catalog key | Treat missing metadata as unknown; validate actual raw/BIDS fields and do not fabricate catalog values. |
| `validate_metadata_against_dataset` returns mismatches | Declared sessions, release subject count, or country code differs | Print every returned string; compare to `all_subjects`, `n_sessions`, and metadata docs | Resolve whether the constructor is filtered (expected) or the catalog/source is stale; keep the mismatch visible until resolved. |
| Catalog search is slow or touches data | `channels` filtering or channel intersection loads subject 1 | Check the search arguments and network logs | Perform catalog-only search first; apply data-dependent channel checks only after an acquisition decision. |
| Fake fixture appears scientifically meaningful | Synthetic random data was mistaken for a real recording | Check `isinstance(dataset, FakeDataset)`, seed, and source label | Use it only for shape/error/reproducibility checks and label all results synthetic. |
| XDF parser rejects a file or marker stream is wrong | The file is not the supported XDF structure, stream metadata is incomplete, or markers use unexpected strings | Run a tiny `read_xdf(path)` check and inspect stream `info`, `time_series`, and `time_stamps` without loading it into a paradigm | Preserve the original file, report the stream/marker mismatch, and use the dataset-specific loader contract; do not relabel marker strings silently. |

Optional Plotly/neural-signature generation, large downloads, NEMAR/upstream
network access, and archive extraction are explicitly non-core. The bundled
scripts are offline and do not attempt any of those operations.
