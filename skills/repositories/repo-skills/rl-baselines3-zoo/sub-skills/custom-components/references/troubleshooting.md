# Troubleshooting custom RL Zoo components

Use this table after validating imports with `../scripts/component_import_checker.py`. For full config-file syntax fixes, route to `../../config-hyperparams/SKILL.md`; for rerunning training, route to `../../training-cli/SKILL.md`.

| Symptom | Likely cause | What to check | Recovery action |
| --- | --- | --- | --- |
| `ModuleNotFoundError`, `ImportError`, or `AttributeError` for a wrapper/callback/policy | Bad dotted import string, package not installed, class renamed, or wrong capitalization. | Run the bundled checker with the exact string. Confirm the string has at least one dot and that the module imports in the same Python environment as RL Zoo. | Install the missing package if it is expected, fix the module path/class name, or place the custom package on `PYTHONPATH`/package it properly. Do not start training until imports pass. |
| Checker reports “component mapping must contain exactly one key” or RL Zoo raises an assertion about YAML formatting | A wrapper/callback dict item has multiple keys because indentation grouped multiple components into one mapping. | Inspect the YAML around `env_wrapper`, `vec_env_wrapper`, or `callback`. Each list item should be either one string or one single-key mapping. | Rewrite as a list of one-key items, for example `- rl_zoo3.wrappers.DelayedRewardWrapper: {delay: 4}` followed by the next `- ...` item. For broader YAML grammar, use `../../config-hyperparams/SKILL.md`. |
| Wrapper imports pass but training fails with an observation/action-space assertion | The wrapper is incompatible with the env spaces. | Check the wrapper constraints in `api-reference.md`: `HistoryWrapper` requires Box observation and Box action spaces; action noise/smoothing wrappers assume continuous Box actions; `HistoryWrapperObsDict` requires a Dict observation with Box `observation`. | Pick the wrapper variant that matches the env, change wrapper order, or remove the wrapper. For Dict observations, use `HistoryWrapperObsDict` instead of `HistoryWrapper`. |
| `HistoryWrapper` fails on a Dict observation environment | `HistoryWrapper` asserts `env.observation_space` is `spaces.Box`. | Determine whether the Dict observation has an `"observation"` key and whether that subspace is Box. | Use `rl_zoo3.wrappers.HistoryWrapperObsDict` when the Dict shape matches its constraints; otherwise write a custom wrapper for the env's Dict schema. |
| `RawStatisticsCallback` raises `You must activate tensorboard logging when using RawStatisticsCallback` | The callback looks for a TensorBoard output format during callback initialization. | Check whether the train command set `--tensorboard-log <dir>` or whether another integration created TensorBoard logging. | Add `--tensorboard-log ./tb` for training runs using this callback. If the task does not need raw TensorBoard episode metrics, remove the callback. |
| `ParallelTrainCallback` raises that the model is not supported | The callback asserts that the model instance is `SAC` or `TQC`. | Check `--algo`. PPO, A2C, DQN, TD3, DDPG, ARS, TRPO, QRDQN, CrossQ, and recurrent PPO are not accepted by this callback in the current implementation. | Use `--algo sac` or `--algo tqc` with compatible off-policy settings, or remove the callback. For HPO interactions, route to `../../tuning-optimization/SKILL.md`. |
| Custom env id is reported as not in Gym registry | The registration module was not imported before RL Zoo checked the registry, or the id differs from the registered id. | Validate the package import with `--gym-package my_envs` in the checker. In a Python shell, importing the package should make `gymnasium.envs.registry` contain the id. | Add `--gym-packages my_envs` to the RL Zoo command, fix the `register(id=...)` string, or package the registration module so it is importable. |
| Optional env family ids are missing even though RL Zoo starts | `rl_zoo3.import_envs` silently skips optional environment packages that are not installed. | Identify whether the env belongs to PyBullet, ALE/Atari, highway, DonkeyCar, Panda Gym, rocket lander, MiniGrid, Box2D/LunarLander, or another optional family. | Install only the needed simulator/env package for the task. Avoid installing every optional family by default. For base install issues, use `../../../references/install-and-environment.md`. |
| `MaskVelocityWrapper` raises `Velocity masking not implemented for ...` | The wrapper only knows specific classic-control and LunarLander ids. | Compare the env id with the supported table in `api-reference.md`. The env needs `env.unwrapped.spec.id`. | Use one of the supported NoVel ids or base ids, or write a custom observation wrapper with the correct velocity indices for the new env. |
| `LunarLanderNoVel-v3` or `LunarLanderContinuousNoVel-v3` cannot be created | NoVel registration exists, but the base LunarLander env requires optional Box2D support. | Check whether Gymnasium Box2D dependencies are installed. | Install the specific Box2D/LunarLander dependency if needed, or choose a supported NoVel id with already available dependencies such as `CartPoleNoVel-v1`. |
| Callback constructor binding fails for a Stable-Baselines3 callback | The callback has required constructor args that were not supplied in config. | Run the checker against the YAML config; it will report signature binding errors when kwargs cannot satisfy the constructor. | Add required kwargs when they are simple scalars, or avoid configuring callbacks that require runtime objects such as an eval env. Use RL Zoo's built-in `--eval-freq`/`--save-freq` for common eval/checkpoint behavior. |
| Policy import passes but model construction fails later | Import validation only proves that the policy object exists; algorithm-specific policy compatibility is checked by SB3 during model construction. | Check that the policy class matches the algorithm family and accepts the algorithm's observation/action spaces. | Use the standard policy string for the selected algo, or provide a custom policy that subclasses the expected SB3 policy type. Route full config changes to `../../config-hyperparams/SKILL.md`. |
| SBX/custom algorithm name is rejected by the CLI parser | The registry patch was not applied before parser construction in the same process. | Confirm the shim updates `rl_zoo3.ALGOS`, the train/enjoy module `ALGOS`, and `rl_zoo3.exp_manager.ALGOS` before calling `train()` or `enjoy()`. | Run through a patched Python shim instead of `python -m rl_zoo3.train`, and ensure optional SBX/JAX dependencies are installed. New algorithm names need compatible config coverage. |
| `rl_zoo3 train` console import fails before reaching component validation | The console router imports plotting modules for all subcommands; plot extras may be missing. | Try `python -m rl_zoo3.train --help`. | Prefer module commands for training/evaluation when console extras are unavailable, or use the root install guidance at `../../../references/install-and-environment.md`. |

## Quick diagnostic sequence

1. Validate explicit registration modules and import strings:

   ```bash
   python ../scripts/component_import_checker.py \
     --gym-package my_envs --config ./my_hyperparams.yml --env MyEnv-v0
   ```

2. If imports pass but a wrapper fails during env creation, check observation/action-space constraints in [api-reference.md](api-reference.md).
3. If a callback fails at training start, check whether it needs TensorBoard logging, SAC/TQC, or runtime objects.
4. Only after the component layer is clean, reroute the actual training or evaluation command to `../../training-cli/SKILL.md` or the appropriate sibling sub-skill.
