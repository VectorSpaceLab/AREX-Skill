# Object Detection Workflows

These workflows are self-contained usage patterns for ImageAI still-image detection. They assume the ImageAI package is installed and that model assets are supplied by the caller; no workflow downloads weights.

## Choose the detector

Use this decision table first:

| Task | Detector class | Model assets | Output guidance |
|---|---|---|---|
| Detect standard COCO objects in a still image with high accuracy | `ObjectDetection` with `retinanet` | RetinaNet `.pth` COCO weights | Use file output for annotated image review; use array output inside services. |
| Detect standard COCO objects with moderate speed/accuracy | `ObjectDetection` with `yolov3` | YOLOv3 `.pt` COCO weights | Good default when matching COCO class labels and using `CustomObjects` filters. |
| Detect standard COCO objects quickly | `ObjectDetection` with `tiny-yolov3` | TinyYOLOv3 `.pt` COCO weights | Faster/smaller, usually less accurate. |
| Detect labels from your own trained detector | `CustomObjectDetection` with `yolov3` or `tiny-yolov3` | Matching custom `.pt`/`.pth` weights plus detection config JSON | Use the JSON generated by ImageAI detection training; do not use RetinaNet in custom mode. |

## COCO still-image detection

```python
from imageai.Detection import ObjectDetection

model_path = "models/yolov3.pt"
input_path = "images/input.jpg"
output_path = "outputs/input-detected.jpg"

detector = ObjectDetection()
detector.setModelTypeAsYOLOv3()
detector.setModelPath(model_path)
detector.loadModel()

detections = detector.detectObjectsFromImage(
    input_image=input_path,
    output_image_path=output_path,
    minimum_percentage_probability=50,
)

for item in detections:
    print(item["name"], item["percentage_probability"], item["box_points"])
```

Change only the model-type setter and weight path for other COCO model families:

```python
# RetinaNet COCO
detector.setModelTypeAsRetinaNet()
detector.setModelPath("models/retinanet_resnet50_fpn_coco.pth")

# TinyYOLOv3 COCO
detector.setModelTypeAsTinyYOLOv3()
detector.setModelPath("models/tiny-yolov3.pt")
```

## COCO filtering with `CustomObjects`

For a request like "detect only cars and motorcycles," build a COCO filter dictionary and pass it as `custom_objects`:

```python
from imageai.Detection import ObjectDetection

detector = ObjectDetection()
detector.setModelTypeAsYOLOv3()
detector.setModelPath("models/yolov3.pt")
detector.loadModel()

custom = detector.CustomObjects(car=True, motorbike=True)
detections = detector.detectObjectsFromImage(
    input_image="street.jpg",
    output_image_path="street-car-motorbike.jpg",
    custom_objects=custom,
    minimum_percentage_probability=40,
)
```

Use [coco-object-classes.md](coco-object-classes.md) for exact labels. The YOLO COCO list uses `motorbike`, `aeroplane`, `sofa`, `pottedplant`, `diningtable`, and `tvmonitor`; RetinaNet switches to the COCO91 list after model loading and uses names such as `motorcycle`, `airplane`, `couch`, `potted plant`, `dining table`, and `tv`. Because `CustomObjects` replaces spaces with underscores for keyword names, use names like `traffic_light=True`, `cell_phone=True`, and `teddy_bear=True` when spaces appear in the loaded class list.

## Custom YOLO/TinyYOLO still-image detection

Custom detection requires a trained ImageAI YOLO/TinyYOLO weight file and the matching detection config JSON containing `labels` and `anchors`.

```python
from imageai.Detection.Custom import CustomObjectDetection

detector = CustomObjectDetection()
detector.setModelTypeAsYOLOv3()  # or setModelTypeAsTinyYOLOv3()
detector.setModelPath("models/custom-detector.pt")
detector.setJsonPath("models/custom_detection_config.json")
detector.loadModel()

detections = detector.detectObjectsFromImage(
    input_image="images/input.jpg",
    output_image_path="outputs/input-custom-detected.jpg",
    minimum_percentage_probability=40,
    nms_treshold=0.4,
    objectness_treshold=0.4,
)
```

Custom-model label filtering uses a dictionary whose keys match config labels with spaces replaced by underscores. Example for a custom config with labels `license plate` and `car`:

```python
custom_filter = {"license_plate": True, "car": False}
detections = detector.detectObjectsFromImage(
    input_image="parking.jpg",
    output_type="array",
    custom_objects=custom_filter,
)
```

When the task is to create the `.pt`/`.pth` and JSON assets, route to `custom-training-and-data` first, then return here to run inference.

## File output versus array output

Choose `output_type="file"` when the caller wants an annotated image saved to disk, for example batch processing or human review:

```python
detections = detector.detectObjectsFromImage(
    input_image="input.jpg",
    output_image_path="detected.jpg",
    output_type="file",
)
```

Choose `output_type="array"` for web APIs, notebooks, in-memory pipelines, or callers that will encode the output image themselves:

```python
image_array, detections = detector.detectObjectsFromImage(
    input_image="input.jpg",
    output_type="array",
)
```

Returned image arrays are OpenCV/Numpy BGR-style arrays. If a web API must return JPEG/PNG bytes, encode explicitly with OpenCV/Pillow after detection. Do not pass `input_type`; current ImageAI 3.x still-image signatures infer the input form from `input_image`.

## Extract detected objects

File extraction:

```python
detections, extracted_paths = detector.detectObjectsFromImage(
    input_image="input.jpg",
    output_image_path="detected.jpg",
    output_type="file",
    extract_detected_objects=True,
)
```

This writes `detected.jpg`, creates `detected-extracted/`, and writes crop files such as `detected-1.jpg`, `detected-2.jpg`, in that directory. The current source derives the extraction directory by removing the output file extension and appending `-extracted`. Ensure that directory does not already exist before calling.

Array extraction:

```python
image_array, detections, extracted_arrays = detector.detectObjectsFromImage(
    input_image="input.jpg",
    output_type="array",
    extract_detected_objects=True,
)
```

`extracted_arrays` contains one Numpy crop for each returned detection above `minimum_percentage_probability`. This is the safer choice for services that do not want temporary extraction directories.

## Threshold and display recipes

- More detections: lower `minimum_percentage_probability`, for example `30`. Expect more false positives.
- Fewer, stricter detections: raise `minimum_percentage_probability`, for example `70`.
- Custom YOLO post-processing: tune `nms_treshold` and `objectness_treshold` only in custom mode. Lower objectness may increase candidate detections; higher objectness may suppress weak detections. The final returned list is still filtered by `minimum_percentage_probability`.
- Hide labels/probabilities on the annotated output without changing detections:

```python
detections = detector.detectObjectsFromImage(
    input_image="input.jpg",
    output_image_path="detected-clean.jpg",
    display_object_name=False,
    display_percentage_probability=False,
)
```

- Hide boxes but keep text:

```python
detections = detector.detectObjectsFromImage(
    input_image="input.jpg",
    output_image_path="detected-text-only.jpg",
    display_box=False,
)
```

## Bundled helper examples

From this sub-skill directory, inspect the helper:

```bash
python scripts/detect_image.py --help
```

COCO YOLOv3 with car/motorbike filtering and file output:

```bash
python scripts/detect_image.py \
  --mode coco \
  --model-type yolov3 \
  --model-path /path/to/yolov3.pt \
  --input-image /path/to/street.jpg \
  --output-image /path/to/street-detected.jpg \
  --custom-objects car,motorbike \
  --minimum-percentage-probability 40 \
  --print-json
```

Custom YOLOv3 with in-memory/array output summarized as JSON:

```bash
python scripts/detect_image.py \
  --mode custom \
  --model-type yolov3 \
  --model-path /path/to/custom.pt \
  --json-path /path/to/custom_detection_config.json \
  --input-image /path/to/input.jpg \
  --output-type array \
  --extract \
  --nms-treshold 0.4 \
  --objectness-treshold 0.4 \
  --print-json
```

The helper validates paths and output choices before loading weights, never downloads assets, and does not assume any current working directory.
