# Cache and Serialization

## Report cache behavior

`ProfileReport` caches expensive intermediate and rendered values. Cached areas
include description data, report structure, HTML, JSON, and widgets.

If you mutate configuration after output has been generated, invalidate the
relevant cache before rendering again:

```python
profile.config.html.minify_html = False
profile.invalidate_cache("rendering")
html = profile.to_html()
```

Accepted `invalidate_cache` values:

| Value | Effect |
| --- | --- |
| `None` | Clear all report/rendering/description caches. |
| `"rendering"` | Clear HTML, JSON, and widgets. |
| `"report"` | Clear report structure and rendered outputs. |

Other values raise `ValueError`.

## Serialization methods

`ProfileReport` inherits serialization helpers:

```python
profile.dump("profile.pp")
reloaded = ProfileReport(df).load("profile.pp")
```

Details:

- `dump(path)` writes a `.pp` suffix.
- `load(path)` reads serialized state into a `ProfileReport` object.
- `dumps()` and `loads(data)` operate on bytes.
- Serialization stores the DataFrame hash, config, computed description, and
  report structure when available.

## DataFrame mismatch

Loading into a report with a different DataFrame raises:

```text
ValueError: DataFrame does not match with the current ProfileReport.
```

Use the same DataFrame or initialize a report without a DataFrame when loading a
saved profile for inspection.

## Version mismatch warning

If serialized report data was generated by a different data-profiling version,
loading may warn that the stored version differs from the current package. Treat
that as a compatibility warning and regenerate the report when exact outputs
matter.

## Recommended automation pattern

For reproducible jobs, prefer regenerating from source data and config. Use
serialization when report computation is expensive and the DataFrame identity is
stable.
