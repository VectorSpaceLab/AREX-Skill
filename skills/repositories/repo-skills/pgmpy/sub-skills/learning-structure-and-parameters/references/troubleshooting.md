# Troubleshooting Learning Workflows

| Symptom | Likely cause | Recovery |
|---|---|---|
| `Unknown CI test` or a CI test silently seems inappropriate | Name typo or data type mismatch | Resolve with `get_ci_test(test=name, data=data)` and check the selected class. Use `chi_square`/`g_sq` for discrete, `pearsonr`/`fisher_z` for continuous, and `pillai` or another mixed test for mixed data. |
| Discrete CI test on numeric-coded continuous data gives misleading graph | Continuous measurements were encoded as numbers but treated as categories | Either discretize intentionally and document bins, or switch to continuous CI tests/scores. |
| Continuous CI test fails or behaves poorly on object/category columns | Categorical states were passed to a continuous test | Convert to the correct dtype and choose a discrete or mixed CI test. Do not fix this by arbitrary integer coding unless the model assumptions justify it. |
| `Unknown scoring method` | Score string does not match the registered score names | Use `bic-d`, `k2`, `bdeu`, `bds`, `ll-d`, `aic-d` for discrete; `bic-g`, `ll-g`, `aic-g` for Gaussian; `bic-cg`, `ll-cg`, `aic-cg` for mixed conditional-Gaussian. |
| Score/data mismatch or nonsensical score-based result | Discrete score on continuous data, Gaussian score on categorical data, or mixed score without mixed assumptions | Reclassify columns first; pass a configured score instance only after confirming its supported data type. |
| Learned graph is a PDAG but parameter fitting expects a BN | Discovery returned `return_type="pdag"`/`"cpdag"` | Refit with `return_type="dag"` when a concrete parameterized BN is required, or explicitly choose a consistent DAG orientation before fitting. |
| `start_dag should be a DAG with the same variables` | `HillClimbSearch.start_dag` nodes differ from data columns | Add all data columns as graph nodes and remove extra nodes before passing `start_dag`. |
| Required expert edges create a cycle | Inconsistent `required_edges`, `start_dag`, or temporal order | Check cycles before fitting. Remove or reverse the conflicting constraint; do not suppress the error by dropping required knowledge silently. |
| Expert knowledge appears ignored | Using the legacy `ExpertKnowledge`, not calling through a supported estimator, or constraints conflict with learned skeleton | Import from `pgmpy.causal_discovery`, use canonical estimators, and inspect fitted `required_edges_`/`forbidden_edges_`. For hard orientation, forbid the reverse edge as well as requiring the forward edge when needed. |
| `Missing nodes in temporal order` | `ExpertKnowledge(temporal_order=...)` does not cover exactly the data columns | Include every variable in one and only one temporal tier, or remove `temporal_order` for variables whose order is unknown. |
| Sparse data produces zero or unstable CPD probabilities | Some parent-state combinations or child states are absent | Pass complete `state_names` and use `DiscreteBayesianEstimator(prior_type="BDeu" or "dirichlet", ...)` with suitable pseudo-counts/equivalent sample size. |
| `pseudo_counts` shape error | Dirichlet pseudo-count matrix shape does not match `(node_cardinality, product(parent_cardinalities))` | Build pseudo-count arrays from the node and sorted parent cardinalities, or use scalar pseudo-counts/BDeu first. |
| CPD state order surprises downstream inference | State names inferred from observed values only or sorted differently than expected | Pass `state_names` explicitly to the estimator and reuse the same mapping for every fit/update. |
| EM drops rows or treats a column as latent | EM preprocessing drops partially missing rows and treats fully missing model columns as latent | Tell the user how many rows/columns are affected, set `latent_card`, and prefer `init_cpds="uniform"` or a seeded random initialization for reproducibility. |
| EM is slow or unstable | Many latent variables, large cardinalities, too small batch size, or random initialization | Reduce latent scope, set `latent_card`, raise `batch_size`, lower `max_iter` for smoke runs, use deterministic `seed`, or initialize CPDs explicitly. |
| `m_step_estimator ... doesn't support weighted data` in EM | M-step estimator cannot consume EM sample weights | Use `DiscreteMLE()` or `DiscreteBayesianEstimator(...)` as the M-step estimator. |
| `LinearGaussianMLE` errors on model/data mismatch | Model nodes are absent from the continuous data | Ensure every model node has a numeric column; route model construction details to `modeling-and-factors` if nodes/edges need redesign. |
| Bivariate `ANM`/`IGCI` raises about exactly two variables, non-continuous data, constant variables, NaN score, or tie | Bivariate assumptions are violated or direction is not identifiable | Pass exactly two non-constant continuous columns; try an alternative score only if assumptions hold. Report ambiguity instead of forcing an orientation. |
| `LLMPairwise` import or provider call fails | Optional LiteLLM dependency, API key, remote network, or local provider endpoint is missing | Treat LLM orientation as optional. Install the optional dependency and configure provider credentials/endpoints only with user approval; use a deterministic custom pairwise estimator for offline verification. |
| Automated examples hang on progress bars or parallel overhead | `show_progress=True` or `n_jobs=-1` on tiny fixtures | Use `show_progress=False`; set `n_jobs=1` for small deterministic tests. |
| User follows old notebook examples and cannot find `estimate(...)` | Legacy API example conflicts with canonical API | Translate to `fit(data)` and read `causal_graph_`. Use legacy classes only when exact legacy behavior is required. |
