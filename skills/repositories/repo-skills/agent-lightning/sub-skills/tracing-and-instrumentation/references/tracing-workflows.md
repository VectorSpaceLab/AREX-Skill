# Tracing workflows

## Purpose

Use this reference to create trace spans, emit learning signals, and inspect the resulting records in a `LightningStore`.

## Tracer choices

| Tracer | Use when | Notes |
| --- | --- | --- |
| `OtelTracer` | You want a small local tracer or already use OpenTelemetry spans | Best default for deterministic CPU smoke tests. |
| `AgentOpsTracer` | You want framework instrumentation through AgentOps-compatible integrations | Default in `Trainer` when no tracer is specified; it does not require hosted AgentOps service for local capture. |
| `DummyTracer` | You need non-propagating local span creation | Useful behind `propagate=False` or tests. |
| Weave tracer | You explicitly installed/configured Weave integration | Experimental; verify in the target environment first. |

## Emitters

The main helpers are:

```python
emit_reward(reward, *, primary_key=None, attributes=None, propagate=True)
emit_message(message, attributes=None, propagate=True)
emit_object(object, attributes=None, propagate=True)
emit_exception(exception, attributes=None, propagate=True)
emit_annotation(annotation, propagate=True)
operation(fn=None, *, propagate=True, name=None, **attributes)
```

### Single reward

```python
import agentlightning as agl
agl.emit_reward(1.0)
```

### Multi-dimensional reward

```python
agl.emit_reward({"task_completion": 1.0, "efficiency": 0.8}, primary_key="task_completion")
```

The first dimension is the primary reward used by `get_reward_value` and `find_final_reward`.

### Operation span

```python
with agl.operation(category="tool") as op:
    op.set_input(query="agent lightning")
    result = {"matches": 3}
    op.set_output(result)
    agl.emit_reward(0.9)
```

`operation` also works as a decorator and records bound arguments plus return values.

## Tags and links

Use helper utilities to express reward labels or connect a reward to an earlier span:

```python
from agentlightning.utils.otel import make_link_attributes, make_tag_attributes

attrs = {
    **make_tag_attributes(["tool", "final"]),
    **make_link_attributes({"conversation_id": "chat-42"}),
}
agl.emit_reward(0.75, attributes=attrs)
```

Later, use `extract_tags_from_attributes`, `extract_links_from_attributes`, and `query_linked_spans` to recover relationships.

## Local trace smoke

Use `OtelTracer` with an in-memory store for a service-free trace:

```python
store = agl.InMemoryLightningStore()
tracer = agl.OtelTracer()
rollout = await store.start_rollout(input={"origin": "manual"})
with tracer.lifespan(store):
    async with tracer.trace_context("manual", store=store, rollout_id=rollout.rollout_id, attempt_id=rollout.attempt.attempt_id):
        agl.emit_message("starting")
        agl.emit_object({"step": 1})
        agl.emit_reward(1.0)
spans = await store.query_spans(rollout.rollout_id)
assert agl.find_final_reward(spans) == 1.0
```

The bundled `scripts/local_trace_smoke.py` is a runnable version with assertions.

## Adapter workflow

Use adapters when algorithms need trace data in a different representation:

- `TraceToMessages()` converts Agent Lightning spans to OpenAI chat message objects for prompt-optimization/SFT-style workflows.
- `TracerTraceToTriplet()` converts tracer spans to `(prompt, response, reward)` triplets and can repair span hierarchy.
- `LlmProxyTraceToTriplet()` interprets spans generated by `LLMProxy`.

Typical inspection flow:

```python
spans = await store.query_spans(rollout_id)
reward = agl.find_final_reward(spans)
messages = agl.TraceToMessages().adapt(spans)
triplets = agl.TracerTraceToTriplet().adapt(spans)
```

Choose the adapter that matches how spans were produced and what the algorithm expects.

## Token IDs and LLM proxy spans

For RL algorithms that train model weights, token IDs can matter because retokenizing chat messages may drift from what the model actually generated. Agent Lightning's `LLMProxy` can request token IDs from compatible vLLM backends and persist proxy spans. Verify token IDs by inspecting span attributes and response payloads; do not assume they are present for every OpenAI-compatible service.

If token IDs are missing:

1. Confirm the backend supports token IDs.
2. Confirm the proxy inserted the appropriate request flag.
3. Inspect `raw_gen_ai_request` or LLM span attributes.
4. Route service setup to `cli-and-services` and training implications to `runner-store-training`.
