# Visitors and transformers

## Dispatch model

Import the two public bases:

```python
from openqasm3.visitor import QASMVisitor, QASMTransformer
```

Dispatch is by exact concrete class name. For a node whose class is
`Identifier`, `visit` looks for `visit_Identifier`; otherwise it calls
`generic_visit`:

```python
class NameCollector(QASMVisitor):
    def __init__(self):
        self.names = []

    def visit_Identifier(self, node):
        self.names.append(node.name)
        return node
```

`QASMVisitor.visit(node, context=None)` forwards the selected method's return
value. `generic_visit` walks direct child values in `node.__dict__` and visits
`QASMNode` items in fields and lists. A specialized method that does not call
`generic_visit` intentionally prunes that node's descendants, so either recurse
explicitly or document the boundary.

## The falsey-context caveat

The implementation tests context truthiness rather than testing
`context is not None`. It calls a visitor with `visitor(node, context)` only
when `context` is truthy; a falsey context is treated like no context. The same
rule is used for recursive calls. Consequently, an empty dictionary, `0`,
`False`, or an empty list will not reach a context-aware method as its context.
Use a non-empty mutable container, override `visit`/`generic_visit` if falsey
values are meaningful, or keep an accumulator on `self`:

```python
class Counter(QASMVisitor):
    def __init__(self):
        self.counts = {}

    def visit(self, node, context=None):
        key = type(node).__name__
        self.counts[key] = self.counts.get(key, 0) + 1
        return super().visit(node, context)
```

Do not accidentally define `visit_Identifier(self, node, context)` and then
call `visit(root, {})`; it will be invoked without the second argument and fail.

## Accumulation and nested shapes

For a simple node count, a visitor override on `visit` is often safer than
writing one method per class. For semantic-looking reports, keep the visitor's
state explicit and avoid confusing an AST walk with symbol resolution. Some
fields contain nested lists or tuples (for example switch cases and index
structures); if a complete structural walk is required, handle those shapes
in a deliberate recursive helper rather than assuming every child is a direct
node.

Use concrete node checks for transformations:

```python
class Rename(QASMTransformer):
    def __init__(self, old, new):
        self.old, self.new = old, new
        self.changed = 0

    def visit_Identifier(self, node):
        if node.name == self.old:
            node.name = self.new
            self.changed += 1
        return node
```

This example is lexical: it changes every `Identifier` node with that exact
name. It does not resolve declarations, scopes, overloads, strings, comments,
or raw calibration text. A production compiler pass needs a symbol/binding
policy outside this base class.

## Transformer mutation contract

`QASMTransformer.generic_visit` mutates the existing node and its list fields:

- Within `generic_visit`, a child visitor returning a node keeps that child. A
  specialized method must call `generic_visit` itself if descendants should be
  traversed.
- Returning `None` from a child visitor removes that child from a list.
- Returning `None` for a scalar child deletes that field with `delattr`; the
  result may become unprintable or invalid.
- Returning a non-node iterable while visiting a list child splices its values
  into that list. Only return a deliberate iterable of compatible nodes; a
  string would be an accidental character splice.
- Existing list objects are updated in place, so aliases to those lists observe
  the rewrite.

Because traversal is in place, preserve the original source/AST separately if a
rollback or diff is needed. The transformer does not automatically repair
spans, annotations, symbol references, type information, or semantic
invariants. A changed identifier keeps its old span even though its spelling
changed; spans are not regenerated by the transformer.

## Conservative transformation workflow

1. Parse strictly and collect the node classes/names that the pass intends to
   touch.
2. Reject ambiguous or collision-prone requests before mutating. For a global
   lexical rename, reject a target name already present anywhere in the AST
   unless a binding-aware policy explicitly allows it.
3. Apply a narrow `visit_<ClassName>` method. Avoid rewriting raw string fields
   or relying on textual replacement.
4. Print with `dumps` and immediately strict-parse the result.
5. Confirm the expected AST change, confirm unrelated identifiers remain, and
   separately run grammar/conformance and semantic checks.

The bundled `scripts/rename_identifiers.py` follows this policy and writes only
a validated normalized result. It intentionally refuses obvious global target
collisions and requires explicit permission to overwrite the input path.

## Common pitfalls

- A method named `visit_identifier` will not dispatch for `Identifier`;
  capitalization must match the concrete class exactly.
- A specialized method that returns without visiting children silently prunes
  descendants.
- A falsey context does not get passed through, despite the `context=None`
  signature.
- Deletion and splicing can make required dataclass fields disappear or put
  incompatible objects in lists.
- Successful printing/reparsing establishes syntactic usability of the emitted
  text, not name binding, type correctness, compiler-pass correctness, or
  provider executability.
