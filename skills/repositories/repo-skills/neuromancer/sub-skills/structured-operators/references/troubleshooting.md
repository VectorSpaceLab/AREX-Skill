# Structured-operator troubleshooting

| Symptom | Likely cause | Repair |
|---|---|---|
| `matmul` reports incompatible feature dimensions | The last input axis is not `insize`, or a prior MLP layer has a different width | Print `x.shape`, `layer.in_features`, and `layer.out_features`; reshape only when the sequence/data contract supports it; otherwise choose a map for the actual adjacent widths |
| `Map must be square` assertion | A `SquareLinear` subclass received unequal dimensions | Set `insize == outsize` for `psd`, `orthogonal`, `symmetric`, skew, symplectic, Schur, Gershgorin, or `Power_bound`; use `linear`, `split`, `spectral`, `softSVD`, or another rectangular map when the dimensions must differ |
| `TrivialNullSpaceLinear` rejects construction | It is not a square fallback: it requires `insize <= outsize` and `bias=False` | Make the output at least as wide as the input and disable bias, or select a generic rectangular map |
| Registry lookup raises `KeyError` | Registry names are exact and include historical spellings/case | Inspect `sorted(slim.maps)`; use `skew_symetric`, `softSVD`, `Power_bound`, and `bounded_Lp_norm` exactly; do not silently map a user name to a different class |
| A keyword is rejected or has no effect | `linargs` is being reused across different map classes, or the keyword is not part of that constructor's contract | Start with `{}`; add only documented options such as `sigma_min`, `sigma_max`, reflector counts, `rank`, or `epsilon` for the selected class; test the instantiated class before passing it through an MLP |
| `OrthogonalLinear(..., bias=False)` fails with `Tensor + NoneType` | This release's `forward()` adds `self.bias` unconditionally even when the base registers no bias | Use `bias=True` for this implementation and account for the affine term, or choose a different square map. Do not hide the error by monkey-patching the module |
| `learnSVD` gives unstable or failing behavior | The repository's map test labels `SVDLinearLearnBounds` as broken | Prefer `softSVD` (`SVDLinear`) and independently check the chosen singular-value bounds |
| Import or construction touches butterfly native code | `linear.py` exposes `ButterflyLinear`, which depends on the butterfly multiplication backend | Do not compile or download an extension for the minimum route. Use a pure-Python registry key and record butterfly/complex support as optional and unverified |
| Complex tensors or `complex=True` are requested | Complex handling belongs to the Butterfly implementation, not the CPU pure-Python map contract | Route to an explicitly provisioned native/complex workflow; the bundled smoke does not claim support |
| `GradientProjection` rejects a constraint | It accepts only inequality comparators whose string is `lt` or `gt` | Use an inequality constraint object; keep symbolic expression/comparator construction in `symbolic-problems`. Equality constraints belong to `IterativeSolver` or another solver |
| Solver output has the wrong key or construction asserts on key lengths | `input_keys` and supplied `output_keys` have different lengths, a string key is being iterated character-by-character by a concrete solver, or the consumer reads the input name after an alias was requested | Pass lists such as `['x']`, supply one output key per input key, and read the exact output names. With no output list, the solver reuses input names |
| `GradientProjection` returns no useful update or autograd errors | An input tensor is detached, does not require gradients, or the constraint cannot produce a differentiable violation | Set `requires_grad=True` on projected tensors, preserve differentiable operations, and test `constraint(state)` plus the violation key before calling the solver |
| Projected energy has an unexpected shape | Constraint violation tensors are flattened per batch item and concatenated; a malformed constraint changed the batch axis | Check every violation has the same leading batch dimension and inspect the constraint's three output keys: name, value, violation |
| `IterativeSolver` fails in `jacfwd`, inverse, or shape checking | It is an experimental equality-only Newton prototype; its Jacobian path and inverse need a compatible, well-conditioned tensor layout | Use a tiny equality fixture, verify comparator `eq`, make the Jacobian square/invertible, and inspect one update. Do not treat it as a generally robust nonlinear solver |
| LOP proximal/DR/ADMM code fails in `vmap`, QR, Cholesky, or triangular solve | The unbatched `(x, parms)` functions, batch dimensions, constraint rank, or positive-definiteness assumptions are violated | Define single-sample functions, check their batched shapes, keep Jacobians correctly ranked, use a positive-definite metric/Hessian, and begin with `ProxBoxConstraint` on CPU |
| Fixed `JF`/`Hf` mode becomes stale | `JF_fixed` or `Hf_fixed` was enabled even though the quantity depends on the current state | Disable the fixed mode or call the documented prefactor only when the linear/quadratic assumptions really hold |
| MLP construction fails even though a single map works | `linear_map` is applied to every adjacent pair in `[insize] + hsizes + [outsize]` | Choose equal widths for square maps or use a rectangular-compatible map; validate the entire MLP, not only its first layer |
| A map property is not exact after training | Several classes express a soft parameterization or expose a regularization error, not a hard projection | Inspect `effective_W()` and the relevant `reg_error()`; state whether the model uses a parameterization, penalty, or true fixed property |
| A CUDA-specific test fails or allocates unexpectedly | GPU behavior is optional and not part of the required CPU route | Run the smoke on CPU. Treat CUDA and multi-GPU execution as unverified unless a separately provisioned device check passes; do not infer support from a CUDA import alone |
| A benchmark or example asks for downloads, large data, or long training | That path is outside the operator skill's safe verification boundary | Stop at API/shape/autograd validation and route data, benchmark, or training work to the appropriate skill; do not add network or destructive behavior to the smoke script |
