# Data and training troubleshooting

| Symptom | Likely cause | Recovery and validation |
|---|---|---|
| `Mismatched number of samples in dataset tensors` | `DictDataset` values disagree on `shape[0]`. | Print `{k: tuple(v.shape) for k, v in data.items()}`; align or explicitly remove the offending feature before construction. |
| Static construction fails while concatenating | A static feature is not rank 2, has a different row count, or is empty after splitting. | Check every value is `(N, D)`, inspect all split counts, and construct a tiny `StaticDataset` before wiring the model. |
| Sequence says data must be a dictionary/list of dictionaries | The input is neither a dict nor a list of dicts, or a dict's first axes differ. | Normalize all values to time-major `(T, D)` arrays and assert equal `T`. |
| Multi-sequence construction reports mismatched keys | One trajectory lacks a variable or has an extra variable. | Take the key intersection only intentionally; otherwise add the missing signal to every trajectory and validate `set(seq.keys())`. |
| `length of time series data must be greater than nsteps` | `nsteps` is equal to or longer than at least one trajectory. | Reduce `nsteps`, increase the split/trajectory length, or omit that split. The comparison is strict, not `>=`. |
| Sequence loader has zero items or an empty batch | Split alignment/context plus `nsteps` left fewer than two windows. | Print `len(dataset)`, `dataset.dims`, and split lengths; use a longer fixture or a smaller horizon before calling `DataLoader`. |
| Expected `X` but received `Xp`/`Xf` (or vice versa) | `SequenceDataset` changes raw names into past/future keys. | Inspect one `dataset[0]` and use the generated suffix contract. Do not hand-rename only one side. |
| Model output or metric key is missing `train_`/`nstep_train_` prefix | Loader was built with ordinary collation or the dataset name is wrong. | Always pass the owning dataset's `collate_fn`; assert `batch["name"]` before training. |
| `LitDataModule` exits during setup with a split-name assertion | Dataset names are not exactly `train` and `dev`. | Construct `DictDataset(..., name="train")`/`name="dev"`; do not rely on variable names to label a dataset. |
| Validation works but test loader fails with `None` | `val_dataloader` tolerates `dev=None`, but this source version's `test_dataloader` uses `self.dev_data.collate_fn`; base `Trainer.test` also iterates every split. | Provide named dev/test data when testing, or skip test and document that only train/validation was run. |
| Empty dev/test split after a percentage split | Thirds or explicit percentages are too small for the sample count or sequence horizon. | Assert sizes after splitting; reduce `nsteps`, change ratios, or intentionally omit the split. Never silently train on a held-out split of zero rows. |
| Held-out values influence normalized train data | `get_*_dataloaders(..., norm_type=...)` normalizes before splitting. | Split raw data first; fit `normalize_data` on train; pass the exact returned stats to dev/test; use the factories with `norm_type=None` if needed. |
| Reusing z-score stats appears to require `mean/std` keys | The public mapping historically calls fields `<key>_min`/`<key>_max` for every norm type. | Reuse the returned mapping unchanged. For z-score, `_min` contains mean and `_max` contains standard deviation. |
| Constant feature becomes zero or contains NaN/Inf | Zero denominator in min-max or standard deviation. | Confirm the feature is constant, accept the implementation's finite-zero behavior, or remove/redefine the feature and record the choice. |
| Graph collate has wrong edges or node batches | Samples were collated with default collation, feature keys differ, or edge indices were not local `(2, E)` tensors. | Call `GraphDataset.collate_fn`, validate `num_nodes`, and check the second graph's edge indices are offset by the first graph's node count. |
| Graph builder cannot find a feature or creates no links | `build_graphs` name is absent, radius is too small, or feature units are unsuitable. | Check `node_attr[feature]`, print edge counts, tune `connectivity_radius`, or pass precomputed graphs. Basic graph dataset construction uses a local CPU radius routine; optional graph packages should not be assumed. |
| `Trainer` raises a metric `KeyError` | `train_metric`/`dev_metric` does not match the Problem output for the batch name. | Run one forward pass, print output keys, then set metrics to existing keys. Keep objective/loss formulation in the symbolic route. |
| Base trainer cannot test an experiment with no dev set | `Trainer.test` loops over train/dev/test without guarding `None`. | Train with `dev_data=None` only if appropriate, but call `test` only after providing all loaders or write a separate bounded evaluation. |
| Best checkpoint is not found | `save_weights=False`, `weight_path` is unwritable, or `eval_metric` is never logged. | Set `save_weights=True`, use an explicit writable path, keep a non-empty dev loader, and monitor the metric emitted by validation. |
| Loading a Lightning checkpoint reports unexpected keys | Lightning stores a wrapper `state_dict` with `problem.` prefixes. | Use `load_state_dict_lightning(problem, checkpoint_path)` rather than `problem.load_state_dict(torch.load(...))` directly. |
| Early stopping occurs immediately or never | `patience`/`warmup` are inconsistent with epoch numbering, or the monitored dev metric is absent. | Use a small CPU run, inspect the monitored metric each epoch, and remember stopping is suppressed only during the configured warmup. |
| Custom Lightning hook raises signature `ValueError` | `LitProblem` compares hook signatures to its supported hook table. | Match signatures exactly, e.g. `on_train_epoch_end(self)` or `on_train_batch_start(self, batch, batch_idx)`. A custom training step is `(model, batch)`, not a Lightning hook signature. |
| Custom `validation_step` hook raises an attribute error | In this package snapshot the custom validation branch references `self.custom_hook` instead of `self.custom_hooks`. | Do not replace `validation_step` through `custom_hooks`; use a supported epoch/batch hook or a carefully tested subclass and record the version caveat. |
| Custom optimization behaves strangely | `automatic_optimization=False` changes Lightning's clipping/gradient handling, while a custom training step may own gradients. | Decide who calls `backward`/optimizer steps, return the expected scalar in automatic mode, and run a one-batch CPU check before scaling. |
| Logger unexpectedly creates files | `BasicLogger` creates `savedir` at construction and `log_artifacts` serializes objects. | Use an explicit temporary/project experiment directory; do not instantiate a file logger in a read-only or package directory. |
| MLflow logger cannot import | Tracking dependencies are optional. | Install the tracking extra only when needed and provide `args.location`, `args.exp`, and `args.run`; otherwise use `BasicLogger`/`LossLogger`. |
| GPU or distributed setup fails | CUDA, driver, memory, or multi-device backend is unavailable. | Fall back to `device="cpu"`/`accelerator="cpu"`. GPU and multi-GPU paths are optional and unverified here; do not treat their failure as a CPU data-contract failure. |
