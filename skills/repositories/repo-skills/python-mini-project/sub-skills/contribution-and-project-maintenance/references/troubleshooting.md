# Troubleshooting

Use this reference when a mini-project folder looks incomplete, unsafe, or inconsistent with the repo's contribution style.

## Common failures

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| Missing `README.md` | A new project was added without the template file, or a rename left the README behind | Create or restore `README.md` in the project folder. Use the template structure from `references/project-template.md`. |
| Folder name feels wrong | The folder uses a path separator, hidden prefix, trailing punctuation, or an unnecessary rename | Keep the name short and stable. Prefer underscores for new folders. Do not rename an existing project folder unless the task explicitly asks for it. |
| `requirements.txt` will not install cleanly | The file contains shell commands, mixed notes, the wrong filename, or malformed package lines | Keep one package per line in UTF-8 text. Only list runtime dependencies that belong to that folder. |
| Root `requirements.txt` looks broken | The repository root file is a legacy UTF-16LE aggregate, not a normal project-local lockfile | Open it with the correct encoding if you need to inspect it, but do not rewrite it as part of a project-local maintenance change. |
| `__pycache__` appears in the change | Generated bytecode or notebook checkpoints were committed | Remove the generated files from the PR. If a cleanup is needed, delete them directly rather than documenting them in the README. |
| A script is unsafe or destructive | The script shuts down the host, sends bulk mail, reaches into credentials, or mutates external systems | Do not run it during maintenance. Mark it as unsafe and route the task to the appropriate runtime-oriented sub-skill. |
| Badge or demo links are stale | README points to a removed image, a remote badge that no longer resolves, or a local asset that is not present | Prefer project-local relative paths. Remove the demo block if the asset is missing. Do not leave broken links in a starter README. |
| README casing varies | Historical folders use `readme.md`, `Readme.md`, or `README.Md` | Use `README.md` for new work. Keep old casing only when preserving an untouched historical folder. |

## Fast checks

- Verify the folder contains exactly the files the task asked for.
- Confirm README paths are relative to the project folder.
- Confirm the README describes only the project in that folder.
- Confirm any dependency file belongs to that folder only.
- Confirm no generated cache or notebook checkpoint files were added.

## When to stop and route elsewhere

If the task requires launching a GUI, serving a web app, calling an API, using credentials, downloading models, or exercising hardware-dependent behavior, stop the maintenance pass and hand the project to the matching sibling sub-skill instead of guessing.
