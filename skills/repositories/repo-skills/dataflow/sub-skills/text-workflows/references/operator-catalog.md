# Operator catalog

This is a practical selection guide, not a complete API dump. Prefer the smallest operator that matches your column shape and dependency budget.

## Core text

| Operator | Best for | Common keys / notes |
| --- | --- | --- |
| `PromptedGenerator` | General prompt-to-text generation | `input_key`, `output_key`, `system_prompt`, optional `json_schema` |
| `FormatStrPromptedGenerator` | Template-driven generation from several columns | Maps input columns through `input_keys`; good for structured prompts |
| `ChunkedPromptedGenerator` | Long file-backed text | `input_path_key`, `output_path_key`, chunked local file reads |
| `Text2QAGenerator` | Seed QA generation from text chunks | Produces `generated_prompt`, `generated_question`, `generated_answer` |
| `RetrievalGenerator` | LightRAG-backed answering | Requires a retrieval serving object, usually async |
| `KCenterGreedyFilter` | Representative sampling before generation | `input_key`, `num_samples`, embedding-serving dependent |
| `BenchDatasetEvaluatorQuestion` / `UnifiedBenchDatasetEvaluator` | Shape / benchmark validation | Use when you need a schema-aware check instead of generation |

## General text

| Operator family | Best for | Dependency style |
| --- | --- | --- |
| `WordNumberFilter`, `SentenceNumberFilter`, `CharNumberFilter` | Length and granularity checks | Pure CPU |
| `BlocklistFilter`, `LanguageFilter`, `NgramFilter`, `MinHashDeduplicateFilter`, `SimHashDeduplicateFilter` | Dedup and heuristic text filtering | Pure CPU or lightweight local libs |
| `RemoveEmojiRefiner`, `RemoveExtraSpacesRefiner`, `HtmlUrlRemoverRefiner`, `LowercaseRefiner` | Cleanup and normalization | Pure CPU |
| `PresidioFilter`, `LangkitFilter`, `LLMLanguageFilter`, `PerspectiveFilter` | Heavier quality / safety checks | May need local models or external services |

## Reasoning

| Operator | Best for | Common keys / notes |
| --- | --- | --- |
| `ReasoningQuestionFilter` | Filter solvable / well-formed questions | Usually `input_key=instruction` or a math problem column |
| `ReasoningQuestionGenerator` | Expand a seed question set | Adds `Synth_or_Input` and reuses the input question column |
| `ReasoningAnswerGenerator` | Generate CoT or final answers | Usually reads `instruction` and writes `generated_cot` |
| `ReasoningAnswerFormatterFilter` | Format check | Pure CPU; usually reads `generated_cot` |
| `ReasoningAnswerGroundTruthFilter` | Compare to gold answers | Reads `generated_cot` and `golden_answer` |
| `ReasoningAnswerNgramFilter` | Remove repetitive answers | Pure CPU heuristic |
| `ReasoningAnswerTokenLengthFilter` | Token-length ceiling | Uses a tokenizer, but no LLM call |
| `ReasoningAnswerModelJudgeFilter` | Model-based correctness judgment | Needs `llm_serving` and a judge prompt |
| `ReasoningQuestionDifficultySampleEvaluator` / `ReasoningQuestionCategorySampleEvaluator` | Difficulty / category tags | Model-backed scoring |
| `ReasoningPretrainFormatConvertGenerator` | Turn SFT-style reasoning into pretrain text | Useful when you need `text` output |

## Code

| --- | --- | --- |
| `CodeAutoGeneratedFilter` | Remove auto-generated code | Usually needs `lines` |
| `CodeLengthSampleFilter` | Remove oversized or malformed files | Usually needs `lines` and `language` |
| `CodeTextCompositionFilter` | Check text vs code composition | Usually needs `text` |
| `CodeEncodedDataFilter` | Detect encoded / binary-like content | Usually needs `text` |
| `CodeDocumentQualityFilter` | Heuristic document quality | Often needs `text` |
| `CodeFileTypeContentFilter` | File-type specific filtering | Usually needs `filetype`, `filename`, `line_count` |
| `CodeGenericScoreFilter` | Threshold a precomputed score | Use when a prior stage already produced a score |
| `CodeInstructionGenerator` | Build a code instruction from code | Model-backed synthesis |
| `CodeCodeToInstructionGenerator` | Turn code into instruction | Model-backed synthesis |
| `CodeInstructionToCodeGenerator` | Turn instruction into code | Model-backed synthesis |
| `CodeQualitySampleEvaluator` | Score instruction/code pairs | Model-backed judging |
| `CodeQualityScoreFilter` | Keep good code samples only | Often follows `CodeQualitySampleEvaluator` |
| `CodeSandboxSampleEvaluator` | Execute code in sandbox | Side-effecting; only use trusted fixtures |

## Text2SQL

| Operator | Best for | Common keys / notes |
| --- | --- | --- |
| `SQLExecutionFilter` | Keep only executable SQL | Pure DB execution; no LLM call |
| `SQLGenerator` | Generate SQL from schema | Needs database manager and LLM serving |
| `SQLVariationGenerator` | Create SQL variants | Good for augmentation |
| `Text2SQLQuestionGenerator` | Generate natural-language questions | Needs LLM, embeddings, and database schema |
| `Text2SQLPromptGenerator` | Build prompts with schema context | Reads `question`, `db_id`, optional `evidence` |
| `Text2SQLCorrespondenceFilter` | Check question/SQL alignment | Model-backed |
| `Text2SQLCoTGenerator` | Generate reasoning traces | Model-backed |
| `Text2SQLCoTVotingGenerator` | Aggregate candidate CoTs | Useful after multiple generations |
| `SQLComponentClassifier` | Assign SQL difficulty | Pure CPU heuristic |
| `SQLExecutionClassifier` | Judge execution difficulty | Model-backed plus database access |

| Operator | Best for | Notes |

| `PerplexityFilter`, `FineWebEduFilter`, `QuratingFilter`, `PairQualFilter`, `DebertaV3Filter` | Pretraining corpus selection | Usually local-model based |

## Selection tips

- Need a CPU-only pass? Start with heuristic filters and format checks.
- Need generation from a single text column? Start with `PromptedGenerator`.
- Need several input columns? Use `FormatStrPromptedGenerator`.
- Need document-backed QA? Use `KCenterGreedyFilter` first, then `Text2QAGenerator`.
- Need SQL? Verify the database and run `SQLExecutionFilter` before any synthesis.
- Need instruction tuning? Build or validate `instruction`, `input`, and `output` columns before synthesis or training.
