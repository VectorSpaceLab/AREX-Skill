# TaskBench evaluation reference

TaskBench evaluation compares prediction JSONL against `DATA_DIR/data.json` across task decomposition, tool invocation, dependency links, and parameter prediction. Validate the data and predictions first when the model output was generated by an uncontrolled endpoint.

## Required inputs

For a single model:

```text
DATA_DIR/
  tool_desc.json
  data.json
  PREDICTION_DIR/
    MODEL_NAME.json
```

Command shape:

```bash
python taskbench/evaluate.py \
  --data_dir DATA_DIR \
  --prediction_dir PREDICTION_DIR \
  --llm MODEL_NAME \
  --splits all \
  --n_tools all \
  --mode add \
  --dependency_type resource \
  -m all
```

`PREDICTION_DIR` is interpreted relative to `DATA_DIR`. If an agent has an absolute prediction directory, derive the path relative to `DATA_DIR` before calling native evaluation or the bundled batch wrapper.

## Metrics

Native `-m all` expands to these metrics when `--prompting cot`:

| Metric option | Purpose | Notes |
| --- | --- | --- |
| `f1` | Tool node classification F1 | Reports micro/macro F1 and per-tool details. |
| `ed` | Tool sequence edit distance | Based on normalized task node names. |
| `link` | Dependency edge binary F1 | Resource links are inferred from `<node-j>` references; temporal links come from `task_links`. |
| `argument` | Argument name and name-value F1 | Compares predicted argument names and values after basic normalization. |
| `rouge` | Task-step text overlap | Uses a metric loader; may require extra local metric packages/cache. |
| `bertscore` | Task-step semantic score | Uses `roberta-large` by default and may require local model/cache availability. |

For a fast local smoke test that avoids heavy text metrics, use repeated metric flags such as:

```bash
-m f1 -m link -m argument
```

If `--prompting` is not `cot`, native `all` skips Rouge and BERTScore.

## Split and tool-count grouping

`--splits all` expands to:

- `overall`
- `single`
- `chain`
- `dag`

`--n_tools all` expands to:

- `overall`
- `1` through `10`

`--mode add` evaluates all splits with `n_tools=overall`, plus all tool counts with `split=overall`. `--mode mul` evaluates every split/tool-count combination.

## Output naming

If `--save_dir` is omitted, native evaluation computes it by replacing `predictions` with `metrics` in `--prediction_dir`.

Examples:

| Prediction directory | Default metrics directory |
| --- | --- |
| `predictions` | `metrics` |
| `predictions_use_demos_2` | `metrics_use_demos_2` |
| `predictions_reformat_by_self` | `metrics_reformat_by_self` |

If `--alignment NAME` is provided, native evaluation appends `_alignment_NAME` to the save directory. Metrics and logs are written under `DATA_DIR/SAVE_DIR/` with names based on `MODEL_NAME`.

## Dependency-type impact

Resource evaluation:

- Requires tool descriptions with `input-type` and `output-type`.
- Converts predicted and label task names by replacing underscores with spaces.
- Infers links by scanning node arguments for `<node-j>` references.
- Derives argument types from file extensions or source tool output types.

Temporal evaluation:

- Requires tool/API descriptions with `parameters`.
- Reads `task_links` directly from labels and predictions.
- Expects node arguments to be objects with `name` and `value`.

Daily Life APIs must use `--dependency_type temporal`. A resource run is invalid even if the directory contains graph links.

## Prediction validation and recovery

Evaluate only after these checks pass:

1. `tool_desc.json` and `graph_desc.json` match the selected dependency type.
2. `data.json` uses normalized evaluator fields (`user_request`, `task_steps`, `task_nodes`, `task_links`) or has been converted in a temporary copy.
3. Every prediction JSONL line parses as JSON.
4. Every prediction has `result.task_steps` and `result.task_nodes`.
5. Temporal predictions also have `result.task_links`.
6. Predicted tool/API names are present in `tool_desc.json` after simple underscore/space normalization.

Use the bundled validator:

```bash
python SUB_SKILL_DIR/scripts/validate_taskbench_fixture.py \
  --tool-desc DATA_DIR/tool_desc.json \
  --graph-desc DATA_DIR/graph_desc.json \
  --data-jsonl DATA_DIR/data.json \
  --user-requests-jsonl DATA_DIR/user_requests.json \
  --predictions-jsonl DATA_DIR/PREDICTION_DIR/MODEL_NAME.json \
  --dependency-type auto \
  --strict
```

Malformed model output recovery:

- If malformed lines are produced during inference, rerun inference with `--reformat true`.
- If the same model should do the formatting, set `--reformat_by self`.
- If a stronger or more reliable formatter endpoint is available, set `--reformat_by FORMATTER_MODEL_NAME`.
- If only a few ids failed, keep existing valid prediction lines and regenerate missing ids; native inference resumes by reading ids already present in the model JSONL file.
- If a JSONL line is corrupt and prevents resume/evaluation, move the corrupt line aside, validate the remaining JSONL, and regenerate that sample id.

## Batch evaluation

Use the bundled shell wrapper for a prediction directory containing multiple model JSON files:

```bash
bash SUB_SKILL_DIR/scripts/batch_evaluate.sh \
  CHECKOUT_ROOT \
  DATA_DIR \
  PREDICTION_DIR \
  python
```

The wrapper:

- Refuses to run unless `CHECKOUT_ROOT/taskbench/evaluate.py` exists.
- Refuses to run unless `DATA_DIR` and `DATA_DIR/PREDICTION_DIR/*.json` exist.
- Detects `temporal` when the `DATA_DIR` basename contains `dailylifeapis`; otherwise uses `resource`.
- Makes no CUDA claim and does not start any model server.

## Known evaluator assumptions

- Missing predictions are silently ignored because evaluation intersects label ids with prediction ids. Check `all_samples` in the metric JSON to confirm coverage.
- JSON decoding errors in the prediction file abort evaluation. Validate first.
- Parse errors inside individual prediction results are logged and skipped, reducing support counts. Check `step_supports`, `node_supports`, `link_supports`, and `argument_supports`.
- Rouge and BERTScore can fail in offline environments if metric packages or model caches are absent. Use narrower metrics for local smoke checks.
