# Troubleshooting evaluation and logging

## No result pairs found

Symptoms:

- The evaluator reports no `*_hr.png` files, no `*_sr.png` files, or zero common pair stems.
- A directory contains only `*_sr_process.png`, `*_sample.png`, or `*_sample_process.png`.

Checks:

1. Point the evaluator at the concrete output directory containing images. Training validation writes into an epoch subdirectory such as `results/<epoch>/`; validation/inference writes directly under the configured result directory.
2. Confirm that final SR images end in `_sr.png`. The process grid `_sr_process.png` is a visualization of the denoising trajectory and should not be paired with HR for metrics.
3. Do not use unconditional `sample.py` outputs for PSNR/SSIM unless you separately provide matching HR images with the same stems.
4. Use `--recursive` only when result pairs are intentionally nested; otherwise a parent experiment directory may contain logs and checkpoints but no images at its top level.

## Filename mismatches

The original standalone evaluator sorts `*_hr.png` and `*_sr.png` lists and zips them. That can hide missing files or pair the wrong images when names differ. In this checkout, its pair assertion also constructs the SR stem from the HR filename, so it can fail even when valid pairs exist.

Prefer the bundled helper, which pairs by stem and reports:

- HR images missing a matching SR image.
- SR images missing a matching HR image.
- duplicate pair stems in recursive or split-directory evaluation.

If patching the original evaluator, compare the stem before `_hr` from the HR path with the stem before `_sr` from the SR path.

## Image shape or metric errors

- PSNR/SSIM require the SR and HR arrays to have identical height, width, and channel count after loading.
- The repository's intended output images are RGB PNGs. Convert non-RGB inputs deliberately before comparing runs.
- SSIM uses an 11×11 Gaussian window; images smaller than 11 pixels in height or width are invalid for this implementation.
- PSNR can be `inf` for identical images. This is valid, but it can make averages less informative on toy fixtures.
- Very low scores can come from comparing `*_inf.png` or `*_lr.png` against HR instead of final `*_sr.png`.

## TensorBoard issues

- The main scripts import `tensorboardX.SummaryWriter`. Install `tensorboardX` before using those entrypoints.
- The log directory is generated by the config parser under a timestamped experiment folder; inspect the actual run folder rather than the literal JSON path value.
- Train-time validation in `sr.py` logs PSNR to TensorBoard, but standalone `eval.py` and the bundled helper print metrics instead of writing TensorBoard events.

## W&B import, login, and table issues

- `-enable_wandb` imports `wandb`; install it before enabling W&B.
- Login or configure offline/disabled behavior before starting a run that enables W&B.
- `sr.py -p val` logs an evaluation table only when both `-enable_wandb` and `-log_eval` are present.
- `infer.py` logs an inference table only when both `-enable_wandb` and `-log_infer` are present.
- Checkpoint artifacts require both `-enable_wandb` and `-log_wandb_ckpt`, and they are logged only at checkpoint save steps.
- If table logging fails, verify the selected config has a `wandb.project` string and that W&B was initialized before rows are added.

## Interpreting surprising scores

- Use the same result resolution and dataset split when comparing to the README table.
- The repository does not shave borders or switch to Y-channel metrics, so numbers may differ from papers or benchmark scripts that use those conventions.
- Validation during training computes only PSNR; run result-pair evaluation afterward if SSIM is required.
