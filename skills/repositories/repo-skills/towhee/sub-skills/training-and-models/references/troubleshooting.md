# Troubleshooting training and model workflows

Use this table before installing optional packages, importing `towhee.trainer`, or running model/training code.

| Symptom | Likely cause | Safe response |
|---|---|---|
| Importing trainer modules fails with `ModuleNotFoundError: torch`, `torchvision`, or `torchmetrics`. | Towhee's training stack is optional and PyTorch-heavy. | Install the intended PyTorch/TorchVision/TorchMetrics variant explicitly in an isolated environment. Do not treat core Towhee import success as proof that training is ready. |
| Importing `towhee.trainer` unexpectedly runs package installation commands. | The package import path tries to install missing `torch`, `torchvision`, or `torchmetrics==0.7.0`; other utility imports may call Towhee's dependency installer for missing optional packages such as YAML or image/data libraries. | Prefer a fresh isolated environment; install optional dependencies deliberately before import. Use [../scripts/training_config_template.py](../scripts/training_config_template.py) without `--check-imports` when only a config template is needed. |
| `AssertionError` while importing with TorchMetrics installed. | The trainer package asserts `torchmetrics.__version__ == "0.7.0"` rather than accepting any version. | Use the version expected by this Towhee release or avoid importing trainer modules when training is out of scope. Check compatibility before upgrading TorchMetrics. |
| `ModuleNotFoundError: ruamel.yaml` or YAML loading/dumping fails. | `TrainingConfig.save_to_yaml(...)` and `load_from_yaml(...)` use `ruamel.yaml`; missing YAML support may trigger Towhee's auto-install helper. | Install `ruamel.yaml` explicitly before using Towhee YAML APIs, or use the bundled template script to generate static YAML without importing Towhee. |
| `AttributeError: There is no trainable model attr in this operator.` | `NNOperator.setup_trainer(...)` could not find `self.model` or `self._model` as a `torch.nn.Module`. | Initialize the operator with a trainable PyTorch module before calling `setup_trainer(...)` or `train(...)`. Inference-only operators need a training-specific model attribute. |
| `Trainer: training requires a train_dataset.` | No `train_dataset` or `train_dataloader` was supplied. | Pass a PyTorch dataset, a Towhee dataset wrapper, or an explicit dataloader. For nonstandard batches, subclass `Trainer` and override loss/metric methods. |
| Loss computation fails because labels or model outputs have unexpected shape/type. | Default `Trainer.compute_loss(...)` assumes each batch is `(inputs, labels)` and calls `loss(model(inputs), labels)`. | Adapt the dataset batch shape, set a compatible loss, or subclass `Trainer.compute_loss(...)` and usually `compute_metric(...)`. |
| Unknown optimizer/loss/scheduler name. | Strings are resolved as class names from PyTorch modules; dict configs require `name_`. | Use names such as `CrossEntropyLoss`, `Adam`, `AdamW`, or scheduler strings `linear`, `cosine`, `cosine_with_restarts`, `polynomial`, `constant`, `constant_with_warmup`. For PyTorch scheduler dicts, include `name_`, for example `name_: StepLR`. |
| GPU is used unexpectedly. | `device_str: null` auto-selects `cuda:0` when CUDA is available. | Set `device_str: cpu` for portable runs and examples. Set `cuda:N` only for a specific GPU. Use `cuda` only when DataParallel across visible GPUs is intended. |
| `cuda`/CUDA errors on a CPU host. | Config selected a CUDA device without a matching runtime. | Switch to `device_str: cpu`, install a CPU PyTorch wheel, or prepare the correct CUDA-enabled PyTorch environment before training. |
| Multi-GPU behavior is not what the user expected. | `device_str: cuda` wraps the model in `torch.nn.DataParallel` over visible GPUs. | Use host CUDA visibility controls before launch or specify `cuda:N` for a single device. Validate batch size and memory assumptions. |
| Training appears to download weights or stalls before model creation. | Examples and model code often use `pretrained=True`, Hub operators, or model-zoo defaults that can fetch checkpoints. | Use `pretrained=False` for smoke checks, pre-populate caches, or get explicit approval for network/downloads. Avoid large pretrained tests during routine validation. |
| Image dataset helper fails on imports or CSV columns. | The helper requires Pandas, PIL/Image support, TorchVision transforms, image files, and a CSV with `image_name` and `category`. | Install those optional dependencies only if image training is required. Validate the CSV schema and route general data handling to `data-utilities`. |
| Unsure whether to install `towhee.models`. | The task may only need Hub operators or pipeline-level inference. | Install `towhee.models` for direct Python model instantiation/fine-tuning. Use Hub operators for task-level pipeline workflows with operator revisions and preprocessing. |
| Core Towhee import fails with `pkg_resources` missing. | Some Towhee versions depend on setuptools' `pkg_resources`, which may be absent in very new setuptools environments. | Use a compatible setuptools version that provides `pkg_resources`, then re-run core import checks before trainer work. |

## Side-effect policy

Do not run full model-zoo tests, pretrained model downloads, CUDA training, Docker/Triton deployment, or Hub network workflows as routine checks. Ask for explicit approval and prepare the corresponding environment first.

For safe diagnosis, generate or inspect a CPU config template, import core Towhee separately from trainer modules, and only then move to optional training imports.
