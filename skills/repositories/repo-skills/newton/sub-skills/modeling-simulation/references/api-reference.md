# Core modeling API reference

Read this when writing or debugging public Newton model-building code. Signatures below were confirmed by installed-package inspection for Newton `1.6.0.dev0`; re-run the root environment check after a version change.

## Public import surface

```python
import warp as wp
import newton
```

Use public modules only. Symbols under `newton._src` are private and can change without deprecation.

## Key constructors and methods

- `newton.ModelBuilder(up_axis=newton.Axis.Z, gravity=None, sdf_texture_paired_samples=True)` creates the mutable builder.
- `ModelBuilder.add_body(*, xform=None, com=None, inertia=None, mass=0.0, label=None, lock_inertia=False, is_kinematic=False, custom_attributes=None) -> int` creates a stand-alone free body.
- `ModelBuilder.add_link(*, xform=None, com=None, inertia=None, mass=0.0, label=None, lock_inertia=False, is_kinematic=False, custom_attributes=None) -> int` creates a body link that should be connected by joints and `add_articulation()`.
- `ModelBuilder.add_articulation(joints, label=None, custom_attributes=None)` groups joint indices into one articulation.
- `ModelBuilder.replicate(builder, world_count, spacing=(0.0, 0.0, 0.0), *, xforms=None)` duplicates a template builder into multiple worlds.
- `ModelBuilder.finalize(device=None, *, requires_grad=False, skip_all_validations=False, skip_validation_worlds=False, skip_validation_joints=False, skip_validation_shapes=False, skip_validation_structure=False, skip_validation_joint_ordering=True) -> newton.Model` creates immutable simulation arrays.
- `newton.Model(device=None)` is usually created through `finalize()`, not directly.
- `model.state()` allocates a time-varying `State` matching the model.
- `model.control()` allocates a `Control` matching the model.
- `newton.CollisionPipeline(model, *, reduce_contacts=True, rigid_contact_max=None, broad_phase=None, narrow_phase=None, deterministic=False, contact_matching="disabled", contact_report=False, ...)` owns contact generation.
- `pipeline.contacts()` allocates a `Contacts` buffer.
- `newton.eval_fk(model, joint_q, joint_qd, state, mask=None, indices=None, body_flag_filter=newton.BodyFlags.ALL)` updates maximal-coordinate body pose/velocity arrays from generalized joint arrays.
- `newton.eval_ik(model, state, joint_q, joint_qd, mask=None, indices=None, body_flag_filter=newton.BodyFlags.ALL)` writes generalized joint arrays from body state.

## Shape and site methods

Common primitive shape methods share the same vocabulary:

```python
builder.add_shape_sphere(body, *, xform=None, radius=1.0, cfg=None, as_site=False, color=None, label=None, custom_attributes=None)
builder.add_shape_box(body, *, xform=None, hx=0.5, hy=0.5, hz=0.5, cfg=None, as_site=False, color=None, label=None, custom_attributes=None)
builder.add_shape_capsule(body, *, xform=None, radius=1.0, half_height=0.5, cfg=None, as_site=False, color=None, label=None, custom_attributes=None)
builder.add_shape_cylinder(body, *, xform=None, radius=1.0, half_height=0.5, barrel_radius=0.0, cfg=None, as_site=False, color=None, label=None, custom_attributes=None)
builder.add_shape_mesh(body, *, xform=None, mesh=None, scale=None, cfg=None, color=None, label=None, custom_attributes=None)
builder.add_ground_plane(*, height=0.0, cfg=None, color=(0.125, 0.125, 0.15), label=None)
```

Use `as_site=True` for non-colliding reference frames that sensors, viewers, or robot controllers need. Route detailed sensor behavior to `../sensors-visualization/SKILL.md`.

## Joint and target layout notes

`ModelBuilder.add_body()` creates a stand-alone body with free-joint generalized coordinates. `add_link()` creates a link that becomes meaningful after adding a joint and grouping it with `add_articulation()`.

For new code that writes position targets, set this once before building models:

```python
newton.use_coord_layout_targets = True
```

Then `Control.joint_target_q` uses the same coordinate layout as `State.joint_q`, which avoids legacy DOF-shaped target misalignment when a robot contains free, ball, or distance joints. Velocity targets and generalized efforts remain in DOF layout.

## State/control/contact arrays

- `State.body_q`: rigid body pose, shape `[body_count]` with transforms.
- `State.body_qd`: rigid body spatial velocity, shape `[body_count]`.
- `State.joint_q`: generalized joint coordinates.
- `State.joint_qd`: generalized joint velocities.
- `Control.joint_target_q`: joint position targets.
- `Control.joint_target_qd`: joint velocity targets.
- `Control.joint_act`: actuator feedforward inputs.
- `Control.joint_f`: generalized effort.
- `Contacts` buffers contain rigid and soft contact information generated by `CollisionPipeline` and consumed by solvers.

Allocate `State`, `Control`, and `Contacts` after any sensors or solver features that request extended attributes, otherwise recreate them so the extra arrays exist.

## Device handling

Newton arrays are Warp arrays. Use Warp device strings such as `"cpu"` or `"cuda:0"` at finalization or through `wp.set_device()`. A CPU smoke is a full substitute for basic API validation, but not for performance, RTX, or GPU-specific tasks.
