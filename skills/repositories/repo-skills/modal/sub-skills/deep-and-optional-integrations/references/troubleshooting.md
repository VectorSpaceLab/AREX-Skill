# Deep and Optional Integration Troubleshooting

Use this matrix after choosing the relevant workflow in the main sub-skill. It focuses on optional deep-learning integrations, not ordinary scikit-learn learner setup or non-dropout query strategy math.

| Symptom | Likely cause | Recovery |
|---|---|---|
| `import modAL.dropout` fails with missing `torch` or `skorch`. | MC dropout imports optional deep-learning dependencies. `skorch` is declared by the package, but PyTorch availability depends on the user's environment. | Install a compatible CPU or selected-backend PyTorch plus skorch in the user's runtime, then rerun a small import/helper check. Do not claim CUDA merely because CPU import works. |
| `from keras...` or `tensorflow.keras...` imports fail. | Keras/TensorFlow examples are optional and version-sensitive. They were not part of the minimum verified runtime. | Treat Keras as a separate optional dependency decision. Identify the installed Keras/TensorFlow wrapper API, avoid dataset downloads by default, and route classical learner mechanics to the learners sub-skill. |
| `DeepActiveLearner` construction raises `AttributeError: initialize`. | The estimator is not skorch-like; `DeepActiveLearner.__init__` calls `estimator.initialize()`. | Use a skorch `NeuralNetClassifier`/compatible wrapper or add an adapter exposing `initialize`, `fit`, `partial_fit`, `predict`/`score`, and for dropout `infer` plus `module_`. For plain scikit-learn estimators, use the classical learner sub-skill. |
| `teach(..., warm_start=True)` raises that `partial_fit` is missing or incompatible. | Deep warm-start teaching calls `estimator.partial_fit`. | Use a skorch estimator that supports `partial_fit`, pass any required fit kwargs, or use `warm_start=False` and pass the full dataset you want to fit from scratch. |
| User passes `only_new=True` to `DeepActiveLearner.teach`. | `only_new` is a classical `ActiveLearner` concept; deep teaching uses `warm_start`. Unknown kwargs may flow to the estimator and fail. | Replace with `warm_start=True` to continue training on the passed batch, or `warm_start=False` to reset and fit the passed dataset. Use `only_new=True` only with classical `ActiveLearner`/Keras-like fit behavior. |
| `RuntimeError: Error in model data type, only dict or tensors supported`. | `modAL.dropout.get_predictions` only accepts a `torch.Tensor` or a mapping of tensor values. | Convert arrays with `torch.as_tensor(...)`. For dict inputs, ensure every value is a tensor with the same first dimension. Keep tensors on the same device as the estimator. |
| `KeyError: The passed index ... is not a Dropout layer`. | `dropout_layer_indexes` contains an index into `list(model.modules())` that is not a dropout module. | Enumerate modules, choose only rows whose class name starts with `Dropout`, use `[]` to toggle all dropout layers, or run the bundled dropout inspection helper with `--list-layers`. |
| Index selection raises an out-of-range error. | The index is outside `list(model.modules())`. | Re-enumerate the exact initialized `module_`; wrapper/model changes can shift indexes. Prefer `[]` during initial debugging. |
| `AssertionError: num_predictions must be larger than zero` or `sample_per_forward_pass must be larger than zero`. | MC dropout requires positive cycle and split sizes. | Set `num_cycles`/`num_predictions >= 1` and `sample_per_forward_pass >= 1`. For memory issues, reduce `sample_per_forward_pass` but keep it positive. |
| MC dropout runs out of memory or is very slow. | Work scales with pool size, model size, `num_cycles`, and forward-pass split size. | Start with a tiny pool, small `num_cycles`, and low `sample_per_forward_pass`. Increase gradually after the user's CPU/GPU memory is observed. |
| Outputs from `infer` have unexpected dimensions or tuple structure. | `get_predictions` expects the adaptor result to be a tensor compatible with `softmax(-1)`. | Provide a `logits_adaptor(input_tensor, samples)` that selects or reshapes logits to `(batch, classes)`, such as `torch.flatten(logits, start_dim=1)` for extra dimensions. |
| Dropout layers remain in training mode after an exception. | A custom adaptor or model forward raised before the normal reset path. | Call `modAL.dropout.set_dropout_mode(learner.estimator.module_, indexes, train_mode=False)` in cleanup before continuing. |
| User expects GPU/CUDA acceleration. | CUDA was not selected or verified by this generated skill. | State the non-claim. Use `device="cpu"` for deterministic helper checks; only move estimator and tensors to CUDA after a separate runtime-specific CUDA smoke test. |
| Keras example tries to download MNIST or use a removed wrapper path. | The examples demonstrate historical patterns and often rely on dataset loaders/network/cache and legacy wrappers. | Use user-supplied data or an approved local dataset. Confirm wrapper import path for the installed Keras/TensorFlow version. Do not make Keras/TensorFlow a hidden dependency of a modAL workflow. |
