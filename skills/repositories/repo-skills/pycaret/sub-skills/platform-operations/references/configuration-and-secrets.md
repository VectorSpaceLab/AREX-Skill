# Configuration and secrets

The server reads settings from environment variables with the `PYCARET_` prefix
and from a `.env` file when present. `pycaret-server init --data-dir ./data`
creates a starter `.env` for single-process local use.

## Core `PYCARET_*` settings

| Setting | Default or shape | Operational notes |
|---|---|---|
| `PYCARET_APP_NAME` | `PyCaret Server` | Display/API metadata. |
| `PYCARET_ENVIRONMENT` | `dev` | Use `prod` for production-shaped deployments. |
| `PYCARET_DEBUG` | `false` | Enable only briefly; may increase log volume. |
| `PYCARET_DATABASE_URL` | `sqlite:///./pycaret.db` | SQLAlchemy URL. Use SQLite for local/single-process; Postgres for production-shaped deployments. |
| `PYCARET_JWT_SECRET` | weak dev fallback | Required strong secret in production. Losing or leaking it invalidates trust in auth tokens. |
| `PYCARET_JWT_ALGORITHM` | `HS256` | Keep default unless the auth implementation changes. |
| `PYCARET_ACCESS_TOKEN_TTL_MINUTES` | `60` | Access-token lifetime. |
| `PYCARET_REFRESH_TOKEN_TTL_DAYS` | `30` | Refresh-token lifetime. |
| `PYCARET_SECRETS_KEY` | unset by default | Fernet key for encrypted LLM keys, datasource passwords, and other stored secrets. Must be stable anywhere credentials are stored. |
| `PYCARET_ARTIFACT_DIR` | `./artifacts` | Local filesystem artifact root for local storage and API backup implementation. |
| `PYCARET_CORS_ORIGINS` | `['http://localhost:3020', 'http://127.0.0.1:3020']` | JSON-array string for allowed browser origins. Quote carefully in shell and Compose. |
| `PYCARET_ENABLE_DEPLOYMENTS` | `true` | In-house serving feature flag. |
| `PYCARET_ENABLE_WEBSOCKET` | `true` | Run event stream fan-out feature flag. |
| `PYCARET_RUNS_BACKEND` | `inprocess` | `inprocess` runs jobs in the API process; `redis` creates queued jobs for workers. |
| `PYCARET_REDIS_URL` | `redis://localhost:6379/0` | Required when `PYCARET_RUNS_BACKEND=redis`. |
| `PYCARET_WORKER_ID` | generated by worker | Use stable IDs for long-running worker hosts. |
| `PYCARET_WORKER_QUEUES` | `default` | Comma-separated queues this worker listens on. |
| `PYCARET_STORAGE_BACKEND` | `local` | `local`, `s3`, or `minio`. |
| `PYCARET_STORAGE_BUCKET` | unset | Required for `s3`/`minio`. |
| `PYCARET_STORAGE_ENDPOINT_URL` | unset | MinIO or S3-compatible endpoint URL. |
| `PYCARET_STORAGE_REGION` | `us-east-1` | S3 region. |
| `PYCARET_STORAGE_ACCESS_KEY` | unset | S3/MinIO credential; never print. |
| `PYCARET_STORAGE_SECRET_KEY` | unset | S3/MinIO credential; never print. |
| `PYCARET_NOTEBOOK_BACKEND` | `local` | `local` returns an unavailable placeholder; `docker` starts JupyterLab containers. |
| `PYCARET_NOTEBOOK_IMAGE` | Jupyter scipy-notebook default in docker backend | Override with a trusted image when Docker notebook mode is enabled. |
| `PYCARET_NOTEBOOK_DATA_DIR` | unset | Host/container data directory used by notebook manager. |
| `PYCARET_NOTEBOOK_NETWORK` | unset | Docker network for notebook containers. |
| `PYCARET_NOTEBOOK_IDLE_TIMEOUT_SECONDS` | `1800` | Notebook idle timeout. |
| `PYCARET_SMTP_HOST` | unset | Email alert/invite delivery is disabled when unset. |
| `PYCARET_SMTP_PORT` | `587` | SMTP port. |
| `PYCARET_SMTP_USE_TLS` | `true` | SMTP TLS toggle. |
| `PYCARET_SMTP_USERNAME` | unset | SMTP credential; never print. |
| `PYCARET_SMTP_PASSWORD` | unset | SMTP credential; never print. |
| `PYCARET_SMTP_FROM` | unset | Sender address. |

Other useful environment variables seen in platform surfaces:

| Setting | Purpose |
|---|---|
| `PYCARET_SAMPLE_DATASETS_DIR` | Optional absolute path to a sample dataset index for the sample-data API. |
| `PYCARET_API_PORT` | Host-port override used by compact Docker Compose. |
| `PYCARET_WEB_PORT` | Host-port override used by compact Docker Compose. |
| `PYCARET_PG_USER`, `PYCARET_PG_PASSWORD`, `PYCARET_PG_DB` | Production-shaped Compose variables used to build the Postgres URL. |
| `PYCARET_S3_BUCKET`, `PYCARET_S3_ACCESS_KEY`, `PYCARET_S3_SECRET_KEY` | Production-shaped Compose variables for MinIO bootstrap and storage credentials. |

## Fernet encryption key

`PYCARET_SECRETS_KEY` must be a Fernet key: a base64-url-safe encoded 32-byte
key. Generate one with:

```bash
python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

Rules:

- Set a stable key before storing real credentials.
- In a compact API container, leaving `PYCARET_SECRETS_KEY` blank is acceptable
  only because the entrypoint generates a key once and persists it under the
  data volume.
- In multi-replica, blue/green, worker, or external secret-store deployments,
  inject the same key into every API and worker process.
- If the key changes, encrypted rows may raise decrypt errors. Re-enter or
  re-encrypt stored secrets; do not guess the old key.
- Never log, paste, or print the key. Use the bundled
  `scripts/check_container_secret_key.sh` helper for presence and format checks.

Container key check examples:

```bash
bash scripts/check_container_secret_key.sh --data-dir ./data
bash scripts/check_container_secret_key.sh --data-dir ./data --create
```

`--create` is the only mode that mutates the target directory.

## JWT secret

Set `PYCARET_JWT_SECRET` to 48+ random bytes for production. Example:

```bash
export PYCARET_JWT_SECRET="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
```

Rotating the JWT secret invalidates existing tokens. Plan a maintenance window
or temporarily shorten refresh-token lifetimes before rotation.

## Database backend

Local SQLite:

```bash
export PYCARET_DATABASE_URL='sqlite:///./data/pycaret.db'
pycaret-server migrate
pycaret-server serve --port 8020
```

Postgres:

```bash
pip install 'pycaret-server[postgres]'
export PYCARET_DATABASE_URL='postgresql+psycopg://user:password@postgres:5432/pycaret'
pycaret-server migrate
pycaret-server serve --host 0.0.0.0 --port 8020
```

Production startup expects explicit migrations for non-SQLite databases. Do not
rely on dev auto-migration in a production Postgres deploy.

## Storage backend

Local filesystem:

```bash
export PYCARET_STORAGE_BACKEND=local
export PYCARET_ARTIFACT_DIR=./data/artifacts
```

S3 or MinIO:

```bash
pip install 'pycaret-server[s3]'
export PYCARET_STORAGE_BACKEND=s3        # or minio
export PYCARET_STORAGE_BUCKET=pycaret-artifacts
export PYCARET_STORAGE_REGION=us-east-1
export PYCARET_STORAGE_ENDPOINT_URL=http://minio:9000  # MinIO/S3-compatible only
export PYCARET_STORAGE_ACCESS_KEY='...'
export PYCARET_STORAGE_SECRET_KEY='...'
```

The S3 driver refuses to start without `PYCARET_STORAGE_BUCKET`, and it requires
`boto3` from the `s3` extra. Database rows store artifact URIs such as `file://`
or `s3://bucket/key`; application code should treat those as opaque.

## Run backend, workers, and Redis

Single process:

```bash
export PYCARET_RUNS_BACKEND=inprocess
```

Distributed workers:

```bash
export PYCARET_RUNS_BACKEND=redis
export PYCARET_REDIS_URL='redis://redis:6379/0'
pycaret-server worker --queues default,cpu-heavy --worker-id worker-1
```

Use the same DB, Redis, storage, and Fernet settings for API and workers.

## CORS

For browser access outside localhost, set a JSON-array string:

```bash
export PYCARET_CORS_ORIGINS='["https://pycaret.example.com"]'
```

If the UI loads but API calls fail with browser CORS errors, compare the exact
browser origin with `PYCARET_CORS_ORIGINS` and the nginx/proxy host.

## Notebook backend

`PYCARET_NOTEBOOK_BACKEND=local` is a safe placeholder: notebooks can be listed
and created, but opening a session returns a backend-unavailable tile.

Docker mode spawns JupyterLab containers and requires a working Docker daemon:

```bash
export PYCARET_NOTEBOOK_BACKEND=docker
export PYCARET_NOTEBOOK_IMAGE=quay.io/jupyter/scipy-notebook:latest
export PYCARET_NOTEBOOK_NETWORK=pycaret_default
pycaret-server serve --port 8020
```

Use Docker mode only where the API process can safely reach the host Docker CLI
and the notebook containers have controlled network/storage access.
