# Training And Evaluation Troubleshooting

Use this table as a stop-and-recover guide. A recovery is safe only when it
changes one known cause, preserves the failed command/log/config, and stays
within the approved compute budget. A workaround that merely hides an error is
not a recovery.

| Symptom | Likely cause | Recovery | Stop condition |
|---|---|---|---|
| `metric bbox is not supported` or `KeyError: metric bbox is not supported` | A generic 3D detection metric was used for a vector-map dataset. The MapTR dataset evaluator allows `chamfer` and `iou`, while the MapTR launcher selects `chamfer`. | Do not launch again with `bbox`. Rebuild the evaluation command with `tools/dist_test_map.sh` semantics or the bundled validator, which appends exactly `--eval chamfer`. Preserve the failed command as evidence. | The requested task truly requires bbox, or the dataset/config is not a MapTR map dataset. Route that request to the owner of the dataset/metric contract instead of guessing a conversion. |
| `--nproc_per_node=8` on a host with one visible GPU, NCCL duplicate-device errors, or workers waiting forever | Requested process count exceeds `CUDA_VISIBLE_DEVICES` or scheduler allocation; physical host count was mistaken for visible allocation. | Stop all launchers. Confirm the process's visible device count and allocation. Construct `--gpus 1` for one visible GPU, or move to a proven eight-GPU allocation. Use a new port after stale workers are terminated. | A multi-GPU claim is required but the allocation cannot provide the requested GPUs. Do not oversubscribe or claim distributed performance. |
| Resume loads but loss/model shape errors appear | Checkpoint and config disagree on model type, map class order/count, fixed points, BEV dimensions, plugin variant, data pipeline, or optimizer/FP16 state. | Locate the config dumped beside the checkpoint. Compare it with the requested config using `print_config`; reconcile all model/data/runner fields before resuming. If there is no compatible config, start a new uniquely named run without `--resume-from` and label it as a restart. | Any unresolved architecture/class/data mismatch, or a checkpoint whose provenance is unknown. Do not force-load by ignoring missing/unexpected keys. |
| `--resume-from` appears ignored | The training entry point only sets `cfg.resume_from` when the supplied path is an existing regular file. | Check spelling, permissions, and file type before constructing the command. Use an absolute or project-relative path that exists, then include the explicit `--resume-from`. Confirm the startup log indicates resume. | The file is absent, unreadable, partial, or its expected run state cannot be established. |
| `FileNotFoundError` for `nuscenes_infos_temporal_*.pkl`, map JSON, camera image, or pretrained backbone | Dataset conversion/assets or configured relative root are missing; the process was launched from an unexpected directory. | Stop before training. Check the config's `data_root` and each referenced annotation/asset. Prepare data through the data-preparation skill and rerun only its documented checks. Launch from the project root or use paths consistent with the config. | Dataset provenance, split, or map annotation version is unknown. Do not fabricate empty annotations or treat parser success as data readiness. |
| `ModuleNotFoundError` for `projects.mmdet3d_plugin`, `mmdet3d`, or custom modules | Project root is not on `PYTHONPATH`, plugin is disabled/mispointed, or legacy package versions are not the documented set. | Run the zero-cost help/config checks from the project root. Confirm `plugin=True`, plugin path, and version compatibility. The distributed wrapper adds the project root to `PYTHONPATH`; the validator does the same on execute. Repair the environment only under an approved environment workflow. | Any private path workaround, unproven package substitution, or unresolved legacy-version conflict. Do not edit the generated skill to bless it. |
| Import/build error for GeometryKernelAttention, deformable attention, or another CUDA extension | Required custom op was not built for the active Python/PyTorch/CUDA ABI, or the host toolchain differs from the documented legacy target. | Stop. Probe the import/build status using the environment-preparation workflow. Rebuild only in an isolated, approved environment with matching versions; do not infer readiness from `torch.cuda.is_available()`. | No matching legacy compiler/runtime, build failure, or host CUDA is merely visible but unproven. Carry the backend block forward; do not claim native execution. |
| `CUDA out of memory` at model construction or first batch | MapTR's large BEV/query setup, image resolution, worker/prefetch behavior, FP16 mode, or process count exceeds memory. | Preserve the log and exact config. First verify process count is correct. Then make one approved conservative change such as reducing loader workers or configured batch/samples per GPU, and record it with `--cfg-options`. A lower-resolution/model config is an architecture change and must be routed to model configuration. | OOM persists, reduction changes the requested experiment materially, or no memory budget is known. Stop rather than repeatedly retrying. |
| FP16 overflow, NaN loss, invalid custom-op dtype, or unstable gradients | Configured `fp16`/loss scale interacts with legacy attention/custom kernels; numerical behavior differs by backend. | Preserve the first failing run. Confirm the merged config's `fp16` and optimizer hook. Do not silently replace AMP or change `loss_scale`; decide explicitly whether a separate FP32/alternate config experiment is acceptable and record the comparability impact. | No approved numerical-change plan, repeated NaNs, or unsupported custom op. Do not report a partial run as a result. |
| `Address already in use`, ranks hang at initialization, or stale workers remain | Port collision or a previous distributed process is still alive. | Terminate only the owned stale processes according to the scheduler/process policy. Choose a free explicit `--port` and reconstruct the dry-run. Ensure every rank uses the same port and visible-device allocation. | Ownership of the stale process is unclear or a scheduler controls the port. Ask the environment owner; do not kill unrelated work. |
| `tools/test.py` asserts in the non-distributed branch | This revision leaves the `launcher == none` inference branch disabled. | Use `tools/dist_test_map.sh` semantics with `--gpus 1` for a one-GPU evaluation. The command remains distributed from the framework's point of view. | A user requires a single-process test without accepting the pinned script behavior. Route to a code-maintenance decision; do not remove the assertion in a runtime run. |
| `--eval` and `--format-only` conflict | The test parser rejects evaluation and format-only together. | Choose one operation. Use `--eval chamfer` for metrics, or `--format-only` for formatter output without evaluation. The MapTR wrapper's default is evaluation. | Both artifacts are required but no separate-output plan exists. Run separate approved commands only if budget and provenance allow. |
| `--out` is rejected, asserts, or no pickle appears | The parser accepts the option, but the checked-in distributed branch reaches an assertion instead of dumping result outputs. | Do not promise `--out`. Use the evaluator's formatted `nuscmap_results.json` under its result prefix, and route visual artifacts to visualization. | A pickle is a hard requirement and no maintained output path is available. Report the implementation limitation. |
| `--show`/`--show-dir` produces no expected distributed visual output | The distributed path calls `custom_multi_gpu_test` without forwarding those flags in this revision. | Remove the expectation from the evaluation command and route visualization to `visualization-benchmarking`. Keep metric evaluation separate from rendering. | Qualitative output is part of acceptance and the visualization route is unavailable. Do not claim it was produced. |
| Training overwrites an existing run or checkpoint | Reused/default work directory, often from omitted `--work-dir`. | Stop before launch. Use a new unique work directory or obtain explicit permission for an intentional resume/update. Preserve the command and directory listing. | Ownership or overwrite permission is unknown. |
| Evaluation writes result JSON but then fails reading ground truth | `map_ann_file` is absent, wrong, or not writable; formatting attempts to create it from dataset annotations. | Check the configured map annotation path, permissions, and dataset split. Prepare the required map annotations through data preparation. Rerun only after the file contract is proven. | Ground-truth map version or split is unknown, or automatic generation would mutate unapproved data. |
| Results differ across reruns despite same seed | Different GPU/process count, cuDNN/CUDA/library versions, data order, custom-op behavior, or nondeterministic kernels. | Record visible GPUs, process count, seed, deterministic flag, merged config, package versions, and checkpoint. Compare only runs with matched provenance. | Bitwise reproducibility is required but the backend does not provide a verified deterministic guarantee. Report the limitation. |
| Command parser rejects a list/tuple override | mmcv `DictAction` received an unquoted value with spaces/brackets or malformed `key=value`. | Quote the whole value, for example `--cfg-options 'some.key=[a,b]'`, then rerun only the parser/config check. Confirm the printed merged config. | The intended override cannot be represented unambiguously; do not guess its syntax. |

## Escalation Record

When stopping, record:

1. intent, config, checkpoint, dataset split, and exact command;
2. visible/allocated GPU count, chosen process count, port, and output paths;
3. the first error and the last relevant log lines;
4. whether parser/config checks passed, and whether plugin/custom-op/data checks
   were actually run;
5. one proposed next probe and the condition under which it must not run.

This record distinguishes a documented procedure from a verified native result.
