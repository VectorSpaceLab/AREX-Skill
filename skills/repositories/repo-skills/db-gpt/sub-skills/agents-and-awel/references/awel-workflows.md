# AWEL workflow reference

AWEL (Agentic Workflow Expression Language) is DB-GPT's graph API for composing
operators, triggers, resources, variables, and local or service-managed execution.
The graph is ordinary Python construction until it is mounted/registered; defining a
DAG does not start a server or execute a model.

## Build a graph

The stable public imports are:

```python
from dbgpt.core.awel import (
    DAG,
    HttpTrigger,
    InputOperator,
    JoinOperator,
    MapOperator,
    ReduceStreamOperator,
    SimpleInputSource,
)
```

`DAG(dag_id, resource_group=None, tags=None, description=None,
default_dag_variables=None)` stores the graph and its caller-supplied ID. Build nodes
inside a DAG context so the current DAG is discovered automatically:

```python
with DAG("local-pipeline", description="A local fixture") as dag:
    source = InputOperator(SimpleInputSource("hello"), task_name="source")
    upper = MapOperator(lambda value: value.upper(), task_name="upper")
    source >> upper

assert len(dag.root_nodes) == 1
assert len(dag.leaf_nodes) == 1
result = await upper.call()
```

`DAGNode` and `BaseOperator` accept `task_id`/`node_id`, `task_name`, `dag`,
`system_app`, `executor`, and `check_serializable` (operator constructors also accept
`runner` and `variables_provider`). IDs generated by a DAG are UUID strings. Use
explicit stable IDs/names for serialized or externally referenced graphs. Node names
must be unique within the DAG; duplicate names raise `ValueError`. `>>` connects
upstream to downstream, `<<` is the inverse, and both can receive a sequence.

The graph properties are computed from connected nodes:

- `root_nodes` have no upstream nodes;
- `leaf_nodes` have no downstream nodes;
- `trigger_nodes` are `TriggerOperator` nodes (and therefore include `HttpTrigger`).

A node created outside `with DAG(...)` can be attached with `dag=dag`, but relying on
implicit global context makes composition and tests harder to inspect. Avoid sharing a
node between unrelated DAGs.

## Operators and task data

`MapOperator(map_function=None, **kwargs)` applies a sync or async callable to one
input. Its default `_do_run` expects one parent; an explicit `call_data` can provide
input at the end operator. `InputOperator(input_source, **kwargs)` is useful for
fixtures; `SimpleInputSource(data, streaming=None)` supplies a value or stream.

`JoinOperator(combine_function, can_skip_in_branch=True, **kwargs)` accepts multiple
parent outputs and calls the combine function with them in input order. Set
`can_skip_in_branch=False` when a shared join must still run if one branch is skipped.
`BranchOperator` selects downstream nodes using callable predicates and node names;
branch target values are strings or already-created operators with a node name.

`ReduceStreamOperator(reduce_function=None, **kwargs)` requires one stream parent and
reduces it to a non-stream value. Stream helpers are:

- `StreamifyAbsOperator` -> convert a value into an async iterator;
- `TransformStreamAbsOperator` -> transform an async iterator;
- `UnstreamifyAbsOperator` -> consume a stream into a value.

The task layer distinguishes `EMPTY_DATA`, `SKIP_DATA`, and ordinary values. A
`TaskOutput` can be non-stream or stream. `SimpleTaskOutput.map()` invokes a sync or
async mapper on its value; `SimpleStreamTaskOutput.map()` maps each yielded item and
`reduce()` consumes the stream. An empty stream raises when reduced. Do not pass a
stream into `MapOperator` when a single value is required, or a non-stream value into
`ReduceStreamOperator`.

The local API is:

```python
value = await leaf.call(call_data, dag_ctx=None, dag_variables=None)
stream = await leaf.call_stream(call_data, dag_ctx=None, dag_variables=None)
```

`call()` returns the leaf output. `call_stream()` returns an async iterator and wraps a
non-stream leaf output as a one-item stream. `_blocking_call()` and
`_blocking_call_stream()` are debug conveniences; do not call them from an already
running event loop. `DefaultWorkflowRunner.execute_workflow(node, call_data=None,
streaming_call=False, exist_dag_ctx=None, dag_variables=None)` recursively executes
upstream nodes, creates task contexts, records `TaskState`, and runs lifecycle hooks.

## DAG context, variables, and lifecycle

`DAGContext` stores node outputs, shared data, event-loop task identity, streaming
state, node-name-to-ID mapping, and optional `DAGVariables`. Operators can use
`current_dag_context` while running. `save_to_share_data()` rejects overwrites unless
`overwrite=True`; task-scoped helpers use the task name as part of the key.

The runner saves a DAG context while executing and calls DAG/node cleanup after a
non-streaming top-level run. For streaming HTTP responses, cleanup is attached to the
response background task after iteration. Implement `before_dag_run()` and
`after_dag_end(event_loop_task_id)` as async, idempotent hooks when a custom operator
needs setup/cleanup. Keep side effects out of graph-construction code.

Flow variables can be supplied as `DAGVariables` or through serialized flow metadata.
A flow variable placeholder has the form `${key:name@scope}` (the exact key/scope must
match the configured variables provider). Flow-private variables receive the flow DAG
ID as a default scope key when built by `FlowFactory`. Never print secret variable
values in topology diagnostics.

## HTTP triggers

`HttpTrigger` has this live constructor shape:

```text
HttpTrigger(
    endpoint: str,
    methods: str | list[str] | None = "GET",
    request_body: type | None = None,
    http_trigger_body: type[BaseHttpBody] | None = None,
    streaming_response: bool = False,
    streaming_predict_func: callable | None = None,
    http_response_body: type[BaseHttpBody] | None = None,
    response_model: type | None = None,
    response_headers: dict[str, str] | None = None,
    response_media_type: str | None = None,
    status_code: int | None = 200,
    router_tags: list[str | Enum] | None = None,
    register_to_app: bool = False,
    **kwargs,
)
```

Behavior that matters when designing a route:

1. A leading slash is added to `endpoint` if absent. `{dag_id}` is replaced by the
   attached DAG's ID; resolving it without a DAG raises `AWELHttpError`.
2. `methods` defaults to `GET` and can be a string or list. For GET/DELETE, a pydantic
   `request_body` class is represented as keyword-only query parameters. A dict body
   is rejected for query methods, and a string body is rejected for query methods.
3. For POST/PUT-style methods, a pydantic `BaseModel` body is passed to the DAG after
   FastAPI validation. A dict, string, or Starlette `Request` is also supported by the
   route builder where its type is valid.
4. `http_trigger_body` can supply a `BaseHttpBody` class. Its `get_body_class()` sets
   the request type and its `streaming_predict_func()` can select streaming from the
   body. `http_response_body` can supply the response model. For common LLM routes,
   `CommonLLMHttpRequestBody` has required `model` and `messages` plus `stream`,
   temperature, token, conversation, chat, incremental, visibility, and extra fields;
   it is provider/application-facing and is not a local no-model fixture.
5. `mount_to_router(router, global_prefix=None)` registers a route through
   `router.api_route()` and returns `HttpTriggerMetadata(path, methods, trigger_mode)`.
   `mount_to_app(app, global_prefix=None)` uses DB-GPT's priority router and is the
   application integration path. A plain FastAPI app may not implement the extra
   priority argument; use `mount_to_router` for portable registration inspection.
6. `trigger()` is intentionally unsupported on `HttpTrigger`. HTTP dispatch calls the
   DAG's leaf. Exactly one leaf is required; `_trigger_dag` raises if there are zero or
   multiple leaves.
7. Non-streaming dispatch awaits `leaf.call(call_data=body)`. Streaming dispatch uses
   `leaf.call_stream()`, normally returns `text/event-stream`, and performs DAG cleanup
   after the response stream completes.

The default DB-GPT application prefixes AWEL trigger paths with
`/api/v1/awel/trigger`. That prefix belongs to the host application, not to the
`HttpTrigger.endpoint` itself. A portable topology check can use a plain `APIRouter`:

```python
from fastapi import APIRouter

router = APIRouter()
meta = trigger.mount_to_router(router, global_prefix="/api/v1/awel/trigger")
assert meta.path.endswith("/api/v1/awel/trigger/...")
```

Do not start Uvicorn merely to validate a pydantic body or route topology. If a
standalone development server is genuinely wanted, `setup_dev_environment([dag],
host="127.0.0.1", port=5555, ...)` registers triggers and blocks when HTTP triggers
are present; it may also visualize graphs with Graphviz. It is not a production
service launcher and should not be used in a unit test.

## Flow UI serialization and deployment

The serialized flow API lives in `dbgpt.core.awel.flow.flow_factory`:

```python
from dbgpt.core.awel.flow.flow_factory import FlowData, FlowFactory, FlowPanel
```

`FlowPanel` contains a label/name, `FlowData`, state, version (default `0.1.1`),
variables, ownership metadata, and optional DAG metadata. `FlowData` contains
`FlowNodeData` and `FlowEdgeData`; each edge carries `source`, `target`,
`source_order`, `target_order`, and an ID. UI handles can fill missing order values.
`FlowFactory.build(flow_panel)` validates node types, topologically orders the graph,
constructs registered resources before dependent resources, creates registered
operators, connects edges, and returns a `DAG`.

Important validation boundaries:

- duplicate node keys, missing source/target keys, cycles, missing metadata, or an
  unknown registered type are construction errors;
- operator-to-resource edges are rejected; resource-to-operator and resource-to-
  resource edges must target a parameter whose category is `resource`;
- operator-to-operator edge order controls input/output position and optional output
  mappers;
- registered metadata is used instead of blindly trusting arbitrary UI metadata;
- `pre_load_requirements()` imports registered metadata classes and may use compatibility
  mappings for renamed classes;
- serialized operators are built with the flow node key as `task_name`, so node keys
  become runtime identity and should be stable.

`BaseOperator.__getstate__()` removes runner, executor, and system-app references for
pickling; unpickling restores current process defaults. A callable can still fail
serialization checks when `check_serializable=True`. Registered operator/resource
classes and simple typed parameters are safer for deployment than closures, open file
handles, event-loop objects, or client instances. Validate serialization before
publishing a flow and provide the serving process with the matching registered class
set.

## Agent operators in AWEL

AWEL agent resources are optional model-backed composition. The public classes include
`AWELAgent`, `AWELAgentConfig`, `AgentPrompt`, `AWELAgentResource`,
`AWELAgentKnowledgeResource`, `AWELAgentOperator`, and `AgentDummyTrigger` under
`dbgpt.agent.core.plan.awel`. An `AWELAgent` describes an agent profile, optional role,
LLM config/prompt, and resource declarations; `AWELAgentOperator` turns an
`AgentGenerateContext` into an agent response. Use these only after the model/provider
route has established a real LLM client and resource boundary. A DAG topology check
must not claim that an agent operator executed just because it imported successfully.
