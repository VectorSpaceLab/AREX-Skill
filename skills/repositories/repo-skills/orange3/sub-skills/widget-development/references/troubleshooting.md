# Widget Development Troubleshooting

Use this table before changing widget logic. Many Orange widget failures come from discovery metadata, stale settings, Qt platform setup, signal wiring, or workflow-load state rather than the algorithm inside the widget.

| Symptom | Likely cause | Fix | Check |
| --- | --- | --- | --- |
| Widget does not appear in Canvas/catalog | Entry point not installed, module import fails, class lacks `name`, category metadata is wrong, or registry categories were not normalized before catalog export | Import the module directly; verify the package entry point; ensure the final widget class has a non-empty `name`; run catalog discovery with normalized `category.widgets` | `python scripts/create_widget_catalog.py --list-categories --no-icons --no-help` |
| Discovery finds categories but zero widgets in custom code | Inspecting `category.widgets` before applying Orange's registry fixup | After `discovery.run(...)`, assign `cat.widgets = widgets` for values in `registry._categories_dict` before iterating widgets | Catalog script reports non-zero widgets for core Orange |
| Widget import crashes during discovery | Optional GUI, WebEngine, SQL, or model dependency imported at module import time | Move optional imports into methods, guard missing optional packages, or show a widget error after construction instead of failing import | `python -c 'import your_widget_module'` in the target env |
| Missing or wrong I/O in Canvas | Old-style `inputs`/`outputs` conflict with new-style descriptors, handler decorator missing, multiple same-type signals lack `default=True`, or `explicit=True` hides auto-connection | Use `class Inputs`/`class Outputs`; decorate exactly one handler per input; set `default=True` where needed; reserve `explicit=True` for supplementary links | `OWWidget.get_widget_description()` or `WidgetPreview` signal errors |
| Input handler receives unexpected `(value, id)` or index args | Confused `Input(..., multiple=True)` with `MultiInput` | Plain multiple input handlers receive `(value, id)`; `MultiInput` handlers receive `(index, value)` plus separate insert/remove handlers | Unit test with `send_signal(..., value, id)` or `MultiInput` insert/remove cases |
| Stored settings crash on startup | Setting type or name changed without migration; default value is no longer compatible; a `Variable` was stored in a plain `Setting` | Bump `settings_version`; implement `migrate_settings`; rename incompatible settings; store domain-dependent variables in `ContextSetting` | `create_widget(Widget, stored_settings=old_settings)` |
| Context setting restores stale variables | `closeContext()`/`openContext()` order is wrong; context match accepts variables that no longer exist; no `migrate_context` for changed context data | Close old context before replacing data; initialize fresh defaults; open context with the new domain; filter invalid variables; raise `IncompatibleContext` for unusable old contexts | Test two different domains with packed settings |
| GUI control does not update attribute | Wrong `master` or attribute string, raw Qt control used without binding, assignment bypasses the bound control, or callback mutates the controlled value recursively | Use `gui.*` wrappers with `self` and the exact setting name; access controls through `self.controls.<name>`; keep callbacks side-effect-safe | After a simulated user action, assert both `self.<name>` and control value |
| Callback fires too often or freezes UI | `keyboardTracking=True` on expensive `spin`; slider callback recomputes on every drag tick; auto-apply sends outputs repeatedly | Set `keyboardTracking=False`; use `callback_finished`; use `gui.auto_apply` / deferred commit; coalesce recomputation in `handleNewSignals()` | Test rapid control changes and output count |
| Qt fails with platform plugin errors | Headless environment lacks a display, or Qt platform plugin cannot initialize | Set `QT_QPA_PLATFORM=offscreen` for tests/previews/catalogs; install the PyQt/Qt package group used by Orange; avoid launching interactive GUI in CI | `QT_QPA_PLATFORM=offscreen orange-canvas --help` |
| WebEngine or catalog help lookup fails | WebEngine missing, or WebEngine cannot initialize in a sandboxed/headless/root-run process | Run catalog with `--no-help`, or install/enable PyQt WebEngine in the same environment; if a trusted non-interactive container reports `Running as root without --no-sandbox`, retry with `QTWEBENGINE_DISABLE_SANDBOX=1`; do not make help URLs a strict gate for widget discovery | `QT_QPA_PLATFORM=offscreen python scripts/create_widget_catalog.py --output tmp --no-icons --no-help` |
| `WidgetPreview` exits the Python process | `WidgetPreview.run()` calls `sys.exit` unless `no_exit=True` | For programmatic/debug checks, use `no_exit=True`; call `tear_down()` when done | Preview code continues after `run(..., no_exit=True)` |
| `WidgetPreview` says no or multiple handlers for input | Positional preview data does not match exactly one/default input signal | Pass explicit handler keywords (`set_data=...`) or set one signal `default=True` | `WidgetPreview(Widget).run(set_data=data, no_exec=True, no_exit=True)` |
| Background task keeps running after input change or deletion | Worker does not check `TaskState.is_interruption_requested()`, old task not cancelled, or `shutdown()` omitted from `onDeleteWidget()` | Use `ConcurrentWidgetMixin`; call `start()` for new tasks, `cancel()` on stop/resume, and `shutdown()` in `onDeleteWidget()`; have the worker return early on interruption | Widget test toggles input/delete and waits without leaked workers |
| Progress/status never updates | Worker does not call `state.set_status`/`set_progress_value`, or Qt event loop is not processing queued signals | Emit through `TaskState`; call `process_events` or wait helpers in tests; do not update Qt widgets directly from worker threads | Progress bar/status changes under `WidgetTest` |
| SQL widget keeps old credentials or shows connection errors | Keyring has stale credentials, host/port parsing changed, live DB unavailable, or backend raises `BackendError` | Use `CredentialManager` service names consistently; clear/update keyring entries; show only first-line connection errors; treat SQL services as optional | Mock `get_backend()` and assert `Error.connection` behavior |
| Large SQL input blocks or downloads unexpectedly | `SqlTable` input handler lacks `check_sql_input` / `check_sql_input_sequence` | Decorate table input handlers so small SQL tables convert to in-memory `Table` and large tables show `download_sql_data` | Unit test with patched `SqlTable.__len__` below/above `AUTO_DL_LIMIT` |
| Workflow `.ows` load fails | Missing widget class, renamed signal without `replaces`, incompatible stored settings, scheme not empty, signal propagation active during load, or optional add-on absent | Load into a fresh `WidgetsScheme`; pass a populated registry; pause signal propagation; add setting migrations and signal `replaces`; install required add-ons | Load fixture with `WidgetsScheme.load_from(f, registry=reg)` and clear/delete scheme after |
| Workflow load leaves Qt objects or hangs | Scheme not cleared/deleted, widgets created immediately without teardown, or background task still running | `scheme.clear()`, `scheme.deleteLater()`, `QTest.qWait(0)`; ensure widgets cancel workers in `onDeleteWidget()` | Repeated workflow-load test passes without object leaks/timeouts |
| Report button crashes or leaks secrets | `send_report()` assumes data/connection exists or reports credentials | Guard empty state; report host/database/user but never passwords; use `report_data`, `report_domain`, and `report_items` for deterministic output | Click report before and after input/connection in `WidgetTest` |

## Quick triage sequence

1. **Import check**: can the widget module import in the target environment?
2. **Discovery check**: does registry discovery list the widget with expected name, category, inputs, and outputs?
3. **Preview check**: can `WidgetPreview(...).run(..., no_exec=True, no_exit=True)` create the widget and send representative signals?
4. **Settings check**: can old/stored settings be packed and restored, including context settings for changed domains?
5. **Unit check**: can `WidgetTest` send signals, inspect outputs, and wait for background work?
6. **Workflow check**: can a fresh `WidgetsScheme` load the `.ows` file with a populated registry and paused signal manager?
7. **Headless check**: if any GUI check fails only in CI/container, re-run with `QT_QPA_PLATFORM=offscreen` before touching widget logic.
