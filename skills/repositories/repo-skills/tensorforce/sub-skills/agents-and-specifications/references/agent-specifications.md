# Agent Specifications

## Purpose

Use this reference when you need to build the `Agent.create(...)` or `Agent.load(...)` inputs for Tensorforce. It covers factory patterns, state/action schema choices, algorithm alias selection, action masking, and lifecycle checks. Use [`api-reference.md`](api-reference.md) for compact signatures and [`interaction-apis.md`](interaction-apis.md) for loops after the agent exists.

## Recommended construction pattern

When an environment object is available, let Tensorforce infer environment-dependent fields:

```python
from tensorforce import Agent, Environment

environment = Environment.create(
    environment='custom_cartpole',
    max_episode_timesteps=200
)

agent = Agent.create(
    agent='ppo',
    environment=environment,
    batch_size=10,
    network=dict(type='auto', size=32, depth=1),
    config=dict(device='CPU', seed=11, tf_log_level=40)
)
```

Why this is preferred:

- `environment.states()` supplies the agent's `states` argument.
- `environment.actions()` supplies the agent's `actions` argument.
- `environment.max_episode_timesteps()` supplies `max_episode_timesteps` for algorithms that require it, provided the environment defines it or it was passed to `Environment.create`.
- The state/action specs stay synchronized with the environment implementation.

If a task only asks for an agent spec and no environment object exists, create the agent from explicit specs:

```python
agent = Agent.create(
    agent='random',
    states=dict(type='float', shape=(4,)),
    actions=dict(type='int', shape=(), num_values=2),
    max_episode_timesteps=100,
    config=dict(device='CPU')
)
```

## Factory input forms

### Alias string plus keyword args

```python
agent = Agent.create(
    agent='dqn',
    states=dict(type='float', shape=(8,)),
    actions=dict(type='int', shape=(), num_values=4),
    memory=10000,
    batch_size=32
)
```

Use this form for most code snippets and programmatic workflows.

### Dictionary specification

```python
agent_spec = dict(
    agent='ppo',
    batch_size=10,
    network=dict(type='auto', size=64, depth=2),
    learning_rate=1e-3,
    config=dict(device='CPU', seed=3)
)
agent = Agent.create(agent=agent_spec, environment=environment)
```

`type` can be used instead of `agent`. Extra keyword arguments passed to `Agent.create` are merged into the dictionary.

### JSON specification path

```python
agent = Agent.create(agent='path/to/user-owned-agent.json', environment=environment)
```

Use this only for a config file that belongs to the user's current project or has been generated by the current workflow. Do not make runtime instructions depend on any source-repository config path.

### Class, object, callable, or module path

Use a class or module path only when a user has a custom Agent subclass importable in the runtime environment. A plain callable can be wrapped as a Recorder-style agent, but then a `recorder` configuration is required and full recording/pretraining details belong to `../persistence-export-and-recording/`.

## Choosing an alias

Use [`api-reference.md`](api-reference.md) for the complete alias table. Practical defaults:

- **Need a smoke test or baseline**: start with `random`; it requires only spaces/specs and validates `act`/`observe` behavior cheaply.
- **Need a common trainable policy-gradient agent**: choose `ppo`; supply `batch_size`, and ensure `max_episode_timesteps` is available.
- **Need discrete Q-learning**: choose `dqn`, `double_dqn`, or `dueling_dqn`; actions should be integer/discrete and you must provide `memory` and `batch_size`.
- **Need custom policy/objective/memory structure**: choose `tensorforce`/`default`; provide `update`, `optimizer`, `objective`, and `reward_estimation`, and route module internals to `../modules-and-configuration/`.
- **Need fixed or deterministic debug actions**: choose `constant` and set `action_values` if defaults are not enough.

Do not silently switch algorithm families to work around a spec error. First check whether the target task requires discrete or continuous actions, replay memory, on-policy updates, recurrent internals, or action masks.

## State and action specifications

### Primitive specs

```python
bool_spec = dict(type='bool', shape=(3,))
int_spec = dict(type='int', shape=(), num_values=5)
float_spec = dict(type='float', shape=(4,), min_value=-1.0, max_value=1.0)
```

Rules:

- `type` is one of `'bool'`, `'int'`, or `'float'`.
- `shape` describes one value, not a batch dimension. Use `()` or omit shape only for scalar actions where the algorithm/docs allow it.
- `num_values` is required for integer discrete values.
- `min_value`/`max_value` are optional for float values but should be supplied for naturally bounded continuous actions.
- State/action batches are passed to `act`/`experience` as arrays/lists; do not include the batch dimension in the spec.

### Singleton spec

A single observation and single action can be written directly:

```python
states = dict(type='float', shape=(8,))
actions = dict(type='int', shape=(), num_values=4)
```

For singleton states, Tensorforce accepts either a raw state value or a dict with the default key `state` when auxiliary fields such as action masks are also present.

### Multi-component specs

Wrap named components in one more dictionary layer:

```python
states = dict(
    observation=dict(type='float', shape=(10,)),
    inventory=dict(type='int', shape=(3,), num_values=6)
)
actions = dict(
    move=dict(type='int', shape=(), num_values=5),
    use_item=dict(type='bool', shape=())
)
```

At runtime, `states` must contain values for every named state component. `act` returns a dict for multi-action specs, so pass that dict to the environment's `execute(actions=...)` unless the environment expects a translated form.

## Action masking

Tensorforce supports masks for integer actions with `num_values`. The mask is supplied as an auxiliary state entry; it is not declared in the `states` specification.

### Singleton integer action

For a singleton action, the default action name is `action`; the mask key is `action_mask`:

```python
states_spec = dict(type='float', shape=(10,))
actions_spec = dict(type='int', shape=(), num_values=3)

states = dict(
    state=np.zeros(shape=(10,), dtype=np.float32),
    action_mask=np.asarray([True, False, True], dtype=bool)
)
action = agent.act(states=states)
assert action != 1
```

### Named integer action

For a named action, the mask key is `<action-name>_mask`:

```python
actions_spec = dict(
    move=dict(type='int', shape=(), num_values=4),
    throttle=dict(type='float', shape=(1,), min_value=0.0, max_value=1.0)
)

states = dict(
    observation=np.zeros(shape=(5,), dtype=np.float32),
    move_mask=np.asarray([True, True, False, True], dtype=bool)
)
```

Only `move` is maskable here because it is the integer action. Float and bool actions do not use this mask convention.

### Mask shape rules

For an integer action with spec `shape=S` and `num_values=N`, the mask shape is `S + (N,)` for a single state. Examples:

| Action spec | Mask key | Single-state mask shape |
|---|---|---|
| `dict(type='int', shape=(), num_values=3)` | `action_mask` or `<name>_mask` | `(3,)` |
| `dict(type='int', shape=(2,), num_values=4)` | `<name>_mask` | `(2, 4)` |
| `dict(type='int', shape=(2, 1), num_values=3)` | `<name>_mask` | `(2, 1, 3)` |

Every action element should have at least one valid (`True`) option. Missing masks default to all options valid when `config.enable_int_action_masking` is true.

### Config switch

Integer action masking is enabled by default in `config`:

```python
config = dict(enable_int_action_masking=True)
```

If a user intentionally disables it, Tensorforce treats mask entries as ordinary extra state keys and validation will usually fail because the agent state spec does not include them.

## Loading an agent while preserving specs

Basic load pattern:

```python
agent = Agent.load(
    directory='path/to/checkpoints',
    filename='agent',
    format='checkpoint',
    environment=environment
)
```

Use `environment=...` when possible so Tensorforce can recover or validate spaces and maximum episode length. If the saved JSON spec is missing constructor details because it contained Python objects or classes, pass the same constructor arguments to `Agent.load(...)` that you would pass to `Agent.create(...)`.

Route detailed checkpoint naming, NumPy/HDF5 formats, `saver`, SavedModel export, recording, and pretraining to `../persistence-export-and-recording/`.

## Lifecycle and introspection checklist

After creating the agent:

```python
spec = agent.get_specification()
architecture = agent.get_architecture()  # learning agents with a model architecture
internals = agent.initial_internals()
```

Before finishing:

```python
agent.close()
environment.close()
```

If a `Runner` created the agent and environment, let `Runner.close()` own closing. Do not close the same object twice from unrelated code paths.

## Minimal validation steps

- For factory/spec changes, run `python scripts/act_observe_smoke.py --episodes 1 --max-timesteps 3` from this sub-skill directory or pass its absolute path to Python.
- For action-mask changes, run `python scripts/action_masking_smoke.py --trials 20`.
- If those scripts fail before importing Tensorforce, check dependency compatibility in [`troubleshooting.md`](troubleshooting.md) before editing agent specs.
