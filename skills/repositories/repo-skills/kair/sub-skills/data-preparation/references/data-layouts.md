# KAIR data layouts

This reference is distilled for agents that need to reason about KAIR datasets without reopening KAIR source files. Paths are written as examples relative to a user's own KAIR checkout.

## Top-level convention

KAIR examples and configs use two conventional roots:

- `trainsets/` for training data.
- `testsets/` for validation and inference data.

Image workflows usually name roots with `dataroot_H` for high-quality/ground-truth images and `dataroot_L` for low-quality/input images. Video workflows usually name roots with `dataroot_gt` and `dataroot_lq`, while command-line test scripts use `--folder_gt` and `--folder_lq`.

## Image train/test folders

### Single-folder image datasets

Use a flat folder of images when KAIR generates degradation on the fly or consumes inputs only:

```text
trainsets/trainH/
  000001.png
  000002.png
  ...

testsets/set12/
  01.png
  02.png
  ...
```

Typical users:

- Denoising (`dncnn`, `ffdnet`, `fdncnn`) with `dataroot_H` only.
- JPEG artifact reduction (`jpeg`) with `dataroot_H` only.
- Blind/real-world SR (`blindsr`, `bsrgan`) with `dataroot_H` only.
- Input-only image testing (`l`, `low-quality`, `input-only`) with `dataroot_L` only.

### Paired image datasets

Use matched LQ and GT folders when the task needs paired inputs:

```text
trainsets/trainH/
  0801.png
  0802.png
trainsets/trainL/
  0801.png
  0802.png
```

For classical SR test sets, KAIR examples often use scale subfolders:

```text
testsets/Set5/
  HR/
    baby.png
    bird.png
  LR_bicubic/
    X2/
      babyx2.png
      birdx2.png
    X3/
    X4/
```

When checking pairs, match by the intended KAIR dataset behavior. Some SR test scripts tolerate scale suffixes in LQ names; training datasets are safest when stem or relative names clearly align with GT names.

### Subimage folders

DIV2K subimage extraction creates flat patch folders. KAIR's source logic removes `x2`, `x3`, `x4`, and `x8` from LR file names before adding patch suffixes, so HR/LR subimage keys can align.

```text
trainsets/DIV2K/
  DIV2K_train_HR_sub/
    0801_s001.png
    0801_s002.png
  DIV2K_train_LR_bicubic/
    X2_sub/
      0801_s001.png
    X3_sub/
    X4_sub/
```

## Video folder layouts

### Clip folder layout

Most VRT/RVRT train and test datasets use a root containing one subfolder per clip, with frames directly inside each clip folder:

```text
testsets/REDS4/
  GT/
    000/
      00000000.png
      00000001.png
      ...
    011/
    015/
    020/
  sharp_bicubic/
    000/
      00000000.png
      00000001.png
      ...
```

Rules:

- LQ and GT roots must have the same clip folder names for paired video testing.
- Each paired clip must have the same number of frames.
- Frame names should sort in temporal order. REDS uses `00000000.png`; DVD often uses `00000.jpg`; GoPro uses six-digit PNG frame names in KAIR configs.
- `VideoRecurrentTestDataset` scans all immediate subfolders when no `meta_info_file` is provided.
- `SingleVideoRecurrentTestDataset` uses only the LQ root and is appropriate when no GT is available.

Common clip-layout examples:

| Dataset | Example LQ root | Example GT root | Frame suffix/template | Notes |
| --- | --- | --- | --- | --- |
| REDS4 VSR | `testsets/REDS4/sharp_bicubic` | `testsets/REDS4/GT` | `png`, `08d` | Validation clips are `000`, `011`, `015`, `020`. |
| REDS4 deblurring | `testsets/REDS4/blur` | `testsets/REDS4/GT` | `png`, `08d` | Same clip names as GT. |
| DVD10 | `testsets/DVD10/test_GT_blurred` | `testsets/DVD10/test_GT` | `jpg`, `05d` | Evaluation script is MATLAB-only. |
| GoPro11 | `testsets/GoPro11/test_GT_blurred` | `testsets/GoPro11/test_GT` | `png`, `06d` | Prepared from GoPro `blur` and `sharp` folders. |
| Set8 denoising | `testsets/Set8` | `testsets/Set8` | image frames | GT is reused as clean source; noise is generated by the model/test dataset. |
| DAVIS denoising | `testsets/DAVIS-test` | `testsets/DAVIS-test` | image frames | GT is reused as clean source. |
| Vid4 or UDM10 VSR | `testsets/Vid4/BIx4`, `testsets/UDM10/BDx4` | `testsets/Vid4/GT`, `testsets/UDM10/GT` | `png` | Used for Vimeo-trained BI/BD models. |

### Vimeo90K sequence layout

Vimeo90K uses a two-level sequence layout with seven frames per sequence:

```text
trainsets/vimeo90k/
  vimeo_septuplet/
    sequences/
      00001/
        0001/
          im1.png
          im2.png
          ...
          im7.png
    sep_trainlist.txt
  vimeo_septuplet_matlabLRx4/
    sequences/
      00001/
        0001/
          im1.png
          ...
```

Rules:

- Meta-info keys look like `00001/0001`.
- Video SR uses neighboring frames selected from `im1` through `im7`.
- Vimeo VFI uses `im4.png` as the center GT frame.
- For VRT/RVRT training configs in this KAIR version, the expected GT LMDB name is `vimeo90k_train_GT_all.lmdb`; it needs keys for all frame names such as `00001/0001/im1`, not only the fourth frame.

### VFI special layouts

Frame interpolation testing has extra layouts:

```text
testsets/UCF101/
  clip_name/
    frame0.png
    frame1.png
    frame2.png
    frame3.png
    framet.png
```

DAVIS/Vid4 VFI derive interpolation windows from clip folders; UCF101 uses the `frame0`/`frame1`/`frame2`/`frame3`/`framet` naming convention.

## Meta-info files

KAIR video training and Vimeo testing rely on text files that list clips or sequences.

### Clip meta-info with start frame

`VideoRecurrentTrainDataset` and its nonblind denoising subclass expect four whitespace-separated fields:

```text
<clip_name> <frame_count> (<height>,<width>,<channels>) <start_frame>
```

Examples:

```text
000 100 (720,1280,3) 00000000
720p_240fps_1 100 (720,1280,3) 00000
GOPR0372_07_00 100 (720,1280,3) 000047
bear 82 (480,854,3) 00000
```

The first token is used as the clip folder name or LMDB key prefix. The start frame controls the first generated frame key, so it must match the frame-number template in the config.

### Vimeo meta-info without start frame

`VideoRecurrentTrainVimeoDataset`, `VideoRecurrentTrainVimeoVFIDataset`, and `VideoTestVimeo90KDataset` use three fields:

```text
<clip>/<sequence> 7 (<height>,<width>,<channels>)
```

Example:

```text
00001/0001 7 (256,448,3)
```

### Test meta-info behavior

For generic video test datasets, `meta_info_file` is optional. If provided, the first token of each line is used to select subfolders under LQ and GT roots. If omitted, KAIR scans all immediate subfolders of the LQ and GT roots.

## LMDB layout and keys

KAIR's LMDB writer creates a directory ending in `.lmdb`:

```text
example.lmdb/
  data.mdb
  lock.mdb
  meta_info.txt
```

`meta_info.txt` stores one record per encoded image:

```text
<key>.png (<height>,<width>,<channels>) <png_compression_level>
```

Examples:

```text
0801_s001.png (480,480,3) 1
000/00000000.png (720,1280,3) 1
00001/0001/im4.png (256,448,3) 1
```

The LMDB key itself is the same string without `.png`, for example `0801_s001`, `000/00000000`, or `00001/0001/im4`.

Key conventions by dataset family:

| Family | Source tree | LMDB key convention | Notes |
| --- | --- | --- | --- |
| DIV2K subimages | flat `*_sub` folders | `0801_s001` | Nonrecursive PNG scan. HR/LR patch counts should match. |
| REDS | `clip/frame.png` | `000/00000000` | Use recursive scan from the directory whose children are clip ids. Avoid an extra `X4/` level in keys unless the config is changed to match. |
| Vimeo90K | `clip/seq/imN.png` | `00001/0001/im1` ... `im7` | LQ LMDB keeps seven frames. GT LMDB for VRT/RVRT training should keep all frames in configs that request `GT_all`; VFI center-frame-only LMDBs are not enough for all configs. |
| DVD | `clip/frame.jpg` | `720p_240fps_1/00000` | Configs use JPEG and `05d` filename template. |
| GoPro | `clip/frame.png` | `GOPR.../000001` | Configs use PNG and `06d` filename template. |
| DAVIS | `clip/frame.jpg` | `bear/00000` | Denoising uses the same clean GT LMDB as both LQ and GT. |
| Set8 | clip folders | usually no LMDB | VRT/RVRT test-time denoising reads frame folders directly. |

## `dataset_type` mapping

`define_Dataset(dataset_opt)` lowercases `dataset_opt["dataset_type"]` and selects one of these classes. Use this table when a config says `Dataset [...] is not found` or when choosing a data layout.

| Accepted `dataset_type` values | Selected dataset | Required roots | Typical use |
| --- | --- | --- | --- |
| `l`, `low-quality`, `input-only` | `DatasetL` | `dataroot_L` | Input-only image folder. |
| `dncnn`, `denoising` | `DatasetDnCNN` | `dataroot_H` | Gaussian denoising from clean images. |
| `dnpatch` | `DatasetDnPatch` | `dataroot_H` | Patch-sampled denoising. |
| `ffdnet`, `denoising-noiselevel` | `DatasetFFDNet` | `dataroot_H` | Denoising with noise-level input. |
| `fdncnn`, `denoising-noiselevelmap` | `DatasetFDnCNN` | `dataroot_H` | Flexible denoising/noise-level map. |
| `sr`, `super-resolution` | `DatasetSR` | `dataroot_H`, optional or paired `dataroot_L` | Classical paired SR or generated LR depending on config. |
| `srmd` | `DatasetSRMD` | `dataroot_H`, optional `dataroot_L` | SRMD-style SR. |
| `dpsr`, `dnsr` | `DatasetDPSR` | `dataroot_H`, optional `dataroot_L` | DPSR/DNSR workflows. |
| `usrnet`, `usrgan` | `DatasetUSRNet` | `dataroot_H` | USRNet degradation-aware SR. |
| `bsrnet`, `bsrgan`, `blindsr` | `DatasetBlindSR` | `dataroot_H` | Blind/real-world SR. |
| `jpeg` | `DatasetJPEG` | `dataroot_H` | JPEG compression artifact reduction. |
| `videorecurrenttraindataset` | `VideoRecurrentTrainDataset` | `dataroot_gt`, `dataroot_lq`, `meta_info_file`, `io_backend` | Paired recurrent video training for REDS/DVD/GoPro. |
| `videorecurrenttrainnonblinddenoisingdataset` | `VideoRecurrentTrainNonblindDenoisingDataset` | `dataroot_gt`, `dataroot_lq`, `meta_info_file`, `io_backend` | Video denoising training; clean GT can be reused as LQ root. |
| `videorecurrenttrainvimeodataset` | `VideoRecurrentTrainVimeoDataset` | `dataroot_gt`, `dataroot_lq`, `meta_info_file`, `io_backend` | Vimeo90K recurrent video SR training. |
| `videorecurrenttrainvimeovfidataset` | `VideoRecurrentTrainVimeoVFIDataset` | `dataroot_gt`, `dataroot_lq`, `meta_info_file`, `io_backend` | Vimeo90K frame interpolation training. |
| `videorecurrenttestdataset` | `VideoRecurrentTestDataset` | `dataroot_gt`, `dataroot_lq`; optional `meta_info_file` | Paired video testing. |
| `singlevideorecurrenttestdataset` | `SingleVideoRecurrentTestDataset` | `dataroot_lq`; optional `meta_info_file` | Video testing with no GT. |
| `videotestvimeo90kdataset` | `VideoTestVimeo90KDataset` | `dataroot_gt`, `dataroot_lq`, `meta_info_file` | Vimeo90K test sequences. |
| `vfi_davis` | `VFI_DAVIS` | task-specific data root | DAVIS frame interpolation test. |
| `vfi_ucf101` | `VFI_UCF101` | task-specific data root | UCF101 frame interpolation test. |
| `vfi_vid4` | `VFI_Vid4` | task-specific data root | Vid4 frame interpolation test. |
| `plain` | `DatasetPlain` | `dataroot_H`, `dataroot_L` | Generic paired image data. |
| `plainpatch` | `DatasetPlainPatch` | `dataroot_H`, `dataroot_L` | Generic paired patch image data. |
