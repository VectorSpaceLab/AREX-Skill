# Dataset, figures, and log formats

## Case JSONL

The evaluation input is one JSON object per non-empty line. The runner's
ChestAgentBench-style records use these practical fields:

```json
{
  "question_id": "case-001-q1",
  "question": "Which finding is most likely ...?",
  "answer": "B",
  "explanation": "Optional reference explanation",
  "images": ["figures/001/figure_1a.jpg", ["figures/001/figure_1b.jpg"]],
  "image_source_urls": ["https://example.invalid/image.jpg"]
}
```

`question_id`, `question`, and `answer` identify the evaluation item. The
reference runner selects `images` in local mode and `image_source_urls` in URL
mode. Each image value may be a string or a list nested to more than one level;
flatten in encounter order. Keep the answer as supplied (normally a choice
letter) and do not use `explanation` as an additional model input beyond the
runner's established contract.

A case with an empty, absent, or entirely unusable selected image field is a
**skip candidate**, not an API call. The runner records `status: "skipped"` and
`reason: "no_images"`. A present but missing local file should be caught by
[validate_case_manifest.py](../scripts/validate_case_manifest.py) before the
run; do not silently turn a data error into a benchmark score.

## Eurorad metadata and figures

The Eurorad metadata source is a JSON object keyed by case identifier. A case
contains fields such as `case_id`, `title`, `section`, demographics, clinical
text, diagnosis, `image_finding`, and `figures`. `figures` is a list of figure
objects, each with `number` and `subfigures`; each subfigure has `number`, `url`,
and `caption`. Metadata is not itself the evaluation JSONL and should not be
scraped or regenerated by this sub-skill.

The companion figure layout is conventionally:

```text
<dataset-root>/figures/<case_id>/<normalized-subfigure>.jpg
```

The source figure utility creates the case directory and lowercases/underscores
the subfigure number (for example, a `Figure 1a` label becomes
`figure_1a.jpg`). The reference quickstart additionally removes a leading
`figures/` from a manifest path and joins it below the `figures` directory.
Therefore validate both the manifest spelling and the actual root; do not
assume that a URL basename or a caption is a local filename.

## Redacted JSONL result contract

Write one object per case. A shareable/redacted result should contain only
metadata and short textual values, never data-URL base64 content or secrets.
Recommended fields are:

- `question_id`, `timestamp`, `model`, `temperature`, `duration`;
- `status` (`ok`, `skipped`, or `error`);
- `usage` with `prompt_tokens`, `completion_tokens`, and `total_tokens` when
  the provider returns usage;
- `model_answer` and `correct_answer` for an attempted case;
- `reason` for a skip, or a sanitized `error_type`/short error for an error;
- `input` containing `question_id`, `image_source` (`local`/`url`), image
  reference count, and normalized reference names only.

The reference implementation's raw success/error entry also stores `input`
messages and image references; URL mode can place a base64 data URL inside a
message. Treat such raw logs as private. Before sharing, remove
`messages[*].content[*].image_url.url` values beginning with `data:`, remove
full prompt text if it contains sensitive case material, and never log
`OPENAI_API_KEY`.

A result log is evidence of what ran, not a clinical record. Keep a separate
run summary with attempted/succeeded/skipped/errored counts and explicit
limitations.
