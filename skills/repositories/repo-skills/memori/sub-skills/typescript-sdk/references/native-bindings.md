# Native Binding Notes

## What the package uses

- The Node package ships a native binding generated by NAPI-RS.
- The loader can pick a platform-specific binary or a package-scoped native
  artifact depending on the runtime.
- The package also depends on `@memorilabs/axon` for request/LLM orchestration.

## Platform and version reminders

- Node `>=20.19.0` is the supported engine floor.
- Native binding resolution is platform-specific and can fail if the peer
  package is missing or the runtime is incompatible.
- Optional DB driver packages (`better-sqlite3`, `pg`, `mysql2`) are not the
  same as the native binding itself.

## Useful signals

- `NAPI_RS_NATIVE_LIBRARY_PATH` can override the resolved binding in special
  debugging situations.
- `NAPI_RS_ENFORCE_VERSION_CHECK` enables version matching for the generated
  package variants.

## Practical rule

If the user only needs a package sanity check, inspect package metadata first.
If the user needs a build or binary troubleshooting path, verify the Node
version, driver packages, and native artifact selection separately.
