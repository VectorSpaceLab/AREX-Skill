# Unsupervised Troubleshooting

Use this matrix for ML-From-Scratch unsupervised workflows. For package-level
install/import problems, dependency pins, or general plotting utilities, also
consult `../../../references/troubleshooting.md`.

| Symptom | Likely cause | Fix or diagnostic |
|---|---|---|
| KMeans, PAM, DBSCAN, or GMM labels look dominated by one high-variance feature. | Distance and covariance algorithms are sensitive to feature scale. | Standardize or normalize numeric columns before clustering. Verify each feature is finite and comparable in units. |
| KMeans returns fewer effective clusters than `k`, warnings about mean of empty slice, or labels look degenerate. | Random initialization picked duplicate/poor centroids, `k` is too large, or duplicate samples created an empty cluster. | Set `numpy.random.seed`, reduce `k`, remove exact duplicate rows, run several seeds, and inspect cluster counts. If empty clusters persist, use PAM or a smaller `k`. |
| KMeans labels change between runs. | Random centroid initialization. | Seed NumPy before `predict(X)` and compare cluster partitions rather than fixed numeric label IDs. |
| DBSCAN returns a single cluster. | `eps` is too large after scaling, or `min_samples` is too low. | Scale features, lower `eps`, increase `min_samples`, and print label counts for each parameter sweep. |
| DBSCAN returns mostly outliers/noise. | `eps` is too small, `min_samples` is too high for the data density, or features are unscaled. | Scale features, increase `eps`, lower `min_samples` for tiny datasets, and inspect nearest-neighbor distances. Remember that this implementation labels unassigned samples with a nonnegative default label, not `-1`. |
| DBSCAN label counts are surprising on tiny synthetic data. | Border/noise behavior is very sensitive to `eps` and this implementation uses its own non-scikit-learn labeling conventions. | Use the bundled clustering smoke for API validation, then sweep `eps`/`min_samples` and verify only high-level density behavior. Do not assume scikit-learn-compatible labels. |
| PCA projection has complex dtype or numerical noise. | Eigen decomposition can return complex dtype with negligible imaginary parts. | Use real finite numeric input, standardize where appropriate, and coerce with `numpy.real_if_close` if the imaginary component is numerical roundoff. |
| PCA output shape is unexpected. | Component count belongs to `transform(X, n_components)`, not to `PCA()` construction. | Call `PCA().transform(X, desired_components)` and check that `X` is 2-D. |
| GMM likelihoods become `nan`, `inf`, or fail around covariance inversion/determinant. | Too few samples per component, duplicate/collinear features, singular covariance, or overly ambitious `k`. | Reduce `k`, standardize features, remove constant columns, use more samples, or reduce dimensionality before GMM. |
| Apriori raises type errors with string items or produces odd candidates. | The implementation treats singleton itemsets as integers when joining candidates. | Map each distinct string item to a stable integer ID before calling Apriori; decode itemsets and rules afterward. The bundled association smoke demonstrates this normalization. |
| Apriori returns no itemsets. | `min_sup` is too high for the number of transactions or transactions are malformed. | Use list-of-lists/tuples, not one flat list. Start with `min_sup` around `1 / n_transactions` to verify plumbing, then raise it. |
| Apriori rules are missing or too few. | `min_conf` is too high, itemsets are not frequent, or confidence is being interpreted backward. | Lower `min_conf`, print frequent itemsets first, and remember confidence is `support(antecedent ∪ consequent) / support(antecedent)`. |
| Code cannot find `rule.consequent`. | The package API misspells the field name. | Read `rule.concequent` along with `rule.antecedent`, `rule.support`, and `rule.confidence`. |
| FPGrowth returns too many itemsets when `min_sup=0.3`. | This implementation compares raw support counts against `min_sup`, despite the fractional-looking default. | Pass an integer count such as `2` or `3` for predictable behavior. Use Apriori when a fractional support threshold is required. |
| FPGrowth results accumulate unexpectedly across calls. | Frequent itemsets are stored on the object. | Create a fresh `FPGrowth(...)` instance for each independent transaction database. |
| Association mining fails on transaction shape. | Transactions must be an iterable of transactions, and each transaction must be an iterable of comparable/hashable item values. | Normalize to `[[item_a, item_b], [item_b, item_c], ...]`; remove empty transactions or handle them explicitly before mining. |
| `ValueError: setting an array element with a sequence` while building transaction data. | Current NumPy rejects ragged `np.array([...])` construction for variable-length transactions. | Keep transactions as a Python list of lists, or explicitly use `np.array(transactions, dtype=object)` only when the algorithm path can handle object arrays. The bundled association smoke uses list-of-lists. |
| GeneticAlgorithm never reaches the target in a smoke test. | The search is stochastic and bounded iterations are only a smoke check. | Use a tiny target such as `AI`, set NumPy seed, increase population/iterations modestly, and keep mutation rate in a reasonable range such as `0.05`-`0.3`. |
| GeneticAlgorithm fails with an unsupported target character. | The implementation's alphabet is space plus ASCII letters. | Remove digits/punctuation or extend the class outside the smoke script; for runtime usage, keep targets to allowed characters. |
| GeneticAlgorithm population size changes or selection behaves oddly. | Reproduction is pair-based. | Use an even `population_size` of at least `4`. |
| RBM appears slow or noisy. | RBM uses iterative contrastive divergence, progressbar output, and reconstruction snapshots. | Start with small `n_hidden`, small `batch_size`, and very few `n_iterations`; scale only after API and data checks pass. |
| RBM reconstructions look poor in a quick run. | A few iterations on tiny data prove usability, not final generative quality. | Check that inputs are binary or scaled to `[0, 1]`, then increase iterations gradually if reconstruction quality matters. |
| Plotting workflows hang or fail with display errors. | Long-form plotting examples call interactive Matplotlib display functions, which may require a GUI backend. | Set `MPLBACKEND=Agg` before importing Matplotlib, avoid interactive display in automated runs, and save figures to an explicit user-approved path only when output images are needed. The bundled smokes do not plot. |
