# Cross-cutting troubleshooting

Use this root troubleshooting page before entering workflow-specific diagnostics when a failure could be caused by installation, version drift, optional backend selection, or a mismatch between source configs and runtime artifacts.

| Symptom | Likely cause | Recovery path | Route |
| --- | --- | --- | --- |
| `ModuleNotFoundError: mmdeploy` or import resolves to an unexpected package | MMDeploy is not installed in the active environment, or another checkout/wheel shadows it. | Install the package in the environment that will run conversion or validation; run `python -c "import mmdeploy; print(mmdeploy.__version__)"`; avoid mixing editable/source and wheel installs unless intentionally refreshing. | Root setup, then relevant sub-skill |
| `ModuleNotFoundError` for `mmengine`, `mmcv`, `onnx`, `h5py`, `pandas`, or `openpyxl` | Runtime, optional, build, or validation helper requirements are incomplete. | Install only the needed requirement group for the selected route; conversion needs core runtime/build deps, calibration needs HDF5 support, validation/regression helpers need table/report dependencies. | conversion or validation |
| Import or conversion fails only after installing a new backend wheel | Backend package dependencies conflicted with MMDeploy pins such as `protobuf<=3.20.2`, or with the target OpenMMLab stack. | Check `pip check`; prefer a separate backend-specific environment when dependency variants conflict; do not keep a backend package that breaks core imports. | backends |
| ONNX export or partition extraction raises an unexpected `TypeError`, `AssertionError`, or shape-inference warning after a version bump | The installed ONNX/PyTorch/MMDeploy combination drifted from the repository's tested API surface, or an upstream API changed under the bundled helper. | Recheck package versions, rerun the relevant bundled helper in the same environment, and refresh the skill if the public API changed. Treat this as version drift before assuming the skill route is wrong. | conversion |
| A backend manager reports unavailable even though MMDeploy imports | The optional backend package, converter executable, vendor SDK, or shared library path is missing. | Use the backend route and bundled `check_env.py`; verify the exact `backend_config.type`, Python package import, required executable, environment variables, and custom-op status. | backends |
| TensorRT, RKNN, Ascend, SNPE, VACC, or other accelerator route is requested on a CPU-only host | These routes need actual vendor runtime/hardware; CPU import checks cannot prove them. | Stop or narrow scope unless the user supplies the required hardware/runtime. Record accelerator evidence as blocked or document-backed only. | backends |
| Conversion succeeds to ONNX/TorchScript but backend file or SDK runtime fails | IR export and backend/runtime execution are separate stages. | Preserve the work directory, identify the failing stage and backend files, then route backend readiness to `backends` or SDK directory/runtime issues to `sdk`. | conversion → backends/sdk |
| SDK Python/C/C++/Java/C# runtime refuses a raw `.onnx`, `.engine`, `.xml`, or `.param` file | SDK task APIs consume a model directory with metadata JSON, not a single backend artifact. | Regenerate or locate the conversion work directory created with `--dump-info`; check `deploy.json`, `pipeline.json`, `detail.json`, and all listed backend files. | sdk |
| Dataset metrics, visual outputs, or latency numbers are missing after conversion | Conversion visualization is not the same as evaluator validation or latency profiling. | Use validation helpers with an exported backend model and compatible model config; choose `test.py` for evaluator metrics or `profiler.py` for latency-only timing. | validation |
| Export fails because an operator is unsupported or partition markers are missing | A function/module/symbolic rewrite, custom op, or `@mark`-based partition path is incomplete or not imported. | Use the extensibility route to register rewrites, custom ops, symbolic overrides, or marks; then return to conversion. | extensibility → conversion |
| A command tells the agent to open original repository docs/tools/tests | Runtime skill should be self-contained. | Use the bundled reference or script in this skill tree instead. If the needed source behavior is absent, treat it as a skill gap and refresh/extend the skill. | root or owning sub-skill |

## Safe operating defaults

- Ask for the target backend, device, deploy config, model config, checkpoint, input sample, work directory, and artifact set before running conversion, SDK, or validation commands.
- Do not run full regression matrices, checkpoint downloads, benchmarks, or vendor accelerator commands without explicit user intent and a verified runtime.
- Treat optional backend skips as skips, not passes. Treat unavailable required accelerator runtime as a blocker until scope is narrowed or hardware/runtime is provided.
- Keep generated outputs, validation logs, and profiler work directories outside this runtime skill directory.
