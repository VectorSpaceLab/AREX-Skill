# Data formats and loader contracts

Use this reference before editing any Fengshen training command. Fengshen data code is a mix of Hugging Face `datasets`, PyTorch Lightning data modules, legacy text readers, sequence-tagging collators, and optional mmap / Megatron indexed datasets.

## Quick map

| Family | Loader or collator | Required shape | Notes |
|---|---|---|---|
| Text classification | `TaskDataModel`, pipeline collators | JSONL with text fields, `label`, optional pair field and `id` | Field names are controlled by `texta_name`, `textb_name`, `label_name`, `id_name`. |
| Sequence tagging | `DataProcessor`, `TaskDataset`, `CollatorForLinear`, `CollatorForCrf`, `CollatorForSpan`, `CollatorForBiaffine` | `train.all.bmes`, `dev.all.bmes`, optional `test.all.bmes`, plus `labels.txt` | Blank line separates samples; `decode_type` controls label inventory. |
| LCSTS-style summary | `LCSTSDataModel`, `LCSTSDataset`, `AbstractCollator` | JSONL with `text` and `summary` | `prompt` is prepended at tokenization time. |
| Medical QA causal LM | `GPT2QADataModel`, `GPT2QADataset` | trusted line-delimited dict records with `Question` and `answer` | The legacy reader uses `eval`; do not feed untrusted records. |
| Unsupervised T5 | `UnsuperviseT5DataModel`, `UnsuperviseT5Dataset` | HF dataset or cached dataset with a text column, default `text` | Span-corruption targets are generated by the collator. |
| Supervised T5 task | `TaskT5DataModel`, `TaskT5Dataset` | JSONL with `question`, `choice`, `texta`, `textb`, `answer` | `force_words_ids` are derived from answer choices. |
| Dialog / QA T5 | `DialogDataModel`, `DialogDataset`, `T5StyleDataset` | `context`, `knowledge`, `target`, or T5-style `question`, `context`, `answer` | Often loaded through `fs_datasets`; raw JSON is also supported in some entry points. |
| Raw pretraining corpus | `BertDataGenerate`, `BertDataModule`, pretraining collators | JSONL `{"text": "..."}` | Sentence-split and cache before long runs. |
| mmap tensors | `MMapDataModule`, `MMapIndexDataset` | `<prefix>_<tensor>.npy` index and `<prefix>_<tensor>.bin` data | `input_tensor_name` lists tensor names such as `input_ids`. |
| Megatron indexed data | `build_train_valid_test_datasets` | indexed dataset prefix plus `.idx`/`.bin` data | Supports `standard_bert`, `bert_cn_wwm`, `bart`, `coco_lm`, `t5`, `ict`. |

## Text classification JSONL

Local classification readers load one JSON object per line. Use the parser args in [training-arguments.md](training-arguments.md) to set field names. A minimal single-text record is:

```json
{"sentence": "这是一条新闻", "label": "科技", "id": 1}
```

A paired record is:

```json
{"sentence": "句子一", "sentence2": "句子二", "label": 0, "id": 2}
```

If `dataset_name` is supplied, the data module uses `datasets.load_dataset(dataset_name)` and expects `train`, `validation`, and `test` splits. If a local JSONL key is missing, some readers fall back to `""` or `0`; validate keys explicitly instead of trusting a silent fallback.

## Sequence tagging BMES/BIO/BIOES files

Directory layout:

```text
labels.txt
train.all.bmes
dev.all.bmes
test.all.bmes   # optional, many examples reuse dev as test
```

Each non-empty line has a token and optional label separated by whitespace. Blank lines end an example:

```text
北 B-LOC
京 E-LOC
今 O
天 O

张 B-PER
三 E-PER

```

The loader normalizes `M-` to `I-` before calling `get_entities(..., markup="bioes")`. Missing labels default to `O` only in test-style reads.

### Decode type and collator choice

| `decode_type` | Collator | `labels.txt` should contain | Batch targets | Use when |
|---|---|---|---|---|
| `linear` | `CollatorForLinear` | full tags such as `O`, `B-PER`, `I-PER`, `E-PER`, `S-LOC` | token `labels` | simple token classification head |
| `crf` | `CollatorForCrf` | same full tag inventory as `linear` | token `labels` plus attention mask | sequence-level transition constraints matter |
| `span` | `CollatorForSpan` | entity type names such as `PER`, `LOC`, plus `O` if used | `start_positions`, `end_positions`, `subjects` | start/end span head |
| `biaffine` | `CollatorForBiaffine` | entity type names such as `PER`, `LOC`, plus `O` | `span_labels`, `span_mask` | span matrix / biaffine classifier |

For `span` and `biaffine`, the dataset first creates `subject` spans as `[entity_type, start, end]` using `get_entities`; the collator converts those spans to start/end or span-matrix targets.

Use [../scripts/check_ner_labels.py](../scripts/check_ner_labels.py) before training when adapting BIOES labels.

## LCSTS-style summary records

`LCSTSDataset` expects JSONL records with `text` and `summary`:

```json
{"text": "长文本正文", "summary": "短摘要"}
```

The data module uses `train_data`, `valid_data`, and `test_data` filenames under `data_dir`. `max_enc_length`, `max_dec_length`, and `prompt` control tokenization. The collator masks padding positions in labels with `-100` for seq2seq loss.

## T5, dialog, and QA records

Unsupervised T5 pretraining uses a text column, default `text`, and creates span-corruption inputs internally. Supervised T5 task data uses:

```json
{
  "question": "下面属于哪一类？",
  "choice": ["科技", "汽车"],
  "texta": "待分类文本",
  "textb": "",
  "answer": "科技"
}
```

Dialog-style generation expects fields such as:

```json
{
  "context": ["用户上一轮", "系统上一轮"],
  "knowledge": "可用知识文本",
  "target": "目标回复",
  "idx": 0
}
```

T5-style QA records use `question`, `context`, and an `answer` list whose first item is used as the target:

```json
{"question": "答案是什么？", "context": "证据段落", "answer": ["答案"], "idx": 0}
```

## Medical QA causal-LM records

`GPT2QADataset` expects each line to evaluate to a dict with `Question` and `answer`:

```json
{"Question": "症状如何处理？", "answer": "建议先..."}
```

The loader concatenates `Question + answer`, pads/truncates to `max_seq_length`, and sets pad positions to `-100` in labels. Because the legacy parser uses `eval`, convert to a trusted, sanitized source file before using it.

## Raw corpus, mmap, and Megatron data

Raw BERT-style corpus files are JSONL with a single `text` field. The usual safe path is:

1. split very large files into smaller JSONL shards,
2. sentence-split long paragraphs into shorter `{"text": ...}` records,
3. save Hugging Face dataset shards,
4. feed the cached dataset through a collator.

`MMapIndexDataset` expects one index and one binary file per tensor name. For a prefix `train_part0` and tensor `input_ids`, provide:

```text
train_part0_input_ids.npy
train_part0_input_ids.bin
```

Megatron indexed datasets use a prefix consumed by `make_indexed_dataset`; split strings may use comma or slash notation such as `949,50,1` or `9/1/0`. Weighted multi-dataset prefixes are written as weight/prefix pairs, for example `0.7 corpus_a 0.3 corpus_b`.

## Field-validation checklist

- Match parser field-name args to actual JSON keys before launching training.
- Keep `labels.txt` consistent with `decode_type`.
- Treat `fs_datasets` as optional infrastructure: if it is unavailable, use local JSON/HF datasets paths where the loader supports them.
- Use a tiny sample through the intended collator before running a distributed job.
