# DexData and registration

## Episode layout

A dataset directory contains episode `*.jsonl` files. Dexbotic can create `index_cache.json` when `DexDataset` first indexes the directory; do not hand-edit the cache to repair data. Each non-empty JSONL line is one frame. An episode should preserve temporal order.

A practical frame record is:

```json
{
  "images_1": {"type": "video", "url": "video/front.mp4", "frame_idx": 21},
  "images_2": {"type": "image", "url": "images/wrist_21.png"},
  "state": [0.1, 0.2, 0.3],
  "action": [0.01, 0.02, 0.03],
  "prompt": "open the door",
  "is_robot": true
}
```

Supported image fields conventionally use `images_1`, `images_2`, etc. Video records require `type: video`, a URL/path and an integer `frame_idx`; image records use `type: image` and a URL/path. Multi-view order is a model/data configuration contract: keep the same order in `images_keys`, `num_images`, and the inference camera order.

`state` is typically proprioception. `action` may be explicit or generated by dataset transforms. `prompt`/`answer` is converted to a conversation when `conversations` is absent. Use `conversations` for LLaVA-style multi-turn records; each turn has `from` and `value`, and image placeholders must match the image transform contract.

## Registration contract

```python
from dexbotic.data.data_source.register import register_dataset

MY_DATASET = {
    "task": {
        "annotations": "<data-root>/task",
        "data_path_prefix": "<video-root>",
        "frequency": 1,
    }
}

meta_data = {
    "non_delta_mask": [6],
    "periodic_mask": [3, 4, 5],
    "periodic_range": 6.283185307179586,
}
register_dataset(MY_DATASET, prefix="my_robot", meta_data=meta_data)
```

The usable name becomes `my_robot_task`. `frequency` may be fractional for a deterministic prefix sample or greater than one for repeated sampling; use this deliberately. `register_dataset` mutates the process-local `CONVERSATION_DATA` registry, so import registration exactly once per process and avoid duplicate prefixes.

`non_delta_mask` identifies action dimensions that must not be differenced. `periodic_mask` and `periodic_range` describe wraparound dimensions such as rotations. These masks must agree with the action transform, inference configuration, and downstream control convention. A wrong mask can yield numerically plausible but physically wrong actions.

## DexDataset construction

`DexDataset` consumes a data-args object, a tokenization callable, and optional action/image/depth processors. Relevant arguments include `dataset_name`, `num_images`, `images_keys`, `depths_keys`, `load_depth`, `data_keys`, `aug_policy`, `image_processor`, and `image_aspect_ratio`. It resolves dataset names from the registration registry, indexes JSONL files, deterministically shuffles file order with a fixed seed, and applies the supplied processors.

A first inspection should assert:

- every registered `annotations` directory exists and contains JSONL;
- all required `images_keys` exist in the selected records;
- state and action dimensions are stable;
- image/video paths resolve under the intended data root;
- the action processor's prediction horizon leaves at least one valid frame;
- depth is either consistently present and enabled or disabled.

## Normalization

`NormStats` stores `mean`, `std`, and optional `q01`, `q99`, `min`, and `max` arrays. `RunningStats` needs at least two vectors before `get_statistics()`. Use `dexbotic.data.utils.normalize.save(directory, stats)` to write `norm_stats.json` and `load(directory)` to read it. Treat normalization as part of checkpoint provenance: action dimension, non-delta mask, periodic handling, and statistics must travel together.
