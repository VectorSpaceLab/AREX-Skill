# Sequence feature shapes, padding, and masks

DeepCTR-Torch sequence features are ordinary model-input arrays whose columns are reserved by `VarLenSparseFeat(maxlen=...)`. The most common errors come from names that do not match `history_feature_list`, arrays that do not have exactly `maxlen` columns, or missing behavior length columns.

## Input array shapes

| Feature role | Feature column | Model-input value | Shape accepted by `fit`/`predict` | Rule |
| --- | --- | --- | --- | --- |
| Target sparse field | `SparseFeat("item_id", ...)` | `model_input["item_id"]` | `(batch,)` or `(batch, 1)` | Integer ids in embedding vocabulary. |
| Dense field | `DenseFeat("score", dimension=d)` | `model_input["score"]` | `(batch,)` when `d=1`, otherwise `(batch, d)` | Floating point values. |
| Behavior history | `VarLenSparseFeat(SparseFeat("hist_item_id", ...), maxlen=T, length_name="seq_length")` | `model_input["hist_item_id"]` | `(batch, T)` | Post-pad/truncate to exactly `T`. |
| Shared behavior length | Generated by `length_name="seq_length"` | `model_input["seq_length"]` | `(batch,)` or `(batch, 1)` | Count of valid leading timesteps, from `0` through `T`. |
| Non-DIN multi-value sequence | `VarLenSparseFeat(SparseFeat("genres", ...), maxlen=T, length_name=None)` | `model_input["genres"]` | `(batch, T)` | `0` is treated as padding by mask-based pooling. |
| DIEN negative history | `VarLenSparseFeat(SparseFeat("neg_hist_item_id", ..., embedding_name="item_id"), maxlen=T, length_name="seq_length")` | `model_input["neg_hist_item_id"]` | `(batch, T)` | Required only when `use_negsampling=True`; same mask as positive history. |

The package concatenates all arrays according to `get_feature_names(feature_columns)`. Build `model_input` from those names to include generated length columns and to catch missing feature keys early.

## Padding and `length_name`

### With `length_name`

When `length_name` is present, `SequencePoolingLayer` and DIN/DIEN attention create a mask from the first `seq_length` positions:

```text
hist_item_id = [12, 54, 8, 0, 0]
seq_length   = 3
valid mask   = [1,  1, 1, 0, 0]
```

Use **post-padding** for behavior histories. Pre-padding such as `[0, 0, 12, 54, 8]` with `seq_length=3` will mask the first three columns and hide the latest valid events.

DIN and DIEN should use a `length_name` on behavior histories. If all sequence feature columns lack a length column, the models raise a max-length-column error during attention.

### Without `length_name`

When `length_name=None`, sequence pooling builds the mask from `sequence_array != 0`:

```text
genres = [2, 5, 0]
mask   = [1, 1, 0]
```

In this mode `0` is reserved for padding and must not encode a real category. Start valid sequence ids at `1` and set `vocabulary_size` to at least `max_id + 1`.

This mode is suitable for pooled multi-value features such as genres. It is not the safe mode for DIN/DIEN behavior attention.

## Behavior-history alignment rules

For `behavior_feature_list = ["item_id", "cate_id"]`:

```text
item_id      shape: (B,)       current candidate item
cate_id      shape: (B,)       current candidate category
hist_item_id shape: (B, T)     item ids of past events
hist_cate_id shape: (B, T)     category ids of the same past events
seq_length   shape: (B,)       valid leading event count
```

Every row and timestep should align across behavior fields:

```text
hist_item_id[i, t] and hist_cate_id[i, t] describe one event.
```

Recommended for DIN/DIEN:

- Use one shared `maxlen` for all positive behavior histories.
- Use one shared `length_name`, typically `seq_length`.
- Use the same `maxlen` and `length_name` for DIEN `neg_hist_*` histories.
- Keep non-behavior `VarLenSparseFeat` columns out of the behavior-history list. If they also have a `length_name`, put behavior histories first and keep the behavior length unambiguous.

## Embedding sharing and dimensions

The target and all corresponding history columns should share the target embedding table:

```python
SparseFeat("item_id", vocabulary_size=n_items, embedding_dim=8)
VarLenSparseFeat(
    SparseFeat("hist_item_id", vocabulary_size=n_items, embedding_dim=8, embedding_name="item_id"),
    maxlen=maxlen,
    length_name="seq_length",
)
```

For DIEN negative sampling, share the same table too:

```python
VarLenSparseFeat(
    SparseFeat("neg_hist_item_id", vocabulary_size=n_items, embedding_dim=8, embedding_name="item_id"),
    maxlen=maxlen,
    length_name="seq_length",
)
```

If embeddings are not shared, dimensions still must match the target for attention. Even when dimensions match, separate target/history tables are usually not the intended DIN/DIEN behavior-pair semantics.

## Maxlen checklist

Before fitting or predicting, assert these conditions for each sequence column:

```python
assert hist_item_id.ndim == 2
assert hist_item_id.shape[1] == maxlen
assert hist_cate_id.shape == hist_item_id.shape
assert seq_length.ndim in (1, 2)
assert seq_length.max() <= maxlen
assert seq_length.min() >= 0
```

For each row, `seq_length` should not exceed the number of leading non-padding events. With `length_name`, the mask trusts `seq_length`; it does not inspect zeros.
