# Model overview and compatibility

## Fit versus explain an existing model

AIX360 uses the word *explainer* for several different operating patterns.
Choose based on the data flow, not on the class name.

| Pattern | AIX360 choices | What is fitted | What the output means | Existing model required? |
|---|---|---|---|---|
| Data/exemplar summary | ProtoDash | prototype weights over candidate rows | representative rows and non-normalized weights | no |
| Direct predictive model | BRCG, GLRM, RIPPER | a new classifier/regressor | prediction is generated by visible clauses/rules | no |
| Model differencing | IMD | joint surrogate structure from two output vectors | regions where outputs agree/differ | yes, two models |
| Teaching explanation | TED Cartesian | a classifier over combined label/explanation ids | predicted label and domain explanation code | no separate teacher API, but explanations are training targets |
| Structural neural interpretation | CoFrNet, DIPVAE | an interpretable neural architecture/generative model | masked network structure, latent edits, reconstructions | no |
| Confidence-profile surrogate | ProfWeight | a simple model weighted by probe confidence | a weighted simple model, not a faithful local explanation by default | complex model probes/checkpoints |

A direct predictive model can be evaluated against the ground truth, but it is
not automatically a faithful surrogate for an existing black box. Conversely,
IMD does not fit either source model and cannot be used if the two prediction
arrays are not aligned to the same rows. TED's explanation id is predicted
jointly with the label and is meaningful only under the domain's explanation
vocabulary.

## Dependency matrix

The package's optional installation groups and observed code boundaries imply
the following matrix. `Core` means the default NumPy/pandas/scikit-learn
installation; `Optional` means install and probe before use; `Legacy` means the
source advertises versions that commonly conflict with a modern environment.

| Capability | Core | Optional packages / backend | Practical status and guard |
|---|---:|---|---|
| `FeatureBinarizer`, `FeatureBinarizerFromTrees` | yes | pandas, SciPy, scikit-learn | Fit with the version-compatible pandas/sklearn combination; preserve MultiIndex |
| ProtoDash | no | `xport`, SciPy, cvxpy, OSQP | `xport` is imported by the module even for array use; probe import and solver |
| BRCG/GLRM | no | cvxpy, ECOS, SciPy, older pandas/sklearn/NumPy constraints | Choose an installed solver; catch solver status and inspect selected rules |
| RIPPER/TRXF | no | numba, cvxpy, nyoka, xmltodict | `RipperExplainer` imports numba in this release; PMML adds serializer constraints |
| IMD | no | networkx; graphviz/pygraphviz only for rendering | Core fit/rules/regions do not require image rendering |
| TED Cartesian | yes-ish | pandas, scikit-learn | Base estimator must accept multiclass composite `YE` labels |
| CoFrNet | no | PyTorch, pandas<2, NumPy constraints, tqdm | PyTorch source uses custom layers and CPU/GPU tensor semantics |
| DIPVAE | no | PyTorch, torchvision, matplotlib | Dataset/model args are source-specific; validate a tiny batch first |
| ProfWeight | no | Keras 2.3.1, TensorFlow 1.14, SciPy | Legacy Python/backend stack; modern Keras/TensorFlow is not an automatic substitute |
| IMD graph image | no | graphviz executable plus pygraphviz | Keep textual rules if native drawing is unavailable |

The repository's historical extras specify, among other constraints, pandas
below 2 and NumPy below or equal to 1.24 for some RBM paths, Keras 2.3.1 and
TensorFlow 1.14 for ProfWeight, and PyTorch for CoFrNet/DIPVAE. These are
compatibility signals, not a guarantee that those exact versions install on
the current interpreter. The current inspection environment should be used
for read-only signature/import facts; a failed optional import is an explicit
boundary, not a reason to alter the runtime skill.

## Inputs and artifacts by family

### Binarization artifacts

Keep:

- original training columns and dtypes;
- the fitted transformer;
- binary MultiIndex columns, in order;
- optional standardized ordinal frame and its column list;
- categorical vocabulary and missing-value policy.

A human-readable rule such as `income <= 42.5` is represented in the binary
frame as `(income, '<=', 42.5)`. Negated and categorical tests are distinct
columns. A transform that silently drops a column or changes category types
can produce a valid-looking but semantically wrong matrix.

### Rule artifacts

For BRCG store `isCNF`, the selected rule strings, target encoding, complexity
settings, and a schema manifest. For GLRM store the coefficient table,
intercept, whether standardized ordinal features were used, and the original
feature-level mapping. For RIPPER/TRXF store a typed list of conjunctions,
predicates, relations, values, and `then_part`; optionally add a PMML string
only after serialization succeeds and round-trip behavior is checked.

### Prototype artifacts

Store candidate-row ids, selected positions, weights, kernel/optimizer settings,
feature preprocessing, and the objective history. A weight of zero or a
nearly duplicate prototype is evidence to diagnose, not to normalize away.

### Difference and teaching artifacts

For IMD store feature names, depth/criterion/alpha, each rule's predicate list
and class label, the observed-domain region, and the metric denominator counts.
For TED store the explanation-id encoder, `NumE`, base estimator identity and
both label/explanation output arrays. Do not publish raw composite `YE` values
without the decoder.

### Neural artifacts

For CoFrNet store connection masks, input/output dimensions, and a versioned
state dict if reproducible inference is required. For DIPVAE store model args,
latent dimension, dataset shape/range, likelihood and output activation, and
edit settings. For ProfWeight store probe file metadata, inclusive layer range,
label shape, computed weight summary, and simple-model hyperparameters; do not
assume a checkpoint is portable across Keras generations.

## Optional routing boundaries

The following are intentionally not implemented by this sub-skill:

- local black-box perturbation or attribution methods;
- counterfactual search, recourse, certification, or transport optimization;
- time-series-specific models or data loaders;
- dataset and metric governance beyond the API-level checks here.

Use the sibling routes in `SKILL.md` for those requests. Keep graph rendering,
PMML serialization, XPT parsing, and legacy neural training optional so that
the core textual/model workflows remain usable without their native tools.
